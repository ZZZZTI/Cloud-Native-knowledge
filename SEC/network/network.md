### TCP三次握手（建立连接）

```Shell
客户端 → 服务器：SYN（seq=x）
服务器 → 客户端：SYN+ACK（seq=y, ack=x+1）
客户端 → 服务器：ACK（seq=x+1, ack=y+1）
运维视角：(命令:tcpdump)
telnet IP port 如果能通             -> 说明三次握手成功（服务端端口已监听且无防火墙拦截）。
抓包看到只有SYN发出，没有SYN+ACK回来   -> 要么服务端没监听端口 要么防火墙丢弃了SYN包
抓包看到SYN之后收到RST               -> 端口被拒绝（服务没启动或主动拒绝）
抓包看到Retransmission              -> 网络丢包或延迟过大。
抓包看到Dup ACK（重复确认）           -> 对端收到乱序包，触发快速重传。

# 为什么要三次握手？
两次握手可能导致服务器因收到客户端滞后的旧SYN包而误建连接，浪费资源且状态不一致。
三次握手中，服务器必须等到客户端的ACK确认才会建立连接，从而避免这一问题。
```

### TCP四次挥手（断开连接）

```Shell
主动关闭方 → 被动方：FIN
被动方 → 主动方：ACK
被动方 → 主动方：FIN
主动方 → 被动方：ACK
(命令:ss)
运维常见状态   含义	                           常见原因
ESTABLISHED	 连接已建立	                     正常
TIME_WAIT	   主动关闭方在等待2MSL	             频繁短连接导致占用端口->调整内核参数tcp_tw_reuse
CLOSE_WAIT	 被动关闭方收到FIN，应用未调用close  应用bug，没及时关闭连接 →导致连接泄漏->修复应用代码
FIN_WAIT2	   主动关闭方等待对方FIN	             对端迟迟不关闭

# 为什么客户端需要等待TIME_WAIT？
客户端发送最后一个ACK后不立即释放，而是等待2MSL。
若ACK丢失，服务端会重发FIN，客户端收到后可重发ACK并刷新计时器，确保服务端正常关闭。
目的是在不可靠网络中可靠地确认连接断开，避免服务端一直停留在最后确认状态。
# 为什么要四次挥手？
TCP支持半关闭：每一方可以单独停止发送数据。
关闭一个方向需要“FIN + ACK”两次交互，双方共需四次挥手才能完全释放连接。
```

### 其他

```Shell
TCP 协议
TCP 特点：面向连接、可靠、有序、流量控制、拥塞控制、全双工。
可靠传输：序列号、确认应答、超时重传、快速重传、滑动窗口、拥塞控制。
流量控制：滑动窗口，接收方告诉发送方可发多少，防止接收方缓冲区溢出。
拥塞控制：慢启动、拥塞避免、快重传、快恢复。防止网络过载。
UDP 协议
UDP 特点：无连接、不可靠、无顺序、开销小、速度快、支持广播多播。
适用场景：视频直播、语音通话、DNS、DHCP、游戏，追求速度容忍丢包。
TCP vs UDP：TCP 可靠有序有连接开销大，UDP 不可靠无序无连接开销小速度快。


DNS
DNS 作用：域名解析成 IP。
解析过程：先查本地缓存和 hosts，再查本地 DNS 服务器，本地 DNS 递归或迭代查询根、顶级、权威服务器。
递归查询：客户端到本地 DNS，本地 DNS 负责查到底。
迭代查询：本地 DNS 到根、顶级、权威，逐级返回。
记录类型：A 地址，AAAA IPv6，CNAME 别名，MX 邮件，NS 域名服务器，PTR 反向解析，TXT 文本。


网络配置
网卡命名：传统 eth0，新版 ens33、enp0s3 等基于固件和位置。
配置文件：CentOS 在 /etc/sysconfig/network-scripts/ifcfg 网卡名，Ubuntu 用 netplan 的 yaml。新版用 NetworkManager。
配置项：IP 地址、子网掩码、网关、DNS、是否开机启动、静态或 DHCP。
NetworkManager：nmcli 命令行管理，nmtui 图形界面。


路由
路由表：目的网络、子网掩码、网关、接口、metric。
默认路由：0.0.0.0，匹配所有，最后匹配。
路由决策：最长前缀匹配优先，metric 小的优先。
静态路由：手动配，适合小网络。
动态路由：协议自动学，如 RIP、OSPF、BGP。


NAT
作用：地址转换，私网访问公网，节省公网 IP。
SNAT：源地址转换，内网出外网。
DNAT：目的地址转换，外网访问内网服务，端口映射。
PAT：端口地址转换，多内网共享一个公网 IP。
iptables 实现：nat 表，PREROUTING 做 DNAT，POSTROUTING 做 SNAT。


抓包分析
tcpdump 常用：指定网卡、指定主机、指定端口、指定协议、写文件。
Wireshark：图形化分析，看三次握手、四次挥手、重传、乱序。
排查方向：丢包、重传、延迟、连接拒绝、连接超时。
```

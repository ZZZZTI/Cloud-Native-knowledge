### 调度

```Shell
# 调度
调度流程：过滤（Filter）：排除不满足条件的节点→ 打分（Score）：选最高分→ 绑定（Bind），失败则Pod停在Pending
影响调度的因素：
resources.requests（节点剩余可分配资源）
nodeSelector（标签匹配）
nodeAffinity：硬约束（过滤阶段）/软约束（打分阶段）
podAffinity/podAntiAffinity：让新 Pod 倾向/避免与某些现有 Pod 运行在同一个拓扑域
topologySpreadConstraints：精确控制每个拓扑域的数量差异

污点（Taint）：打在节点上的“标签”，表明该节点具有某种特殊属性（如专用 GPU、故障状态），默认排斥所有 Pod。
容忍（Toleration）：Pod 的“通行证”，允许其被调度到带有对应污点的节点上。
```

### 排障

```Shell
1. 看现象：是 Pod 问题？Service 问题？Ingress 问题？节点问题？应用问题？
2. kubectl get：确认资源状态（Running/Pending/CrashLoopBackOff）
3. kubectl describe：看 Events，找关键错误信息
4. kubectl logs / --previous：看应用日志
5. kubectl exec：进容器验证配置、网络、文件
6. 查 Service/Endpoints：Endpoints 是否为空？selector 是否匹配？
7. 查 DNS：nslookup / dig 测试域名解析
8. 查 NetworkPolicy：是否被隔离？
9. 查存储：PVC 是否 Bound？PV 是否可用？
10. 查节点/控制面：kubelet、apiserver、etcd 是否正常？

kubectl get pods -A -o wide                 # 全局视角
kubectl get pod <pod> -o yaml               # 查看完整状态（status.conditions）
kubectl describe pod <pod>                  # 【最重要】看 Events
kubectl get events -A --sort-by=.metadata.creationTimestamp
kubectl get endpoints <svc>                 # 检查 Service 后端
kubectl get endpointslices                  # 新版端点切片
kubectl get pv,pvc,sc                       # 存储链路
kubectl get nodes -o wide                   # 节点状态
kubectl top nodes / kubectl top pods        # 需 Metrics Server
kubectl logs <pod>                          # 当前日志
kubectl logs <pod> --previous               # 上次崩溃日志（CrashLoopBackOff 必看）
kubectl logs -f <pod> --tail=100            # 实时跟踪
kubectl logs <pod> -c <container>           # 多容器指定容器
kubectl exec -it <pod> -- sh                # 进入容器
kubectl cp <pod>:/path ./local              # 拷贝文件
kubectl port-forward svc/<svc> 8080:80      # 本地访问
kubectl debug <pod> -it --image=busybox     # 临时调试容器（不改变原 Pod）
kubectl debug node/<node> -it --image=busybox  # 调试节点
kubectl auth can-i --list                   # 检查权限
crictl ps -a        # 查看所有容器
crictl logs <id>    # 查看容器日志

码  含义	              典型场景
0	  正常退出	         Job 完成；前台进程退出也会 0 → CrashLoopBackOff
1	  应用报错退出	      配置错误、依赖连不上、参数不合法
126	命令不可执行	      入口脚本没有可执行权限
127	命令找不到	command  写了镜像里没有的二进制
137	128+9(SIGKILL)	  OOMKilled 或 kubectl delete 强杀
143	128+15(SIGTERM)	  优雅终止超时后被杀
139	SIGSEGV	          程序段错误（架构不匹配最常见）
```

### 安全

```Shell
请求 → [认证 Authentication] → [授权 Authorization] → [准入控制 Admission] → etcd

# RBAC (授权 Authorization)
资源	               作用范围	  说明
Role	              命名空间内	 定义一组权限规则
RoleBinding	        命名空间内	 把 Role 绑定到用户/组/ServiceAccount
ClusterRole	        集群级别	  定义集群级权限，或跨命名空间复用
ClusterRoleBinding	集群级别	  把 ClusterRole 绑定到用户/组/ServiceAccount
 
# Role：只读 pods
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: default
  name: pod-reader
rules:
  - apiGroups: [""]                  # API 组，空字符串表示核心组
    resources: ["pods", "pods/log"]  # 资源类型
    verbs: ["get", "list", "watch"]  # 允许的操作
---
# RoleBinding：绑定到 SA
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-pods
  namespace: default
subjects:
  - kind: ServiceAccount
    name: app-sa
    namespace: default
roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
  
kubectl auth can-i get pods  # 当前用户能否 get pods
kubectl auth can-i get pods --as=system:serviceaccount:default:app-sa -n default # 模拟指定 SA
kubectl auth can-i --list   # 列出当前用户所有权限

# SecurityContext
spec:
  securityContext:
    runAsNonRoot: true      # 禁止以 root 运行
    runAsUser: 1000         # 指定 UID
    runAsGroup: 3000        # 指定 GID
    fsGroup: 2000           # 挂载卷的组所有权，影响 PVC 权限
    seccompProfile:
      type: RuntimeDefault
  containers:
    - name: app
      image: my-app:1.0
      securityContext:
        allowPrivilegeEscalation: false   # 禁止提权
        readOnlyRootFilesystem: true      # 根文件系统只读
        capabilities:
          drop: ["ALL"]                   # 丢弃所有 Linux capabilities


┌─────────────────────────────────────────────────────┐
│ 4C 模型：Cloud → Cluster → Container → Code          │
├─────────────────────────────────────────────────────┤
│ 请求三关：认证 → 授权（RBAC）→ 准入（PSA/Webhook）       │
├─────────────────────────────────────────────────────┤
│ 身份：ServiceAccount（短期 Token + 最小权限）           │
├─────────────────────────────────────────────────────┤
│ 运行时：SecurityContext（非 root、只读、drop ALL）      │
├─────────────────────────────────────────────────────┤
│ 网络：NetworkPolicy（默认拒绝 + 白名单）                │
├─────────────────────────────────────────────────────┤
│ 供应链：Trivy 扫描 + Cosign 签名 + digest 固定         │
├─────────────────────────────────────────────────────┤
│ 审计：API Server Audit Log（事后追溯）                 │
└─────────────────────────────────────────────────────┘
```



### 包管理：Helm

```Shell
# ---------- 一、仓库管理 (Repo) ----------
helm repo add <repo-name> <url>          # 添加仓库
helm repo add ingress-nginx https://helm-charts.itboon.top/ingress-nginx
helm repo list                           # 列出已添加的仓库
helm repo update                         # 更新仓库索引（添加新仓库后必做）
helm repo remove <repo-name>             # 移除仓库

# ---------- 二、查找与查看 (Search & Inspect) ----------
helm search repo <keyword>               # 在已添加的仓库中搜索 Chart
helm search hub <keyword>                # 在 Artifact Hub 中搜索
helm show values <repo>/<chart>          # 【重要】查看 Chart 默认的 values.yaml
helm show readme <repo>/<chart>          # 查看 Chart 的说明文档
helm show chart <repo>/<chart>           # 查看 Chart 的基本信息

# ---------- 三、安装、升级与卸载 (Install / Upgrade / Uninstall) ----------
helm install <release-name> <chart> -n <namespace>                # 安装（存在会报错）
helm upgrade --install <release> <chart> -n <namespace> -f values.yaml  # 【最常用】安装或升级
helm uninstall <release-name> -n <namespace>                      # 卸载
helm uninstall <release-name> -n <namespace> --keep-history       # 卸载但保留历史（可回滚）

# 常用参数解析：
# --install          : 不存在时自动安装
# -n <namespace>     : 指定命名空间（不存在可加 --create-namespace）
# --set key=value    : 命令行覆盖单个值（带方括号需加单引号，如 'a.b[0].c=x'）
# -f values.yaml     : 从文件读取配置
# --wait             : 等待所有资源就绪
# --timeout 10m      : 超时时间
# --atomic           : 升级失败自动回滚（生产环境强烈建议）

# ---------- 四、查看状态 (List & Status) ----------
helm list                                # 列出当前命名空间下的 Release
helm list -A                             # 列出所有命名空间的 Release
helm status <release-name> -n <namespace>               # 查看 Release 详细状态
helm get manifest <release-name> -n <namespace>         # 【排错神器】查看渲染后的 K8s YAML
helm get values <release-name> -n <namespace>           # 查看实际生效的 values

# ---------- 五、版本控制与回滚 (History & Rollback) ----------
helm history <release-name> -n <namespace>              # 查看发布历史
helm rollback <release-name> <revision> -n <namespace>  # 回滚到指定版本
helm rollback <release-name> -n <namespace>             # 回滚到上一个版本

# ---------- 六、本地开发与调试 (Template & Lint) ----------
helm create <chart-name>                 # 创建 Chart 脚手架
helm template <release-name> ./<chart> -f values.yaml   # 【极力推荐】本地渲染模板，不部署
helm lint ./<chart>                      # 检查 Chart 语法错误
helm package ./<chart>                   # 打包 Chart 为 .tgz 文件
```

声明式 API：用户提交「期望状态」（YAML），而不是「执行步骤」。
控制器循环（Reconcile Loop）：观察实际状态 → 与期望状态比较 → 采取动作缩小差异，永不停止。
一切皆对象：所有资源都通过 apiserver 读写 etcd，没有带外状态。
松耦合：组件之间只通过 apiserver 通信，不直接互相调用。

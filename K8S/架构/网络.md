> 网络：Service，Ingress，CoreDNS，Endpoints，NetworkPolicy

------

### 网络通信与服务发现

```Shell
外部客户端
   |
Ingress       七层HTTP 路由规则，按 Host/Path 把请求分发到不同 Service（外部流量入口）
   |
Service       给易变的 Pod IP 一个稳定入口，提供稳定 VIP（四层负载均衡）
kube-proxy    把 VIP 请求按 Service 规则 DNAT 到某个 Pod IP
   |
EndpointSlice 自动维护的"Ready Pod IP 列表"（Headless 和 ExternalName 的 Endpoints 为空）
CoreDNS       集群内的 DNS 服务器，为 Service 和 Pod 提供 DNS 记录
   |
NetworkPolicy pod级别的防火墙（默认全通，加了策略就变默认拒绝，只放行白名单）
 CNI插件       Pod 网络的底层实现
   |
  pod
```

### Service.yaml

```Shell
# ============================================================
# ClusterIP 分配一个集群内部的虚拟 IP（VIP），用于集群内部通信，微服务之间的互相调用、内部数据库、缓存
# ============================================================
spec:
  type: ClusterIP             # 默认类型，分配集群内部虚拟 IP
  selector:
    app: my-app               # 【避坑】必须与 Pod 的 labels 完全一致，否则 Endpoints 为空
  ports:
    - name: http              # 端口命名（多端口时必须写，单端口可省略）
      protocol: TCP           # 支持 TCP / UDP / SCTP
      port: 80                # Service 自身暴露的端口（其他 Pod 访问这个端口）
      targetPort: 8080        # 【避坑】Pod 容器内真实监听的端口（通常是 containerPort）
  
  # --- 高级配置（可选）---
  sessionAffinity: ClientIP   # 会话保持：同一个客户端 IP 的请求始终打到同一个 Pod
  sessionAffinityConfig:
    clientIP:
      timeoutSeconds: 10800   # 会话保持超时时间（默认 3 小时）
      
  internalTrafficPolicy: Cluster # 默认。若设为 Local，集群内部访问优先转发给同节点的 Pod
  
# ============================================================
# NodePort 在每个 Node 的真实 IP 上开放一个端口，用于开发、测试环境，或者简单的对外暴露
# ============================================================
spec:
  type: NodePort              # 在每个 Node 上开放一个物理端口
  selector:
    app: my-app
  ports:
    - name: http
      protocol: TCP
      port: 80                # 集群内部访问的端口
      targetPort: 8080        # Pod 容器端口
      nodePort: 30080         # 【可选】节点暴露的端口（30000-32767）。不写则系统随机分配
      
  # --- 关键高级配置 ---
  externalTrafficPolicy: Local 
  # 默认是 Cluster（流量可能跨节点转发，丢失客户端真实 IP）。
  # 设为 Local 后，外部请求只会打到有该 Pod 的节点上，保留源 IP，减少一跳网络。
  # 【避坑】如果设为 Local，且你的节点没有运行该 Pod，访问该节点端口会超时（需要配合负载均衡器使用）。
  
# ============================================================
# LoadBalancer 向云平台申请外部负载均衡器，分配一个公网 IP，用于生产环境对外暴露服务
# ============================================================
apiVersion: v1
kind: Service
metadata:
  name: my-app-lb
  namespace: default
  annotations:
    # 【注意】不同云厂商的注解不同，用来控制 LB 的行为
    # 例如 AWS 指定使用 NLB，并开启跨可用区负载均衡
    service.beta.kubernetes.io/aws-load-balancer-type: "nlb"
    service.beta.kubernetes.io/aws-load-balancer-cross-zone-load-balancing-enabled: "true"
spec:
  type: LoadBalancer
  selector:
    app: my-app
  ports:
    - name: http
      port: 80
      targetPort: 8080
  externalTrafficPolicy: Local
  # 本地 Kind 集群如果没有安装 MetalLB，EXTERNAL-IP 会一直显示 <pending>

# ============================================================
# ExternalName 把 Service 的名字直接解析到外部的域名，用于集群内的应用访问集群外部的数据库
# ============================================================
spec:
  type: ExternalName
  externalName: mydb.rds.aliyuncs.com  # 直接写外部域名/CNAME
  # 注意：ExternalName 不需要 selector，也不需要 ports
  # 内部 Pod 直接访问 my-external-db 即可，DNS 会解析到真实的外部域名
```

### Ingress.yaml

```Shell
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: my-app-ingress
  namespace: default
  labels:
    app.kubernetes.io/name: my-app
  annotations:  # 以下注解针对 Nginx Ingress Controller
    # 1. 路径重写（最常用）：将 /api/ 前缀去掉，只把后面的路径转给后端
    nginx.ingress.kubernetes.io/rewrite-target: /$2
    # 2. 后端协议：如果后端 Service 是 HTTPS 的，需指定（默认 HTTP）
    # nginx.ingress.kubernetes.io/backend-protocol: "HTTPS"
    # 3. 超时设置（默认 60 秒）：针对大文件上传或长时间处理的接口
    nginx.ingress.kubernetes.io/proxy-connect-timeout: "10"
    nginx.ingress.kubernetes.io/proxy-read-timeout: "300"
    nginx.ingress.kubernetes.io/proxy-send-timeout: "300"
    # 4. 请求体大小限制（默认 1m），上传大文件必须调大，否则报 413
    nginx.ingress.kubernetes.io/proxy-body-size: "50m"
    # 5. 限流：基于客户端 IP 的每秒请求数（RPS）限制
    nginx.ingress.kubernetes.io/limit-rps: "10"
    # 6. 强制 HTTPS 重定向（如果配置了 TLS）
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    # 7. 跨域 CORS 配置
    nginx.ingress.kubernetes.io/enable-cors: "true"
    nginx.ingress.kubernetes.io/cors-allow-origin: "*"
spec:
  # 1. 指定 Ingress Controller 类型（K8s 1.18+ 必须指定，除非配置了默认 Controller）
  ingressClassName: nginx

  # 2. TLS 配置（HTTPS 证书）
  # 需要提前创建一个类型为 kubernetes.io/tls 的 Secret（包含 tls.crt 和 tls.key）
  tls:
    - hosts:
        - www.example.com
        - api.example.com
      secretName: my-app-tls-secret

  # 3. 路由规则（可以配置多个 host）
  rules:
    # --- 规则一：前端页面 ---
    - host: www.example.com
      http:
        paths:
          # 匹配根路径，转发给前端 Service
          - path: /
            pathType: Prefix      # Prefix：前缀匹配（推荐）；Exact：精确匹配；ImplementationSpecific
            backend:
              service:
                name: frontend-svc
                port:
                  number: 80      # 指定 Service 的 port（不是 targetPort）

    # --- 规则二：后端 API ---
    - host: api.example.com
      http:
        paths:
          # 匹配 /api/v1/ 等，利用 annotation 中的 rewrite-target: /$2 重写路径
          - path: /api(/|$)(.*)
            pathType: Prefix
            backend:
              service:
                name: backend-svc
                port:
                  name: http      # 也可以使用 name（前提是 Service 的 port 有 name 定义）
                  
          # 静态资源路由到特定 Service
          - path: /static
            pathType: Prefix
            backend:
              service:
                name: static-svc
                port:
                  number: 8080

  # 4. 默认后端（可选）：当所有 host 和 path 都没匹配上时，兜底处理的 Service（通常是 404 页面）
  defaultBackend:
    service:
      name: default-404-svc
      port:
        number: 80
```

### NetworkPolicy.yaml

```Shell
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-all
  namespace: default
# ================ 默认拒绝所有流量 ==========================
spec:
  podSelector: {}           # {} 表示选中当前命名空间下的【所有】Pod
  policyTypes:
    - Ingress               # 拒绝所有入站流量
# ========= 允许同命名空间内的特定 Pod 访问 ====================
spec:
  podSelector:
    matchLabels:
      app: backend          # 【目标】策略作用于带有 app=backend 标签的 Pod
  policyTypes:
    - Ingress
  ingress:
    - from:
        - podSelector:
            matchLabels:
          # 【来源】只允许带有 app=frontend 标签的 Pod 访问
          app: frontend
      ports:
        - protocol: TCP
          port: 8080        # 只允许访问 8080 端口
          
# =============== 允许跨命名空间访问 ==========================
spec:
  podSelector: {}           # 作用于 default 下的所有 Pod
  policyTypes:
    - Ingress
  ingress:
    - from:
        - namespaceSelector: # 【来源】选择命名空间
            matchLabels:
              kubernetes.io/metadata.name: monitoring  # K8s 1.21+ 自动打的命名空间标签
      ports:
        - protocol: TCP
          port: 9090
```

> k8s架构，生产级 Kubernetes 集群规划 → 前置 → 初始化 → HA → CNI → 证书 → 升级 → 验收
>

------

# 架构

```text
        kubectl / CI / ArgoCD
                 │ HTTPS :6443
                 ▼
   ┌─────────────────────────────────────────┐
   │  CONTROL PLANE                          │
   │  ┌───────────┐ ┌───────────┐            │
   │  │ apiserver │ │ scheduler │            │
   │  └───────────┘ └───────────┘            │
   │  ┌──────────────────┐ ┌────────┐        │
   │  │ controller-mgr   │ │  etcd  │        │
   │  └──────────────────┘ └────────┘        │
   └─────────────────────────────────────────┘
                 │
                 ▼
   ┌─────────────────────────────────────────┐
   │  WORKER NODE                            │
   │  kubelet ──CRI──> containerd ──> Pod    │
   │  kube-proxy  (iptables / ipvs rules)    │
   └─────────────────────────────────────────┘
   

设计哲学：声明式 API（提交期望状态而非步骤）、控制器循环（观察 → 比较 → 收敛，永不停止）、一切皆对象（组件间只经 apiserver 通信，无带外状态），松耦合：组件之间只通过 apiserver 通信，不直接互相调用。

一次 kubectl apply 的路径：apiserver 认证授权准入 → 写入 etcd → 控制器（如 Deployment）创建 ReplicaSet → 创建 Pod（未调度）→ scheduler 绑定节点 → kubelet 感知后经 CRI 拉起容器 → kube-proxy 更新规则。

插件：CoreDNS（服务发现）、CNI（Pod 网络，Calico/Cilium 支持 NetworkPolicy，Flannel 不支持）、Ingress Controller、metrics-server（`kubectl top` 与 HPA 依赖）。
```

| 组件 | 职责 | 注意 |
| :-- | :-- | :-- |
| `kube-apiserver` | 唯一入口，认证/授权/准入，读写 etcd | 无状态，可多实例，前置 LB |
| `etcd` | 保存集群全部状态，唯一持久化数据源 | 奇数节点；SSD；**必须备份** |
| `kube-scheduler` | 为新 Pod 选节点（Filter → Score → Bind） | 多实例时 leader 选举 |
| `kube-controller-manager` | 各类控制器，持续调和期望状态 | 内含几十个控制器 |
| `kubelet` | 节点代理，管 Pod 生命周期、执行探针、上报状态 | 10250；日志 `journalctl -u kubelet` |
| `kube-proxy` | 把 Service 转成 iptables/ipvs 转发规则 | 不是代理进程，只写规则 |
| `containerd` | 真正创建运行容器 | 通过 CRI 被 kubelet 调用 |
| `pod` | 最小执行单位 | 共享 Network Namespace，Volume |

# kubeadm集群

### 1.生产级规划

| 项 | 建议 |
| :-- | :-- |
| 控制平面数量 | **3 台**（etcd 需多数派，2 台反而不如 1 台） |
| 控制平面规格 | 4C / 8G 起，etcd 单独 SSD 数据盘 |
| etcd 拓扑 | Stacked（与控制面同机，简单）或 External（独立集群，故障域隔离） |
| Pod CIDR | 与宿主机网段、VPC 网段**不能重叠**，如 `10.244.0.0/16` |
| Service CIDR | 不与 Pod CIDR 重叠，如 `10.96.0.0/12` |
| 版本策略 | 全集群同一 minor；**升级一次只跨一个小版本** |
| 节点池 | 系统组件与业务负载分离，用污点 + 亲和 |
| 访问入口 | VIP（keepalived）或云 SLB，指向 `--control-plane-endpoint` |

### 2.系统前置配置

所有节点执行。

```bash
# 1. 关闭 swap（kubelet 默认拒绝在 swap 开启时启动）
swapoff -a
sed -ri 's/.*swap.*/#&/' /etc/fstab

# 2. 内核模块
cat > /etc/modules-load.d/k8s.conf <<EOF
overlay
br_netfilter
EOF
modprobe overlay && modprobe br_netfilter

# 3. 内核参数：网桥流量经 iptables + 开启转发
cat > /etc/sysctl.d/99-k8s.conf <<EOF
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
fs.inotify.max_user_watches         = 524288
net.core.somaxconn                  = 32768
EOF
sysctl --system

# 4. 时间同步（证书校验依赖时间）
timedatectl set-timezone Asia/Shanghai
systemctl enable --now chronyd

# 5. 主机名与 hosts（每个节点唯一）
hostnamectl set-hostname k8s-master-01
# /etc/hosts 中写入所有节点与 VIP

# 6. 文件句柄与进程数
printf '* soft nofile 655350\n* hard nofile 655350\n' > /etc/security/limits.d/99-k8s.conf

# 7. 防火墙：受控内网可关闭；否则按最小集放行
#    6443 apiserver | 2379-2380 etcd | 10250 kubelet | 10257/10259 控制面
#    8472/udp 或 4789/udp：CNI（Calico VXLAN / Flannel）
systemctl disable --now firewalld
```

检查：`swapon --show` 应为空；`sysctl net.ipv4.ip_forward` 为 1。

### 3.容器运行时（containerd）

```bash
dnf install -y containerd
mkdir -p /etc/containerd
containerd config default > /etc/containerd/config.toml

# ① 必须用 systemd cgroup 驱动，否则与 kubelet 冲突
sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml

# ② sandbox 镜像换成可达的仓库（国内环境）
sed -i 's#sandbox_image = .*#sandbox_image = "registry.aliyuncs.com/google_containers/pause:3.10"#' \
  /etc/containerd/config.toml

systemctl enable --now containerd

# crictl 指向 containerd（排障常用）
cat > /etc/crictl.yaml <<EOF
runtime-endpoint: unix:///run/containerd/containerd.sock
image-endpoint: unix:///run/containerd/containerd.sock
timeout: 10
EOF
```

**关键校验**：`containerd config dump | grep -i systemdcgroup` 必须是 `true`；`crictl ps` 能正常返回。

### 5.初始化控制平面

生产建议用配置文件而不是一长串 flag，便于版本化和复用。

```bash
kubeadm config print init-defaults > kubeadm-config.yaml
```

```yaml
apiVersion: kubeadm.k8s.io/v1beta4
kind: InitConfiguration
localAPIEndpoint:
  advertiseAddress: 192.168.1.11      # 本机 IP
  bindPort: 6443
nodeRegistration:
  criSocket: unix:///run/containerd/containerd.sock
  kubeletExtraArgs:
    - name: max-pods
      value: "200"
---
apiVersion: kubeadm.k8s.io/v1beta4
kind: ClusterConfiguration
kubernetesVersion: v1.31.0
controlPlaneEndpoint: "k8s-api.example.com:6443"   # VIP 或 DNS，HA 必须有
imageRepository: registry.aliyuncs.com/google_containers
networking:
  podSubnet: 10.244.0.0/16
  serviceSubnet: 10.96.0.0/12
  dnsDomain: cluster.local
apiServer:
  extraArgs:
    - name: audit-policy-file
      value: /etc/kubernetes/audit-policy.yaml
    - name: audit-log-path
      value: /var/log/kubernetes/audit.log
    - name: audit-log-maxage
      value: "30"
    - name: enable-admission-plugins
      value: NodeRestriction
  extraVolumes:                      # 审计文件必须挂进静态 Pod，否则读不到
    - { name: audit-policy, hostPath: /etc/kubernetes/audit-policy.yaml,
        mountPath: /etc/kubernetes/audit-policy.yaml, readOnly: true }
    - { name: audit-log, hostPath: /var/log/kubernetes, mountPath: /var/log/kubernetes }
etcd:
  local:
    dataDir: /var/lib/etcd          # 生产建议指向独立 SSD 盘
```

```bash
kubeadm init --config kubeadm-config.yaml --upload-certs --v=5

# kubeconfig
mkdir -p $HOME/.kube
cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
chown $(id -u):$(id -g) $HOME/.kube/config
export KUBECONFIG=$HOME/.kube/config

kubectl get nodes          # 应为 NotReady，等 CNI 装好
kubectl -n kube-system get pod
```

`--upload-certs` 会把控制平面证书加密上传到 `kube-system/kubeadm-certs`，供其他 master 加入时自动下载，**有效期 2 小时**。

### 6.高可用控制平面（3 master）

**VIP + LB**：所有节点通过 `k8s-api.example.com:6443` 访问，该域名解析到 VIP。

```bash
# 三台 master 都装
dnf install -y keepalived haproxy
```

```Shell
# /etc/keepalived/keepalived.conf（master-01，BACKUP 节点改 state 与 priority）
vrrp_instance VI_1 {
    state MASTER
    interface eth0
    virtual_router_id 51
    priority 100                 # BACKUP 用 90 / 80
    advert_int 1
    authentication { auth_type PASS; auth_pass k8s123 }
    virtual_ipaddress { 192.168.1.100/24 }
}

# /etc/haproxy/haproxy.cfg
frontend k8s-api
    bind *:6443
    mode tcp
    default_backend k8s-api-servers

backend k8s-api-servers
    mode tcp
    balance roundrobin
    option tcp-check
    server master-01 192.168.1.11:6443 check
    server master-02 192.168.1.12:6443 check
    server master-03 192.168.1.13:6443 check
```

```bash
systemctl enable --now keepalived haproxy
ip a | grep 192.168.1.100          # 确认 VIP 已在 MASTER 上

# 其余两台 master 加入
kubeadm join k8s-api.example.com:6443 \
  --token <token> \
  --discovery-token-ca-cert-hash sha256:<hash> \
  --control-plane \
  --certificate-key <key> \
  --apiserver-advertise-address=192.168.1.12
```

`--certificate-key` 用 `kubeadm init phase upload-certs --upload-certs` 重新生成；token 用 `kubeadm token create --print-join-command`。

**注意**：每台 master 的 `--apiserver-advertise-address` 必须写自己的 IP，不要写 VIP。

### 7.工作节点加入

```bash
kubeadm join k8s-api.example.com:6443 \
  --token <token> \
  --discovery-token-ca-cert-hash sha256:<hash>
```

```bash
# 在 master 上核对

```

token 默认 24 小时过期，长期可用 `kubeadm token create --ttl 0`（不建议）。

### 8.CNI 与核心插件

```bash
# Calico（生产常用，支持 NetworkPolicy）
kubectl apply -f https://raw.githubusercontent.com/projectcalico/calico/v3.28.2/manifests/calico.yaml
# 若 podSubnet 不是 192.168.0.0/16，需同步修改 CALICO_IPV4POOL_CIDR

# metrics-server（kubectl top / HPA 依赖）
kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
# 自签证书环境需加 --kubelet-insecure-tls

# Ingress Controller
helm upgrade --install ingress-nginx ingress-nginx \
  --repo https://kubernetes.github.io/ingress-nginx \
  -n ingress-nginx --create-namespace

kubectl get pod -n kube-system -l k8s-app=calico-node
kubectl get node                   # 应变为 Ready
```

**装完 CNI 前节点都是 NotReady，这是正常现象，不要去改节点状态。**

### 9.证书管理

```bash
# 默认：CA 10 年，其余叶子证书 1 年
kubeadm certs check-expiration

# 续期（全部）
kubeadm certs renew all
systemctl restart kubelet
# 续期后必须更新 kubeconfig，否则 kubectl 仍用旧证书
cp /etc/kubernetes/admin.conf $HOME/.kube/config

# 续期单个组件
kubeadm certs renew apiserver
```

证书到期表现：`kubectl` 报 `x509: certificate has expired`，或节点 NotReady。建议把 `certs check-expiration` 接进监控。

### 10.升级

```bash
# ① 前置：读 Release Notes、扫描废弃 API、备份 etcd（见「安全.md」）
kubeadm upgrade plan
pluto detect-api-resources

# ② 第一个控制平面节点
kubectl drain <cp-01> --ignore-daemonsets
dnf install -y kubeadm-1.31.1 --disableexcludes=kubernetes
kubeadm upgrade apply v1.31.1
dnf install -y kubelet-1.31.1 kubectl-1.31.1 --disableexcludes=kubernetes
systemctl daemon-reload && systemctl restart kubelet && kubectl uncordon <cp-01>

# ③ 其余控制平面（注意是 upgrade node，不是 apply）；④ 工作节点同理，多传 --delete-emptydir-data
for n in <cp-02> <cp-03> <worker-01>; do
  kubectl drain "$n" --ignore-daemonsets --delete-emptydir-data
  dnf install -y kubeadm-1.31.1 kubelet-1.31.1 --disableexcludes=kubernetes
  kubeadm upgrade node
  systemctl daemon-reload && systemctl restart kubelet && kubectl uncordon "$n"
done
```

**版本 skew 规则**：kubelet 可落后 kube-apiserver **2 个小版本**，kubectl 只允许 **±1**。一次只升一个 minor，不要跳版本。

### 11.集群验收

```bash
kubectl get nodes -o wide                     # 全部 Ready，无 SchedulingDisabled
kubectl get pod -A | grep -v Running          # 应为空（Job 的 Completed 除外）
kubectl -n kube-system get pod -l k8s-app=kube-dns     # 2 副本 Running
kubectl -n kube-system get pod -l k8s-app=calico-node  # 每节点 1 个 Ready
kubectl run test --image=busybox:1.36 --rm -it --restart=Never -- nslookup kubernetes.default
kubectl top node                              # metrics-server 生效
kubeadm certs check-expiration                # 剩余 > 30 天
etcdctl endpoint health --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key
swapon --show; timedatectl | head -1          # swap 为空、时间同步正常
```

除命令外还要确认这几项**没有命令能直接验证**：默认 StorageClass 能 Bound、etcd 定时备份**且做过恢复演练**、节点/容器/控制面/etcd 四层指标齐全。

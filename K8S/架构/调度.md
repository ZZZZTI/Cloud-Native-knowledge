> 调度：Filter（nodeSelector，nodeAffinity），Score，Taint/Toleration，配额与限制
>







### 核心概念

1. **调度流程**：`过滤（Filter）`→ 排除不满足条件的节点 → `打分（Score）`→ 选最高分 → 绑定（Bind）。失败则 Pod 停在 `Pending`。
2. **影响调度的因素**
   - `resources.requests`（硬约束：节点剩余可分配资源）
   - `nodeSelector`（最简单）
   - `nodeAffinity`：`requiredDuringSchedulingIgnoredDuringExecution`（硬）/`preferred...`（软）
   - `podAffinity` / `podAntiAffinity`：按 `topologyKey` 和已有 Pod 的标签聚散
   - `topologySpreadConstraints`：均匀分布（比反亲和更精细）
3. **Taint / Toleration**
   - `NoSchedule` / `PreferNoSchedule` / `NoExecute`（后者会驱逐不容忍的 Pod）
   - 控制面节点默认有 `node-role.kubernetes.io/control-plane:NoSchedule`（单节点 kind 为了让 addon 跑起来移除了部分 taint）
4. **优先级与抢占**：`PriorityClass`；高优先级 Pod 可以抢占低优先级的。
5. **资源与运行时**
   - CPU：可压缩资源，超 `limits` 被 **throttle**（`container_cpu_cfs_throttled_seconds_total`）
   - 内存：不可压缩，超 `limits` 被 **OOMKilled**（`describe pod` 看 `Reason: OOMKilled`，退出码 137）
   - `requests` 决定 QoS 与调度；`limits` 决定上限
6. **配额与限制**：`ResourceQuota`（命名空间总量）、`LimitRange`（单个对象的默认值/上下限）
7. **弹性**：HPA（副本数）/ VPA（资源大小）/ Cluster Autoscaler（节点数）



```Shell
# 调度
调度流程：过滤（Filter）：排除不满足条件的节点→ 打分（Score）：选最高分→ 绑定（Bind），失败则Pod停在Pending
影响调度的因素：
resources.requests（节点剩余可分配资源）
nodeSelector（标签匹配）
nodeAffinity：硬约束（过滤阶段）/软约束（打分阶段）
podAffinity/podAntiAffinity：让新 Pod 倾向/避免与某些现有 Pod 运行在同一个拓扑域
topologySpreadConstraints：精确控制每个拓扑域的数量差异

污点（Taint）：打在节点上的“标签”，表明该节点具有某种特殊属性（如专用 GPU、故障状态），默认排斥所有 Pod。
容忍（Toleration）：Pod 的“通行证”，允许其被调度到带有对应污点的节点上。


# Qos class（服务质量）：是 K8s 用来决定 Pod 在节点资源紧张时优先级的一种机制。
1.Guaranteed（保证型）：资源分配最稳定，最不容易被驱逐。
条件：Pod 中每一个容器的 requests 必须严格等于 limits
2.Burstable（突发型）：允许容器在空闲时突发使用超出 requests 的资源，但不能超过 limits
条件：Pod 中至少有一个容器设置了 requests 或 limits。
3.BestEffort（尽力而为型）：一旦节点资源紧张，这类 Pod 会被最先杀掉。
条件：Pod 中所有容器都没有设置任何 requests 和 limits。


# -----------------------------------------------------------------------------
# 七、节点维护与调度控制
# -----------------------------------------------------------------------------
kubectl cordon <node>                        # 将节点标记为不可调度（新 Pod 不会调度上去）
kubectl uncordon <node>                      # 解除不可调度标记
kubectl drain <node> --ignore-daemonsets --delete-emptydir-data  # 驱逐节点上的 Pod（维护前使用）
kubectl taint node <node> key=value:NoSchedule   # 给节点添加污点
kubectl taint node <node> key=value:NoSchedule-  # 移除污点（末尾加 -）
kubectl label node <node> disktype=ssd       # 给节点打标签
```

### 核心概念

1. **请求三关**：`认证（Authentication）`→`授权（Authorization）`→`准入控制（Admission）`。
2. **ServiceAccount**：Pod 的身份。现代用法是 Token 投射（`automountServiceAccountToken: false` + projected volume），不再是永久 Secret。
3. **RBAC 四件套**：`Role`（命名空间级）/`ClusterRole`（集群级）/`RoleBinding`/`ClusterRoleBinding`。
   - 规则三要素：`apiGroups` + `resources` + `verbs`
   - 常用调试：`kubectl auth can-i get pods --as=system:serviceaccount:default:app-sa -n default`
4. **SecurityContext**
   - `runAsNonRoot: true`、`runAsUser`、`fsGroup`
   - `readOnlyRootFilesystem: true`（配合 emptyDir 挂 `/tmp`）
   - `allowPrivilegeEscalation: false`、`capabilities.drop: ["ALL"]`
   - `seccompProfile.type: RuntimeDefault`
5. **Pod Security Admission（PSA）**：命名空间标签 `pod-security.kubernetes.io/enforce: restricted|baseline|privileged`（1.25+ 替代 PSP）。
6. **网络隔离**：NetworkPolicy（本集群 kindnet 已支持并执行；需要 ipBlock 等更完整特性时再上 Calico/Cilium）
7. **供应链**：镜像扫描（Trivy）、镜像签名（cosign）、`imagePullPolicy: Always` + 固定 digest。
8. **审计**：API Server audit log（思路了解即可）。





## 调度

### 节点选择

| 机制                        | 写法                                       | 特点                 |
| :-------------------------- | :----------------------------------------- | :------------------- |
| `nodeSelector`              | 精确匹配标签                               | 最简单，硬性要求     |
| `nodeAffinity`              | `requiredDuring...` / `preferredDuring...` | 支持操作符与软硬两种 |
| `podAffinity`               | 与某些 Pod 靠拢                            | 需指定 `topologyKey` |
| `podAntiAffinity`           | 与某些 Pod 远离                            | **多副本打散的关键** |
| `topologySpreadConstraints` | 按拓扑域均匀分布                           | 比反亲和更精细       |
| `taints` + `tolerations`    | 节点排斥 Pod                               | 用于专用节点、驱逐   |

```yaml
# 硬亲和：必须落在 SSD 节点
affinity:
  nodeAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:
      nodeSelectorTerms:
        - matchExpressions:
            - key: disktype
              operator: In
              values: ["ssd"]

# 拓扑打散：跨可用区均匀
topologySpreadConstraints:
  - maxSkew: 1
    topologyKey: topology.kubernetes.io/zone
    whenUnsatisfiable: DoNotSchedule     # 或 ScheduleAnyway
    labelSelector:
      matchLabels: { app: web }
```

### 污点与容忍

```bash
kubectl taint nodes node1 gpu=true:NoSchedule        # 加污点
kubectl taint nodes node1 gpu=true:NoSchedule-       # 删污点
```

三种效果：`NoSchedule`（不调度新 Pod）、`PreferNoSchedule`（尽量不调度）、`NoExecute`（**驱逐**已在运行的、不容忍的 Pod）。

内置污点（节点异常时 kubelet 自动打）：

| 污点                                     | 触发条件         |
| :--------------------------------------- | :--------------- |
| `node.kubernetes.io/not-ready`           | 节点未就绪       |
| `node.kubernetes.io/unreachable`         | 节点失联         |
| `node.kubernetes.io/disk-pressure`       | 磁盘不足         |
| `node.kubernetes.io/memory-pressure`     | 内存不足         |
| `node.kubernetes.io/pid-pressure`        | PID 耗尽         |
| `node.kubernetes.io/network-unavailable` | 网络未就绪       |
| `node.kubernetes.io/unschedulable`       | 被 cordon        |
| `node-role.kubernetes.io/control-plane`  | 控制平面默认污点 |

Pod 默认自动容忍 `not-ready` 和 `unreachable` **300 秒**（`tolerationSeconds`），这就是节点宕机后 Pod 要等 5 分钟才被重新调度的原因。

### 节点维护

```bash
kubectl cordon node1                              # 标记不可调度（不驱逐现有 Pod）
kubectl drain node1 --ignore-daemonsets \
                   --delete-emptydir-data          # 驱逐所有 Pod（含 emptyDir 数据的）
# ... 维护 ...
kubectl uncordon node1                            # 恢复调度
```

`drain` 会遵守 PodDisruptionBudget，如果 PDB 阻止驱逐会一直卡住，用 `--disable-eviction` 或 `--force` 绕过（会破坏 PDB 保证，慎用）。

### 优先级与抢占

```yaml
apiVersion: scheduling.k8s.io/v1
kind: PriorityClass
metadata: { name: high-priority }
value: 1000000
globalDefault: false
preemptionPolicy: PreemptLowerPriority
```



高优先级 Pod 调度失败时会**抢占**（驱逐）低优先级 Pod。滥用会导致关键服务被反复驱逐。

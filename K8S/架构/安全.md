> 安全：授权（RBAC），pod身份，SecurityContext，PSA，恢复与备份

------

### 概念

```Shell
请求 → [认证 Authentication] → [授权 Authorization] → [准入控制 Admission] → etcd
        证书、Token、OIDC             RBAC               PSA、Kyverno

# RBAC (授权 Authorization)
资源	               作用范围	  说明
Role	              命名空间内	 定义一组权限规则
RoleBinding	        命名空间内	 把 Role 绑定到用户/组/ServiceAccount
ClusterRole	        集群级别	  定义集群级权限，或跨命名空间复用
ClusterRoleBinding	集群级别	  把 ClusterRole 绑定到用户/组/ServiceAccount

① 扫描（Trivy/Grype）→ 高危阻断构建
② 签名（cosign，签 digest 不签 tag）
③ 准入验证（Kyverno verifyImages / Gatekeeper）→ 未签名不允许调度

┌─────────────────────────────────────────────────────┐
│ 4C 模型：Cloud → Cluster → Container → Code          │
├─────────────────────────────────────────────────────┤
│ 请求三关：认证 → 授权（RBAC）→ 准入（PSA/Webhook）       │
├─────────────────────────────────────────────────────┤
│ 身份：ServiceAccount（短期 Token + 最小权限）           │
├─────────────────────────────────────────────────────┤
│ 运行时：SecurityContext（非 root、只读、drop ALL）      │
├─────────────────────────────────────────────────────┤
│ 网络：NetworkPolicy（默认拒绝 + 白名单）                │
├─────────────────────────────────────────────────────┤
│ 供应链：Trivy 扫描 + Cosign 签名 + digest 固定         │
├─────────────────────────────────────────────────────┤
│ 审计：API Server Audit Log（事后追溯）                 │
└─────────────────────────────────────────────────────┘
```

### Role/RoleBinding.yaml

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role                        # 命名空间级；ClusterRole 是集群级
metadata:
  namespace: dev
  name: pod-reader
rules:
  - apiGroups: [""]                   # API 组，空字符串表示核心组
    resources: ["pods", "pods/log"]   # 资源类型
    verbs: ["get", "list", "watch"]   # 允许的操作
# 常用 verbs：get list watch create update patch delete deletecollection
# 特殊资源：pods/exec、pods/portforward、pods/log
---

apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  namespace: dev
  name: pod-reader-binding
subjects:
  - kind: ServiceAccount          # User / Group / ServiceAccount
    name: dev-sa
    namespace: dev
roleRef:
  kind: Role                      # Role 或 ClusterRole
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

### 权限命令

```bash
kubectl auth can-i get pods  # 当前用户能否 get pods
kubectl auth can-i get pods --as=system:serviceaccount:default:app-sa -n default # 模拟指定 SA
kubectl auth can-i --list   # 列出当前用户所有权限
```

### ServiceAccount.yaml

```yaml
apiVersion: v1
kind: ServiceAccount
metadata: { name: app-sa, namespace: dev }
automountServiceAccountToken: false      # 不需要访问 apiserver 就关掉，减小攻击面
```

### Pod.spec.securityContext字段

```yaml
securityContext:
  runAsNonRoot: true                 # 拒绝以 root 运行
  runAsUser: 1000                    # 指定 UID
  runAsGroup: 1000                   # 指定 GID
  fsGroup: 2000                      # 挂载卷的属组
  seccompProfile:
  type: RuntimeDefault               # 系统调用过滤
  containers:
  - name: app
    image: my-app:1.0
    securityContext:
      allowPrivilegeEscalation: false    # 禁止提权（防 setuid）
      readOnlyRootFilesystem: true       # 只读根文件系统
      capabilities:
        drop: ["ALL"]                    # 丢弃所有能力
        add: ["NET_BIND_SERVICE"]        # 按需最小添加
```

### etcd 备份与恢复「定期自动备份 + 定期恢复演练」

### 备份

```bash
ETCDCTL_API=3 etcdctl \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key \
  snapshot save /backup/etcd-$(date +%F-%H%M).db

# 校验快照完整性
etcdctl snapshot status /backup/etcd-2026-10-09.db -w table
```

用 CronJob 或系统 cron 每天备份，并同步到异地/对象存储。

### 恢复

```bash
# 1. 停掉控制平面（把 manifest 移走，静态 Pod 就停了）
mkdir -p /tmp/manifests && mv /etc/kubernetes/manifests/* /tmp/manifests/

# 2. 从快照恢复到一个新数据目录
ETCDCTL_API=3 etcdctl snapshot restore /backup/etcd-2026-10-09.db \
  --data-dir=/var/lib/etcd-restore

# 3. 让 etcd 使用新数据目录（改 etcd manifest 的 hostPath / --data-dir）
#    单节点：直接改 /etc/kubernetes/manifests/etcd.yaml
#    多节点：需要 --initial-cluster 与 --initial-cluster-token 保持一致

# 4. 恢复 manifest，验证
mv /tmp/manifests/* /etc/kubernetes/manifests/
etcdctl endpoint health --endpoints=https://127.0.0.1:2379 \
  --cacert=... --cert=... --key=...
kubectl get nodes
```

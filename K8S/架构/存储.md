### 核心概念

1. **卷的类型谱系**
   - 临时：`emptyDir`（Pod 删除即丢，容器崩溃不丢）
   - 节点本地：`hostPath`（**危险**，仅实验用）、`local`
   - 配置：`configMap`/`secret`/`projected`/`downwardAPI`
   - 持久：`persistentVolumeClaim`
2. **PV / PVC / StorageClass 三角关系**
   - PVC 是"用户的申请单"（要多大、什么访问模式），PV 是"实际的盘"。
   - 绑定条件：容量 ≥ 申请、accessModes 匹配、storageClassName 一致、selector 匹配。
   - `accessModes`：`ReadWriteOnce`（单节点读写，最常用）/`ReadOnlyMany`/`ReadWriteMany`（需 NFS/CephFS 等）/`ReadWriteOncePod`。
   - `persistentVolumeReclaimPolicy`：`Retain`/`Delete`/`Recycle`。
3. **静态供给 vs 动态供给**
   - 静态：管理员先建 PV，PVC 去匹配。
   - 动态：PVC 指定 `storageClassName`，provisioner 自动建 PV（生产主流）。
   - `volumeBindingMode: WaitForFirstConsumer`：等 Pod 调度后再建盘（解决本地盘拓扑问题）。
4. **CSI**：容器存储接口，K8s 只定义接口，具体实现由厂商提供。
5. **StatefulSet + volumeClaimTemplates**：每个副本独立 PVC（`data-db-0`、`data-db-1`）。





### ConfigMap/Secret 命令创建

```Shell
# ==========================================
# 一、 创建 ConfigMap
# ==========================================
# 1. 从键值对创建
kubectl create configmap my-config --from-literal=APP_ENV=prod --from-literal=LOG_LEVEL=info

# 2. 从单个文件创建（key默认为文件名）
kubectl create configmap nginx-config --from-file=./nginx.conf

# 3. 从单个文件创建（自定义key名）
kubectl create configmap nginx-config --from-file=custom.conf=./nginx.conf

# 4. 从整个目录创建（目录下所有文件转为key）
kubectl create configmap all-configs --from-file=./configs/

# 5. 从 .env 格式文件创建（文件内为 KEY=VALUE 格式）
kubectl create configmap env-config --from-env-file=./app.env

# ==========================================
# 二、 创建 Secret
# ==========================================
# 1. 创建通用 Secret（直接输入明文，K8s自动Base64编码）
kubectl create secret generic db-secret --from-literal=DB_USER=admin --from-literal=DB_PASS=password123

# 2. 从文件创建 Secret
kubectl create secret generic file-secret --from-file=./id_rsa

# 3. 创建 TLS 证书 Secret（用于 Ingress HTTPS）
kubectl create secret tls my-app-tls --cert=./tls.crt --key=./tls.key

# 4. 创建拉取私有镜像的 Secret
kubectl create secret docker-registry regcred \
  --docker-server=https://index.docker.io/v1/ \
  --docker-username=myuser \
  --docker-password=mypassword

# ==========================================
# 三、 【高阶技巧】生成 YAML 但不创建（强烈推荐）
# ==========================================
# 只生成 YAML 文件，方便存入 Git 或用 kubectl apply 部署
kubectl create configmap my-config --from-literal=APP_ENV=prod --dry-run=client -o yaml > config.yaml
kubectl create secret generic db-secret --from-literal=DB_PASS=123 --dry-run=client -o yaml > secret.yaml
```

### ConfigMap.yaml

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: my-app-config
  namespace: default
data:
  # --- 方式一：简单的键值对（常用于环境变量注入） ---
  APP_ENV: "production"
  LOG_LEVEL: "info"
  
  # --- 方式二：多行配置文件（常用于挂载为文件） ---
  nginx.conf: |
    server {
        listen 80;
        server_name localhost;
        location / {
            root /usr/share/nginx/html;
            index index.html;
        }
    }
    
  application.properties: |
    spring.datasource.url=jdbc:mysql://db:3306/mydb
    spring.datasource.username=admin
    # 密码不要写在这里，应该放 Secret

# --- 高级配置 ---
# immutable: true   # 设为 true 后，该 ConfigMap 不可修改（改了只能删了重建）。
                    # 好处：防止误改引发线上故障，且 kubelet 不需要监听其变化，提升性能。
```

### configMap/secret 挂载到 Pod

```yaml
# 全部注入为环境变量（适合轻量级配置）：注入后修改，Pod的环境变量不会热更新，必须重建Pod才能生效
   spec:
      containers:
        - name: my-app
          image: my-app:1.0
          env: # 单条注入自定义
            - name: DB_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: my-app-secret
                  key: DB_PASS
                  optional: false    # 找不到 key 则 Pod 启动失败
          envFrom: # 批量注入整个yaml
            - configMapRef:
                name: my-app-config  # configMap文件名
          
# 全部挂载为文件目录（适合配置文件，支持热更新）：修改后，这里的文件会自动热更新（延迟几十秒）。
    spec:

      containers:
      # configMap
        - name: my-app1
          image: nginx
          volumeMounts:
            - name: config-vol
              mountPath: /etc/nginx/conf.d   # 挂载到一个目录
      # secret
        - name: my-app2
          image: my-app:1.0
          volumeMounts:
            - name: secret-vol
              mountPath: /etc/app/secret
              readOnly: true         # 强制只读
      volumes:
        - name: config-vol
          configMap:
            name: my-app-config
            defaultMode: 0644
        - name: secret-vol
          secret:
            secretName: my-app-secret
            defaultMode: 0400        # 【安全关键】只允许属主读取（-r--------）
            
# 精准挂载特定 Key（使用 items 重命名）：使用subPath 挂载的文件不支持热更新
    spec:
      containers:
        - name: my-app
          image: nginx
          volumeMounts:
            - name: config-vol
              mountPath: /etc/nginx/nginx.conf  # 直接挂载为单个文件
              subPath: nginx.conf               # 使用 subPath 指定文件
      volumes:
        - name: config-vol
          configMap:
            name: my-app-config
            items:
              - key: nginx.conf                 # 只提取这个 key
                path: nginx.conf                # 文件名保持不变
                mode: 0644                      # 单独设定权限
```

```Shell
# ============================================================
# PersistentVolumeClaim (PVC) 持久化存储声明 （管理员可以申请PV，StorageClass资源）
# 作用：为 Pod 申请持久化存储，与底层 PV 绑定
# ============================================================
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: app-pvc
  namespace: demo-namespace
spec:
  accessModes:
    - ReadWriteOnce    # RWO：单节点读写；ROX：多节点只读；RWX：多节点读写
  resources:
    requests:
      storage: 1Gi     # 申请 1GiB 存储空间
  storageClassName: standard  # 指定存储类，取决于集群环境（如 local-path, nfs-client 等）
```

### Secret

```bash
kubectl create secret generic db-secret \
  --from-literal=password='S3cr3t!' \
  --from-literal=username=app

kubectl create secret docker-registry regcred \
  --docker-server=registry.example.com \
  --docker-username=robot \
  --docker-password='xxx' \
  --docker-email=ops@example.com

kubectl create secret tls web-tls --cert=tls.crt --key=tls.key
```

| 类型                                    | 用途                                    |
| :-------------------------------------- | :-------------------------------------- |
| `Opaque`                                | 通用键值（默认）                        |
| `kubernetes.io/dockerconfigjson`        | 私有镜像仓库凭据，配 `imagePullSecrets` |
| `kubernetes.io/tls`                     | Ingress 证书                            |
| `kubernetes.io/service-account-token`   | SA 令牌                                 |
| `kubernetes.io/basic-auth` / `ssh-auth` | 基础认证 / SSH                          |

**关键认知**：

- Secret 只是 **base64 编码，不是加密**。有 etcd 读权限或 `get secret` 权限的人都能还原明文。
- 生产必须开启 **静态加密**：apiserver 加 `--encryption-provider-config`，provider 可选 `aescbc` / `aesgcm` / `secretbox` / `kms`（KMS 最安全，密钥在外部）。
- 更彻底的做法是外部密钥管理：Sealed Secrets / External Secrets Operator / Vault + CSI Driver。
- 用 `stringData` 可以直接写明文，apiserver 会帮忙编码（写入后 `data` 里是 base64）。

### Downward API

把 Pod 自身的元数据注入容器，无需调用 apiserver：

```yaml
env:
  - name: POD_NAME
    valueFrom: { fieldRef: { fieldPath: metadata.name } }
  - name: NODE_NAME
    valueFrom: { fieldRef: { fieldPath: spec.nodeName } }
  - name: CPU_LIMIT
    valueFrom: { resourceFieldRef: { containerName: app, resource: limits.cpu } }
```

## 存储

### Volume 类型

| 类型                    | 生命周期     | 典型用途                                                |
| :---------------------- | :----------- | :------------------------------------------------------ |
| `emptyDir`              | 随 Pod 销毁  | 临时缓存、多容器共享目录                                |
| `hostPath`              | 绑定节点目录 | **危险**，Pod 漂移后数据不跟随；仅用于 DaemonSet 类     |
| `configMap` / `secret`  | 随 Pod       | 配置文件注入                                            |
| `downwardAPI`           | 随 Pod       | 元数据注入                                              |
| `projected`             | 随 Pod       | 把多个来源合成一个目录（SA token + configmap + secret） |
| `persistentVolumeClaim` | 独立于 Pod   | 生产持久化数据的唯一正确选择                            |
| `csi`                   | 由驱动决定   | 云盘/NFS/对象存储，现代存储接入方式                     |

### PV / PVC / StorageClass

```yaml
# StorageClass：定义「用哪种存储、怎么供应」
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata: { name: fast-ssd }
provisioner: ebs.csi.aws.com
parameters: { type: gp3 }
reclaimPolicy: Delete                    # Retain 保留数据（生产重要数据选它）
allowVolumeExpansion: true               # 允许在线扩容 PVC
volumeBindingMode: WaitForFirstConsumer  # 等 Pod 调度后再创建卷（多可用区必须）
---
# PVC：用户的存储申请
apiVersion: v1
kind: PVC
metadata: { name: data }
spec:
  accessModes: ["ReadWriteOnce"]
  storageClassName: fast-ssd
  resources:
    requests: { storage: 20Gi }
```

**绑定流程**：

- 静态供应：管理员先建 PV → PVC 按 `capacity` + `accessModes` + `storageClassName` 匹配 → 绑定。
- 动态供应：StorageClass 里有 provisioner → 创建 PVC 时自动生成 PV。
- PVC 处于 `Pending` 一般是：没有匹配的 PV / StorageClass 不存在 / `WaitForFirstConsumer` 但还没有 Pod 用它。

**Access Modes**：

| 模式             | 缩写 | 说明                                           |
| :--------------- | :--- | :--------------------------------------------- |
| ReadWriteOnce    | RWO  | 单节点读写（云盘基本都是这个，**不是单 Pod**） |
| ReadOnlyMany     | ROX  | 多节点只读                                     |
| ReadWriteMany    | RWX  | 多节点读写（需要 NFS/CephFS 等共享存储）       |
| ReadWriteOncePod | RWOP | 单 Pod 读写（1.22+，最严格）                   |

**Reclaim Policy**：`Delete`（默认动态供应）删 PVC 就删数据；`Retain` 保留卷需手动清理。**生产重要数据务必确认是 Retain**。

```bash
kubectl get pv,pvc -A
kubectl describe pvc data
kubectl get storageclass
# 扩容（需 StorageClass 允许）
kubectl patch pvc data -p '{"spec":{"resources":{"requests":{"storage":"50Gi"}}}}'
```

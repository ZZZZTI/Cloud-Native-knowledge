> 配置与密钥：configmap和sercet，存储：PV，PVC，StorageClass 

------

### volume

```Shell
# 存储
volume类型	       特点	                                   适用场景
emptyDir	        Pod内容器共享的临时目录 Pod删除后数据丢失 	  容器间共享临时文件、缓存
hostPath	        挂载宿主机目录 Pod删除后数据保留 	          单节点测试、访问宿主机文件
configMap/secret	把常规配置/敏感配置（密钥）挂载为文件	        配置注入
PVC	              挂载 PVC，获得持久化存储	                 生产环境持久化数据
nfs	              挂载 NFS 共享	                           多节点共享读写
CSI	              通过 CSI 驱动挂载任意存储	                 云盘、Ceph、SAN 等

# 三者关系
PV	          集群级	     “实际的盘”：NFS、云盘、Ceph RBD、本地盘等
PVC	          命名空间级	  “用户的申请单”：要多大、什么访问模式、哪个 StorageClass
StorageClass  集群级	     “供给模板”：用哪个 provisioner、什么参数、绑定模式、回收策略

# pvc和pv的绑定条件
容量 ≥ 申请：           PV 容量不能小于 PVC 的 resources.requests.storage。
accessModes 匹配：     PV 支持的访问模式要覆盖 PVC 请求。
storageClassName 一致：PVC 指定的 SC 与 PV 的 storageClassName 匹配；空值也有语义差异。
selector 匹配：        如果 PVC 配了 selector，PV 标签要匹配。

用户创建 PVC（指定 storageClassName） ──► StorageClass ──► 自动创建 PV ──► 自动绑定
```

### ConfigMap/Secret 命令创建

```Shell
# ConfigMap
# 1. 从键值对创建
kubectl create configmap my-config --from-literal=APP_ENV=prod --from-literal=LOG_LEVEL=info
# 2. 从单个文件创建（key默认为文件名）
kubectl create configmap nginx-config --from-file=./nginx.conf
# 3. 从单个文件创建（自定义key名）
kubectl create configmap nginx-config --from-file=custom.conf=./nginx.conf
# 4. 从整个目录创建（目录下所有文件转为key）
kubectl create configmap all-configs --from-file=./configs/
# 5. 从 .env 格式文件创建（文件内为 KEY=VALUE 格式）
kubectl create configmap env-config --from-env-file=./app.env

# Secret
# 1. 创建通用 Secret（直接输入明文，K8s自动Base64编码）
kubectl create secret generic db-secret --from-literal=DB_USER=admin --from-literal=DB_PASS=password123
# 2. 从文件创建 Secret
kubectl create secret generic file-secret --from-file=./id_rsa
# 3. 创建 TLS 证书 Secret（用于 Ingress HTTPS）
kubectl create secret tls my-app-tls --cert=./tls.crt --key=./tls.key
# 4. 创建拉取私有镜像的 Secret
kubectl create secret docker-registry regcred \
  --docker-server=https://index.docker.io/v1/ \
  --docker-username=myuser \
  --docker-password=mypassword
```

### ConfigMap.yaml

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: my-app-config
  namespace: default
immutable: false            # true 则不可修改，性能更好、防止误改
data:
  # --- 方式一：简单的键值对（常用于环境变量注入） ---
  APP_ENV: "production"
  LOG_LEVEL: "info"
  
  # --- 方式二：多行配置文件（常用于挂载为文件） ---
  nginx.conf: |
    server {
        listen 80;
        server_name localhost;
        location / {
            root /usr/share/nginx/html;
            index index.html;
        }
    }
    
  application.properties: |
    spring.datasource.url=jdbc:mysql://db:3306/mydb
    spring.datasource.username=admin
```

### Secret.yaml

```yaml
# ============================================================
# 类型一：Opaque（通用类型，用于存密码、API Key 等）
# ============================================================
apiVersion: v1
kind: Secret
metadata:
  name: my-app-secret
  namespace: default
type: Opaque
data:
  # 【注意】data 下的值必须是 Base64 编码后的字符串
  # 编码命令：echo -n 'admin' | base64  =>  YWRtaW4=
  DB_USER: YWRtaW4=
  DB_PASS: cGFzc3dvcmQxMjM=
stringData:
  # 【推荐用法】stringData 允许直接写明文，K8s 会自动帮你转成 Base64 存入 etcd
  API_KEY: "my-super-secret-key-123"

---
# ============================================================
# 类型二：kubernetes.io/tls（用于 Ingress HTTPS 证书）
# ============================================================
apiVersion: v1
kind: Secret
metadata:
  name: my-app-tls
  namespace: default
type: kubernetes.io/tls
data:
  # 必须提前把证书和私钥转成 Base64
  tls.crt: LS0tLS1CRUdJTi... # Base64 编码的证书
  tls.key: LS0tLS1CRUdJTi... # Base64 编码的私钥

---
# ============================================================
# 类型三：kubernetes.io/dockerconfigjson（用于拉取私有镜像）
# ============================================================
apiVersion: v1
kind: Secret
metadata:
  name: my-registry-secret
  namespace: default
type: kubernetes.io/dockerconfigjson
data:
  # 这个值是通过 docker login 或 kubectl create 命令生成的
  .dockerconfigjson: eyJhdXRocyI6eyJodHRwczovL2luZGV4LmRvY2tlci5pby92MS8iOnsidXNlcm5hbWUiOiJteXVzZXIiLCJwYXNzd29yZCI6Im15cGFzcyIsImVtYWlsIjoi...
```

### configMap/secret 挂载到 Pod

```yaml
# 全部注入为环境变量（适合轻量级配置）：注入后修改，Pod的环境变量不会热更新，必须重建Pod才能生效
   spec:
      containers:
        - name: my-app
          image: my-app:1.0
          env: # 单条注入自定义
            - name: DB_PASSWORD
              valueFrom:
                secretKeyRef:
                  name: my-app-secret
                  key: DB_PASS
                  optional: false    # 找不到 key 则 Pod 启动失败
          envFrom: # 批量注入整个yaml
            - configMapRef:
                name: my-app-config  # configMap文件名
          
# 全部挂载为文件目录（适合配置文件，支持热更新）：修改后，这里的文件会自动热更新（延迟几十秒）。
    spec:

      containers:
      # configMap
        - name: my-app1
          image: nginx
          volumeMounts:
            - name: config-vol
              mountPath: /etc/nginx/conf.d   # 挂载到一个目录
      # secret
        - name: my-app2
          image: my-app:1.0
          volumeMounts:
            - name: secret-vol
              mountPath: /etc/app/secret
              readOnly: true         # 强制只读
      volumes:
        - name: config-vol
          configMap:
            name: my-app-config
            defaultMode: 0644
        - name: secret-vol
          secret:
            secretName: my-app-secret
            defaultMode: 0400        # 【安全关键】只允许属主读取（-r--------）
            
# 精准挂载特定 Key（使用 items 重命名）：使用subPath 挂载的文件不支持热更新
    spec:
      containers:
        - name: my-app
          image: nginx
          volumeMounts:
            - name: config-vol
              mountPath: /etc/nginx/nginx.conf  # 直接挂载为单个文件
              subPath: nginx.conf               # 使用 subPath 指定文件
      volumes:
        - name: config-vol
          configMap:
            name: my-app-config
            items:
              - key: nginx.conf                 # 只提取这个 key
                path: nginx.conf                # 文件名保持不变
                mode: 0644                      # 单独设定权限
```

### PVC.yaml

```yaml
# ============================================================
# 场景一：动态供应（最常用，推荐）
# 只需指定 StorageClass，K8s 会自动创建底层 PV 并绑定
# ============================================================
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-app-data-pvc
  namespace: default
spec:
  accessModes:
    - ReadWriteOnce       # 【必填】访问模式，RWO单节点读写，ROX多节点只读，RWX多节点读写，RWOP单Pod读写
  resources:
    requests:
      storage: 10Gi          # 【必填】申请容量
  storageClassName: standard # 【关键】指定存储类，取决于集群环境
  volumeMode: Filesystem     # 默认就是 Filesystem，如果是块设备则设为 Block

---
# ============================================================
# 场景二：静态绑定（手动指定已存在的 PV）
# 适用于管理员已经提前建好 PV 的场景
# ============================================================
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-static-pvc
  namespace: default
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 5Gi
  # volumeName: my-manual-pv      # 方式 A：直接指定 PV 名称（精准匹配）
    selector:                     # 方式 B：通过 Label 选择 PV（灵活匹配）
    matchLabels:
      type: local-ssd
      
# ============================================================
# 挂载
# ============================================================
spec:
  containers:
    - name: app
      image: nginx:1.27
      volumeMounts:
        - name: data
          mountPath: /usr/share/nginx/html   # 挂载到容器内的目录
  volumes:
    - name: data
      persistentVolumeClaim:
        claimName: my-app-data-pvc           # 引用上面创建的 PVC
```

### StorageClass.yaml

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: my-storage-class
  annotations:
    # 【可选】设为默认 SC。当用户创建 PVC 没指定 storageClassName 时，默认使用这个
    storageclass.kubernetes.io/is-default-class: "true"
    
# 【必填】存储供应商（Provisioner）
# 不同环境不同：云厂商如 ebs.csi.aws.com / disk.csi.aliyun.com；
# 本地环境如 rancher.io/local-path / kubernetes.io/no-provisioner
provisioner: rancher.io/local-path 

# 【可选】回收策略：Delete（删 PVC 就删 PV 和数据，动态供应默认）、Retain（保留数据）
reclaimPolicy: Delete

# 【极其重要】卷绑定模式
# Immediate：PVC 一创建就立刻创建 PV。
# WaitForFirstConsumer：等到有 Pod 使用该 PVC 时，再创建 PV（对于本地盘、拓扑受限的云盘必填！）
volumeBindingMode: WaitForFirstConsumer

# 【可选】是否允许 PVC 扩容（默认 false）
allowVolumeExpansion: true

# 【可选】传给底层插件的参数（不同 Provisioner 参数完全不同）
parameters:
  # 例如 AWS EBS 的参数：
  # type: gp3
  # encrypted: "true"
  
  # 例如 local-path 的参数：
  # type: HostPath
```

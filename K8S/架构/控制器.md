> 控制器：deployment，StatefulSet，DaemonSet，Job，CronJob，PHA，PHB



```Shell
# ============================================================
# Deployment 无状态工作负载
# 作用：管理 Pod 的副本数、滚动更新、自愈
# ============================================================
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-deployment
  namespace: demo-namespace
  labels:
    app: web
spec:
  replicas: 3              # 期望的 Pod 副本数
  selector:                # 标签选择器，必须匹配 template.metadata.labels
    matchLabels:
      app: web
  # 更新策略
  strategy:                
    type: RollingUpdate    # 滚动更新（默认），另一个是 Recreate（先全部删再建）
    rollingUpdate:
      maxSurge: 1          # 更新时最多超出期望副本数的 Pod 数量（可以是数字或百分比）
      maxUnavailable: 0    # 更新时最多不可用的 Pod 数量（0 表示保证服务不中断）
  # Pod 模板
  template:                
    metadata:
      labels:
        app: web           # 必须与 selector.matchLabels 匹配
    spec:
      # ---- 调度相关 ----
      nodeSelector:        # 节点选择器，将 Pod 调度到带特定标签的节点
        disktype: ssd
      tolerations:         # 容忍度，允许 Pod 调度到带污点（Taint）的节点
        - key: "dedicated"
          operator: "Equal"
          value: "web"
          effect: "NoSchedule"
      affinity:            # 亲和性（此处省略详细配置，生产中常用于 Pod 反亲和）
        podAntiAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
            - weight: 100
              podAffinityTerm:
                labelSelector:
                  matchLabels:
                    app: web
                topologyKey: kubernetes.io/hostname

      # ---- 容器配置 ----
      containers:
        - name: web
          image: nginx:1.27
          imagePullPolicy: IfNotPresent  # Always, IfNotPresent, Never
          
          # 端口声明
          ports:
            - name: http
              containerPort: 80
              protocol: TCP
          
          # 环境变量：从 ConfigMap 和 Secret 注入
          envFrom:
            - configMapRef:
                name: app-config
            - secretRef:
                name: app-secret
          
          # 单个环境变量（优先级更高）
          env:
            - name: MY_POD_NAME
              valueFrom:
                fieldRef:
                  fieldPath: metadata.name
                  optional: true    # 缺失时不报错，注入空值
          
          # 资源配额
          resources:
            requests:
              cpu: 100m
              memory: 128Mi
            limits:
              cpu: 500m
              memory: 256Mi
          
          # 挂载卷
          volumeMounts:
            - name: config-vol
              mountPath: /etc/nginx/conf.d
              readOnly: true
            - name: data-vol
              mountPath: /usr/share/nginx/html/data
          
          # ---- 探针配置 ----
          startupProbe:       # 启动探针：判断应用是否启动成功
            httpGet:
              path: /
              port: 80
            failureThreshold: 30
            periodSeconds: 2
          livenessProbe:      # 存活探针：判断应用是否假死，失败则重启容器
            httpGet:
              path: /healthz
              port: 80
            initialDelaySeconds: 5  # 容器启动后等多久才开始探测
            periodSeconds: 10       # 每隔多久探一次
            failureThreshold: 3     # 连续失败几次算失败   
            # failureThreshold × periodSeconds ≥ 应用最坏启动时间
          readinessProbe:     # 就绪探针：判断应用是否准备好接收流量
            httpGet:
              path: /
              port: 80
            initialDelaySeconds: 3
            periodSeconds: 5
            failureThreshold: 2
      
      # ---- 卷定义 ----
      volumes:
        - name: config-vol
          configMap:
            name: app-config
            items:
              - key: nginx.conf
                path: default.conf
        - name: data-vol
          persistentVolumeClaim:
            claimName: app-pvc
---

# ============================================================
# HorizontalPodAutoscaler (HPA) 水平自动扩缩容
# 作用：根据 CPU/内存等指标自动调整 Deployment 的副本数
# ============================================================
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: web-hpa
  namespace: demo-namespace
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: web-deployment
  minReplicas: 2           # 最小副本数
  maxReplicas: 10          # 最大副本数
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 80  # CPU 使用率超过 80% 时触发扩容
  behavior:                # 扩缩容行为控制（可选）
    scaleDown:
      stabilizationWindowSeconds: 300  # 缩容冷却时间，避免抖动
```





```Shell
# 控制器
对象	       职责	                       典型场景
Deployment	管无状态应用，更新和回滚（无序） Web 服务、API
ReplicaSet  保证副本数（几乎不直接用）
StatefulSet	管有状态应用的标识与存储（有序） 数据库、消息队列
DaemonSet  	每个节点跑一份	               日志/监控采集器、CNI
Job	        跑一次就结束	                数据迁移、批处理
CronJob	    按 cron 周期创建 Job	         定时巡检、报表
HPA / PDB	  副本弹性 / 可用性保护	        自动扩缩、节点维护


# -----------------------------------------------------------------------------
# 六、Deployment 发布管理（rollout）
# -----------------------------------------------------------------------------
kubectl rollout status deployment/<deploy>   # 查看发布进度
kubectl rollout history deployment/<deploy>  # 查看发布历史
kubectl rollout history deployment/<deploy> --revision=3  # 查看指定版本的详情
kubectl rollout undo deployment/<deploy>     # 回滚到上一版本
kubectl rollout undo deployment/<deploy> --to-revision=2  # 回滚到指定版本
kubectl rollout restart deployment/<deploy>  # 滚动重启（不改变镜像，常用于让 Pod 重新拉取配置）
kubectl rollout pause deployment/<deploy>    # 暂停发布
kubectl rollout resume deployment/<deploy>   # 恢复发布

```



### 核心概念

1. **ReplicaSet**：保证副本数；一般**不要直接用**，用 Deployment 管它。
2. **Deployment**：管理 RS 的版本。
   - `strategy.rollingUpdate`：`maxSurge`（最多超出多少）/`maxUnavailable`（最多不可用多少）
   - `revisionHistoryLimit`、`progressDeadlineSeconds`
   - 关键命令：`rollout status / history / undo / restart / pause / resume`
   - 变更 `spec.template` 才触发发布；只改副本数不会。
3. **StatefulSet**：有状态应用
   - 稳定的网络标识：`pod-0.web.default.svc.cluster.local`（需 headless Service）
   - 稳定的存储：`volumeClaimTemplates` 每副本一块盘，删 Pod 不删盘
   - 有序部署/缩容（默认 `OrderedReady`），可 `podManagementPolicy: Parallel`
4. **DaemonSet**：每个（符合条件的）节点跑一份，用于日志/监控/网络插件。
5. **Job / CronJob**：批处理
   - Job：`completions`/`parallelism`/`backoffLimit`/`activeDeadlineSeconds`/`ttlSecondsAfterFinished`
   - CronJob：`schedule`（5 段式或 `@daily`）/`concurrencyPolicy`（Allow/Forbid/Replace）/`suspend`/`startingDeadlineSeconds`
6. **HPA**（`autoscaling/v2`）：基于 CPU/内存/自定义指标扩缩容；需要 metrics-server。
7. **PDB**（`policy/v1`）：自愿中断时保证最低可用副本（配合节点维护/drain）。







### Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 3
  revisionHistoryLimit: 10
  minReadySeconds: 10
  progressDeadlineSeconds: 600
  strategy:
    type: RollingUpdate                # 或 Recreate
    rollingUpdate:
      maxSurge: 25%                    # 最多超出期望副本数
      maxUnavailable: 0                # 生产建议 0，保证容量不掉
  selector:
    matchLabels: { app: web }          # 一经创建不可变
  template:
    metadata:
      labels: { app: web }
    spec:
      affinity:
        podAntiAffinity:               # 副本打散到不同节点
          preferredDuringSchedulingIgnoredDuringExecution:
            - weight: 100
              podAffinityTerm:
                topologyKey: kubernetes.io/hostname
                labelSelector:
                  matchLabels: { app: web }
      containers:
        - name: app
          image: registry.example.com/web:1.2.3
```

```bash
kubectl rollout status deployment/web          # 等待滚动完成
kubectl rollout history deployment/web         # 查看历史版本
kubectl rollout undo deployment/web            # 回滚到上一版
kubectl rollout undo deployment/web --to-revision=2
kubectl rollout restart deployment/web         # 滚动重启（不改镜像，重新拉 Pod）
kubectl rollout pause/resume deployment/web    # 暂停/恢复
kubectl set image deployment/web app=web:1.2.4 # 触发一次更新
kubectl scale deployment/web --replicas=5
```

### StatefulSet

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mysql
spec:
  serviceName: mysql-headless        # 必须指向 Headless Service
  replicas: 3
  podManagementPolicy: OrderedReady  # 默认按序；Parallel 可并行
  selector:
    matchLabels: { app: mysql }
  template:
    metadata:
      labels: { app: mysql }
    spec:
      containers:
        - name: mysql
          image: mysql:8.0
          volumeMounts:
            - name: data
              mountPath: /var/lib/mysql
  volumeClaimTemplates:              # 每个 Pod 自动生成独立 PVC
    - metadata:
        name: data
      spec:
        accessModes: ["ReadWriteOnce"]
        storageClassName: fast-ssd
        resources:
          requests:
            storage: 20Gi
---
apiVersion: v1
kind: Service
metadata:
  name: mysql-headless
spec:
  clusterIP: None                    # Headless Service
  selector: { app: mysql }
  ports:
    - port: 3306
```

- Pod 名称固定为 `<sts>-0/1/2`，删除后会以同名重建并挂回原 PVC。
- DNS：`mysql-0.mysql-headless.default.svc.cluster.local`。
- 扩缩容按序号从大到小缩，缩容**不会删除 PVC**（要手动清）。

### DaemonSet / Job / CronJob

```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata: { name: node-exporter }
spec:
  selector:
    matchLabels: { app: node-exporter }
  template:
    metadata:
      labels: { app: node-exporter }
    spec:
      tolerations:                    # 关键：容忍控制平面污点，否则不落在 master
        - operator: Exists
      hostNetwork: true
      hostPID: true
      containers:
        - name: node-exporter
          image: prom/node-exporter:v1.8.0
          ports: [{ containerPort: 9100 }]
---
apiVersion: batch/v1
kind: Job
metadata: { name: db-migrate }
spec:
  completions: 1
  parallelism: 1
  backoffLimit: 6                  # 失败重试次数
  activeDeadlineSeconds: 600       # 整个 Job 超时
  ttlSecondsAfterFinished: 3600    # 完成后 1 小时自动清理
  template:
    spec:
      restartPolicy: OnFailure     # Job 只能是 OnFailure / Never
      containers:
        - name: migrate
          image: registry.example.com/migrate:1.0
---
apiVersion: batch/v1
kind: CronJob
metadata: { name: backup }
spec:
  schedule: "0 3 * * *"                    # 分 时 日 月 周
  timeZone: "Asia/Shanghai"                # 1.27+ 支持
  concurrencyPolicy: Forbid                # Allow / Forbid / Replace
  startingDeadlineSeconds: 300
  successfulJobsHistoryLimit: 3
  failedJobsHistoryLimit: 1
  suspend: false
  jobTemplate:
    spec:
      template:
        spec:
          restartPolicy: OnFailure
          containers:
            - name: backup
              image: registry.example.com/backup:1.0
```

### HPA / PDB

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata: { name: web }
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: web
  minReplicas: 2
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target: { type: Utilization, averageUtilization: 70 }
  behavior:
    scaleDown:
      stabilizationWindowSeconds: 300     # 避免抖动
---
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata: { name: web-pdb }
spec:
  minAvailable: 2                       # 或 maxUnavailable: 1
  selector:
    matchLabels: { app: web }
```

HPA 依赖 metrics-server；`kubectl get hpa` 显示 `<unknown>` 就是 metrics 拿不到。

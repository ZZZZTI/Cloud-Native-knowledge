项目经历

项目一：Kubernetes 多集群容器化平台建设与发布体系改造

技术栈：Kubernetes · Docker · Helm · ArgoCD · GitLab CI · Karmada · Calico · Terraform
  • 背景：业务原采用虚拟机 + 手工部署，单服务发布需 30 分钟且易出错，资源利用率仅 15%，缺乏多环境隔离与灰度能力。
  • 容器化改造：制定统一镜像规范，优化 Dockerfile（多阶段构建 + 精简基础镜像），业务镜像体积由 1.2GB 降至 210MB，拉取耗时下降 70%。
  • 集群建设：使用 kubeadm + Ansible 搭建生产/预发/测试三套高可用集群，配置 Calico 网络、CSI 存储与节点亲和/污点策略；用 Terraform 管理云上 VPC、SLB、节点池等资源，实现环境可复制。
  • 发布体系：用 Helm Chart 统一 80+ 服务的部署模板，接入 GitLab CI 完成构建-扫描-推送，通过 ArgoCD 实现 GitOps 自动同步与一键回滚；结合 HPA + Cluster Autoscaler 实现弹性伸缩。
  • 多集群治理：引入 Karmada 管理多地集群，实现统一调度与故障转移，核心服务跨可用区部署。
  • 成果：单服务发布耗时由 30min 降至 5min，发布失败率由 12% 降至 1.5%；集群 CPU 平均利用率由 15% 提升至 45%，年度云成本节省约 30%；支撑大促期间 3 倍流量峰值零故障。

项目二：全链路可观测性与 SLO 告警治理体系

技术栈：Prometheus · VictoriaMetrics · Grafana · Alertmanager · Loki · OpenTelemetry · Jaeger · Python
  • 背景：故障主要靠用户投诉发现，平均发现时长 25min；告警日均 800+ 条且 70% 为噪声，值班人员严重告警疲劳。
  • 指标监控：基于 Prometheus + VictoriaMetrics 构建指标采集与长期存储，覆盖主机、容器、中间件与业务自定义指标；为业务接入 RED/ 黄金指标看板，Grafana 统一 30+ 仪表盘。
  • 日志与链路：部署 Loki + Promtail 做日志采集（替代原 ELK 高成本方案，存储成本降 60%），接入 OpenTelemetry + Jaeger 实现跨服务链路追踪，日志与 TraceID 双向关联。
  • SLO 体系：与业务方共同定义核心接口 SLI（可用性、P99 延迟、错误率）与 SLO 目标，引入错误预算燃尽率（Burn Rate）多窗口告警，替代原粗暴阈值告警。
  • 告警治理：用 Python 编写告警收敛与去重服务，按服务维度聚合、抑制上下游级联告警，并接入企业微信/电话分级通知。
  • 应急体系：梳理 on-call 轮值与升级机制，编写 30+ 篇 runbook，沉淀故障复盘（Postmortem）模板；搭建混沌工程演练（Chaos Mesh）定期注入 Pod 故障、网络延迟验证系统韧性。
  • 成果：告警量由日均 800+ 降至 220 条，噪声告警下降 72%；MTTD 由 25min 降至 3min，MTTR 由 32min 降至 8min；核心服务可用性从 99.9% 提升至 99.95%，半年内未发生 P0 级故障。

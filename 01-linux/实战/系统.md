# > 启动与安全
> 覆盖：cron、时间同步、fstab、root 密码、/etc 权限、SELinux、系统启动。
------

## 场景 1：定时任务不执行

**现象**：crontab 中配置了 `*/5 * * * * /opt/scripts/task.sh`，但脚本从未执行。

**可能原因**：

- cron 服务未启动
- 脚本没有执行权限
- cron 环境变量极简，PATH 不对
- Windows 换行符
- `%` 未转义
- 任务写错用户
- SELinux 拦截

**排查命令**：

```bash
systemctl status crond  # 查看 cron 服务状态（RHEL）
systemctl status cron  # 查看 cron 服务状态（Debian）
crontab -l  # 查看当前定时任务
ls -l /opt/scripts/task.sh  # 查看脚本权限
tail -f /var/log/cron  # 实时跟踪日志
grep CRON /var/log/syslog  # 查看 cron 日志
bash -x /opt/scripts/task.sh  # 调试执行脚本
file /opt/scripts/task.sh  # 查看文件类型
```

**处理命令**：

```bash
chmod +x /opt/scripts/task.sh  # 添加执行权限
dos2unix /opt/scripts/task.sh  # 转换 Windows 换行符

# crontab 中用绝对路径，必要时加载环境
*/5 * * * * /bin/bash -lc '/opt/scripts/task.sh >> /var/log/task.log 2>&1'  # cron：每 5 分钟执行
```

**注意**：cron 不会加载完整的用户环境；脚本里尽量写绝对路径，重要任务建议改用 systemd timer。

## 场景 2：系统时间不同步

**现象**：日志时间比实际慢几分钟，HTTPS 证书校验偶发失败，分布式任务时间不一致。

**可能原因**：

- chrony/ntpd 未运行
- 时间源不可达
- 防火墙拦截 UDP 123
- 虚拟机宿主时间同步异常
- 时区配置错误

**排查命令**：

```bash
date  # 查看系统时间
timedatectl  # 查看/设置时间
systemctl status chronyd  # 查看服务状态
chronyc sources -v  # 查看时间源
chronyc tracking  # 查看时间同步状态
ss -lunp | grep ':123'  # 查看 UDP 监听端口
```

**处理命令**：

```bash
timedatectl set-timezone Asia/Shanghai  # 设置时区
timedatectl set-ntp true  # 开启 NTP 同步
systemctl enable --now chronyd  # 开机自启并立即启动
chronyc makestep  # 强制步进时间
hwclock --systohc  # 同步硬件时钟
```

**注意**：偏差很大时先确认业务能否接受时间跳变；容器通常继承宿主机时间，不要在容器里单独跑 NTP。

## 场景 3：fstab 写错进入 emergency mode

**现象**：修改 `/etc/fstab` 后重启，系统进入 emergency mode，提示 `Failed to mount /data`。

**可能原因**：

- UUID 写错或磁盘不存在
- 挂载点目录不存在
- 文件系统类型错误
- 磁盘损坏、需要 fsck

**排查命令**：

```bash
# emergency mode 输入 root 密码后
mount -o remount,rw /  # 将根分区重新挂载为读写
cat /etc/fstab  # 查看 fstab 配置
blkid  # 查看块设备 UUID
lsblk -f  # 查看块设备
journalctl -xb | grep -iE 'mount|failed|fstab'  # 查看本次启动日志
systemctl status data.mount  # 查看挂载单元状态
```

**处理命令**：

```bash
cp /etc/fstab /etc/fstab.bak  # 备份 fstab
vi /etc/fstab                 # 注释或修正错误行
mkdir -p /data  # 创建挂载点
systemctl daemon-reload  # 重载 systemd 配置
mount -a  # 挂载 fstab 中所有条目
findmnt /data  # 查看挂载信息
reboot  # 重启系统
```

**注意**：修改 fstab 后先 `mount -a` 验证再重启；非关键数据盘加 `nofail`。

## 场景 4：root 密码忘记

**现象**：无法登录 root，普通用户也没有 sudo 权限，但能接触控制台/带外管理。

**可能原因**：

- 密码遗忘
- 认证配置被改坏
- 账户被锁定

**排查/处理命令**：

```bash
# GRUB 菜单按 e，在 linux 行末尾加 rd.break
# 启动后：
mount -o remount,rw /sysroot  # 救援模式将根分区改为读写
chroot /sysroot  # 切换根目录
passwd root  # 修改 root 密码
touch /.autorelabel  # 触发 SELinux 重打标签
exit  # 退出 chroot
reboot  # 重启系统
```

或者：

```bash
# GRUB 内核行加 init=/bin/bash
mount -o remount,rw /  # 将根分区重新挂载为读写
passwd root  # 修改 root 密码
exec /sbin/init  # 启动 systemd
```

**注意**：需要物理控制台、IPMI、云厂商 VNC/串口；改完 SELinux 要 `touch /.autorelabel`，否则可能登录异常。

## 场景 5：误把 /etc 权限改成 777

**现象**：执行了 `chmod -R 777 /etc`，随后 `sudo` 报错、SSH 公钥登录失败、部分服务启动异常。

**可能原因**：

- 误操作递归改权限
- 脚本权限设置写错路径

**排查命令**：

```bash
ls -ld /etc /etc/shadow /etc/sudoers /etc/ssh  # 查看关键文件权限
rpm -Va | head -100          # RHEL/CentOS
dpkg --verify                # Debian/Ubuntu
```

**处理命令**：

```bash
# RHEL/CentOS：按包恢复
rpm --setperms $(rpm -qa)  # 恢复 RPM 包默认权限
rpm --setugids $(rpm -qa)  # 恢复 RPM 包默认属主

# Debian/Ubuntu：重装受影响包
apt install --reinstall <package>  # 重装软件包

# 关键权限
chmod 644 /etc/passwd /etc/group  # 恢复关键文件权限
chmod 440 /etc/sudoers  # 恢复 sudoers 权限
chmod 600 /etc/ssh/sshd_config  # 恢复 sshd 配置权限
restorecon -Rv /etc  # 恢复 SELinux 上下文
```

**注意**：先在控制台确认能登录，不要直接重启；`/etc/shadow` 的默认权限因发行版而异，以包管理器恢复结果为准。

## 场景 6：SELinux 导致服务起不来

**现象**：服务配置和端口都正常，但一启动就失败，`/var/log/audit/audit.log` 出现 `avc: denied`。

**可能原因**：

- 文件上下文不对
- 使用了非标准端口
- 需要访问网络/数据库但布尔值为 off
- 自定义目录没有打标签

**排查命令**：

```bash
getenforce  # 查看 SELinux 模式
sestatus  # 查看 SELinux 状态
ls -Z /var/www/html  # 查看 SELinux 上下文
ps -eZ | grep <service>  # 查看进程 SELinux 上下文
ausearch -m avc -ts recent  # 查询审计日志
sealert -a /var/log/audit/audit.log  # 分析 SELinux 告警
```

**处理命令**：

```bash
restorecon -Rv /var/www/html  # 恢复 SELinux 上下文

semanage fcontext -a -t httpd_sys_content_t '/web(/.*)?'  # 设置 SELinux 文件上下文
restorecon -Rv /web  # 恢复 SELinux 上下文

semanage port -a -t http_port_t -p tcp 8080  # 设置 SELinux 端口标签
setsebool -P httpd_can_network_connect on  # 设置 SELinux 布尔值
```

**注意**：不要把 `setenforce 0` 当长期方案；先用 AVC 日志定位，再决定改上下文、端口标签还是布尔值。

## 场景 7：系统无法启动

**现象**：开机卡在 GRUB、`grub>`、`dracut-initqueue`、kernel panic，或直接进入 emergency mode。

**可能原因**：

- GRUB 配置损坏、内核/initramfs 丢失
- 根分区 UUID 变化、磁盘识别不到
- 文件系统损坏、fstab 错误
- 内核升级后驱动缺失
- 硬件/RAID 故障

**排查命令**：

```bash
# GRUB 命令行下手动引导
ls  # 列出磁盘和分区
set root=(hd0,1)  # 指定 /boot 所在分区
linux /vmlinuz-<版本> root=/dev/sda1 ro  # 加载内核
initrd /initramfs-<版本>.img  # 加载 initramfs
boot  # 启动

# 进入救援模式后
mount -o remount,rw /sysroot  # 根分区改读写
chroot /sysroot  # 切换根目录
cat /etc/fstab  # 检查 fstab
blkid  # 查看 UUID
dracut -f  # 重建 initramfs（RHEL）
grub2-mkconfig -o /boot/grub2/grub.cfg  # 重建 GRUB
```

**处理命令**：

```bash
fsck -f /dev/sda1  # 检查根分区文件系统
dracut -f --regenerate-all  # 重新生成 initramfs
grub2-mkconfig -o /boot/grub2/grub.cfg  # 重新生成 GRUB 配置
# Debian/Ubuntu 对应：
# update-initramfs -u
# update-grub
```

**注意**：需要控制台/IPMI/云 VNC；不要在不确认分区的情况下重装 GRUB 或格式化磁盘。

------

> 备注：命令以 Linux（GNU 工具链）为准；生产环境执行删除、重启、`kill -9`、`fsck`、改权限前，先确认影响范围。

### 异常处理

```python
import json, logging

log = logging.getLogger(__name__)

try:
    data = json.loads(text)
except json.JSONDecodeError as e:        # 捕获最具体的异常
    log.error("解析失败: %s", e)
    data = {}
except (KeyError, TypeError) as e:
    data = {}
else:
    log.info("解析成功")                  # 没异常才执行
finally:
    conn.close()                         # 无论成败都执行
```

**三条纪律**：

1. **禁止裸 `except:`** —— 它连 `KeyboardInterrupt`、`SystemExit` 一起吞掉，脚本会变得 Ctrl+C 都停不下来。
2. **禁止 `except Exception: pass`** —— 出错静默，半年后没人知道为什么数据少了。
3. **只捕获你知道怎么处理的异常**，其余让它带着 traceback 抛出来。

```python
# 需要看完整调用栈时用 log.exception，别 print(e)
try:
    risky()
except Exception:
    log.exception("执行失败")        # 自动附带 traceback
```

```python
# 自定义异常，让上层能区分「可重试」和「不可重试」
class RetryableError(Exception): ...
class FatalError(Exception): ...

try:
    do_work()
except RetryableError:
    retry_later()
```

### 可变默认参数（最经典的坑）

```python
def bad(items=[]):          # ❌ 所有调用共享同一个 list
    items.append(1)
    return items

bad()   # [1]
bad()   # [1, 1]   ← 第二次居然带着上次的数据

def good(items=None):       # ✅
    items = items if items is not None else []
    items.append(1)
    return items
```

同样的坑还有 `def f(cache={})`、`def f(seen=set())`。**默认值只在函数定义时求值一次**。

### dict 取值

```python
cfg = {"host": "10.0.0.1"}

cfg["port"]                       # ❌ 缺 key 直接 KeyError，脚本崩
cfg.get("port", 8080)             # ✅ 给默认值

# 深层嵌套用链式 get，避免中间层缺失
port = resp.get("data", {}).get("spec", {}).get("port", 0)

# setdefault：有就返回，没有就写入
cfg.setdefault("retries", 3)
```

### 编码

```python
open("hosts.txt", encoding="utf-8")                  # 读文件必须显式指定
open("app.log", encoding="utf-8", errors="replace")  # 脏数据不让整个脚本崩
subprocess.run(cmd, text=True, encoding="utf-8")     # 调外部命令同理
```

不指定编码时用的是系统默认（中文环境可能是 GBK），换台机器就乱码。

### 模块入口

```python
def main() -> int:
    ...
    return 0

if __name__ == "__main__":        # 直接运行才执行；被 import 时不跑
    raise SystemExit(main())
```

好处：同一个文件既能当脚本跑，也能被别的脚本 `import` 复用其中的函数。

### 退出码

| 码 | 含义 | 使用场景 |
| :-- | :-- | :-- |
| `0` | 正常 | 检查通过 |
| `1` | 检查不通过 | 业务层面的异常（有 Pod 挂了） |
| `2` | 执行失败 | 脚本自身错误（连不上集群、参数非法） |

监控和 CI 都靠退出码判断结果。**别在成功失败时都 `exit(0)`**，那等于告诉调用方「一切正常」。

### 其他易错点

```python
# 1. 浮点比较
0.1 + 0.2 == 0.3          # False
abs(0.1 + 0.2 - 0.3) < 1e-9   # ✅ 用误差范围

# 2. 整数除法
7 / 2      # 3.5
7 // 2     # 3

# 3. 遍历时修改列表
for x in items:
    items.remove(x)        # ❌ 会跳过元素
for x in list(items):      # ✅ 遍历副本
    items.remove(x)

# 4. is 与 ==
a is None        # ✅ 判断 None 用 is
a == None        # ❌ 不要这样写

# 5. 布尔判断
if len(items) > 0:   # 啰嗦
if items:            # ✅ 空容器为假

# 6. 字符串拼接循环
s = ""
for x in items:
    s += x           # ❌ O(n²)
s = "".join(items)   # ✅
```

### 核心概念

1. **只捕具体异常**，禁止裸 `except:` 和 `except Exception: pass`。
2. **默认参数不要用可变对象**（`[]`、`{}`、`set()`）。
3. **dict 用 `.get(key, default)`**，嵌套用链式 `get`。
4. **打开文件显式写 `encoding="utf-8"`**，脏数据加 `errors="replace"`。
5. **`if __name__ == "__main__"`** 让脚本可执行也可被 import。
6. **退出码分三种**：0 正常 / 1 检查不通过 / 2 执行失败。
7. **判断 `None` 用 `is`**，判断空容器直接用真假值。

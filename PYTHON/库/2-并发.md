> 第 7 类：并发、重试与调度。把「逐个等」变成「一起等」，把「手写循环重试」变成声明式。

------

## 1. concurrent.futures / threading / queue ★★★ —— 线程池、进程池、队列

### 先选对模型

```
类型        特征              例子                    用
IO 密集     大部分时间在等    HTTP、SSH、读写文件      线程池 / asyncio
CPU 密集    大部分时间在算    正则、压缩、哈希、加解密   进程池
```

GIL 决定：**多线程不能加速纯计算**，但等待 IO 时会释放 GIL，所以能加速网络请求。

### ThreadPoolExecutor

```
ThreadPoolExecutor(max_workers=20, thread_name_prefix="probe")
pool.submit(fn, *args, **kw)    提交一个任务，返回 Future
pool.map(fn, iterable)          按输入顺序返回结果（生成器）
pool.shutdown(wait=True, cancel_futures=False)
with ThreadPoolExecutor(...) as pool:    退出自动 shutdown

Future:
f.result(timeout=None)          取返回值（任务异常会在这里重抛）
f.exception()                   取异常对象（不抛）
f.done() / f.cancelled()        状态
f.cancel()                      只有还没开始跑才能取消
f.add_done_callback(fn)         完成后回调

as_completed(fs, timeout=None)  谁先完成先给谁（不是提交顺序）
wait(fs, timeout=, return_when=)  等一批
```

```Python
from concurrent.futures import ThreadPoolExecutor, as_completed

def probe(host: str, port: int = 22, timeout: float = 2.0) -> tuple[str, bool]:
    """探测单个目标（内部要有自己的超时）。"""
    import socket
    try:
        with socket.create_connection((host, port), timeout=timeout):
            return host, True
    except OSError:
        return host, False

hosts = [f"10.0.0.{i}" for i in range(1, 101)]

# ==== 提交 + 逐个收结果 ====
with ThreadPoolExecutor(max_workers=20) as pool:      # 20 是并发上限
    futures = {pool.submit(probe, h): h for h in hosts}

    for fut in as_completed(futures):
        host = futures[fut]
        try:
            h, ok = fut.result()                       # 任务异常在这里抛
            if not ok:
                print(f"[FAIL] {h}")
        except Exception as e:
            print(f"[ERR ] {host}: {e}")

# ==== 不需要顺序、只要结果列表：用 map ====
with ThreadPoolExecutor(max_workers=20) as pool:
    results = list(pool.map(probe, hosts))             # 按输入顺序返回

ok = sum(1 for _, up in results if up)
print(f"{ok}/{len(results)} 可达")
```

### 并发数怎么定

```
IO 密集（HTTP/SSH）     10–50 起步，看对端承受能力
数据库操作              别超过连接池上限
本地磁盘扫描            2–8，再高没收益
fd 上限                 一个连接一个 fd，ulimit -n 决定天花板
```

### ProcessPoolExecutor

```
ProcessPoolExecutor(max_workers=None)   默认用 CPU 核数
pool.submit / map / shutdown            接口同上
```

```Python
from concurrent.futures import ProcessPoolExecutor
from pathlib import Path
import hashlib

def sha256(path: str) -> tuple[str, str]:
    """纯 CPU 活——必须定义在模块顶层，才能被 pickle 送进子进程。"""
    h = hashlib.sha256()
    with open(path, "rb") as f:
        for chunk in iter(lambda: f.read(1 << 20), b""):
            h.update(chunk)
    return path, h.hexdigest()

if __name__ == "__main__":        # Windows / spawn 模式下必须加这层保护
    files = [str(p) for p in Path("/data").rglob("*.tar")]
    with ProcessPoolExecutor() as pool:
        for path, digest in pool.map(sha256, files):
            print(digest[:12], path)
```

⚠️ 进程池限制：

- 参数和返回值**必须可 pickle**（不能传连接、文件句柄、lambda、闭包）
- 子进程是独立内存，改不了父进程的变量
- 启动开销比线程大，任务太碎反而更慢

### threading / queue

```
threading.Thread(target=, args=, daemon=True)   .start() / .join()
threading.Lock() / RLock()                      with lock: 加锁
threading.Event()                               set() / wait() / clear()
threading.Semaphore(n)                          限流
threading.local()                               线程本地存储

queue.Queue(maxsize=0)                           FIFO
queue.PriorityQueue()                            优先级（元素要可比较）
queue.LifoQueue()                                栈
q.put(item, block=True, timeout=None)
q.get(block=True, timeout=None)
q.task_done() / q.join()                         配合使用：join 等所有 task_done
q.empty() / q.full() / qsize()
queue.Empty / queue.Full                         异常
```

```Python
import queue
import threading

q: queue.Queue = queue.Queue(maxsize=100)
lock = threading.Lock()
counter = 0

def worker(name: str) -> None:
    global counter
    while True:
        try:
            item = q.get(timeout=1)         # 1 秒没数据就退出
        except queue.Empty:
            return
        try:
            process(item)
            with lock:                      # 改共享状态必须加锁
                counter += 1
        finally:
            q.task_done()                   # 无论成败都要报告完成

# 生产者
for x in range(1000):
    q.put(x)

# 消费者
threads = [threading.Thread(target=worker, args=(f"w{i}",), daemon=True)
           for i in range(8)]
for t in threads:
    t.start()

q.join()                 # 等所有任务 task_done
print("处理总数:", counter)
```

⚠️ 坑：

- `Future.result()` 会把任务里的异常**重新抛出**，不 try 住一个失败就中断汇总
- 线程池**杀不掉正在运行的线程**，超时必须下沉到具体 IO 调用（socket timeout / requests timeout）
- 别共享可变状态；让任务返回结果、主线程汇总，比加锁干净
- `q.join()` 前每个任务都必须 `task_done()`，漏一个就永远阻塞

## 2. tenacity ★★ —— 声明式重试

把「while + sleep + 2**n」换成一个装饰器。

### 装饰器参数

```
@retry
retry=retry_if_exception_type((TimeoutError, ConnectionError))   什么情况重试
stop=stop_after_attempt(5)          最多 5 次
     stop_after_delay(60)           最多 60 秒
     stop_any(...) / stop_never     组合
wait=wait_fixed(2)                  固定 2 秒
     wait_exponential(multiplier=1, max=30)   指数退避
     wait_random(min=1, max=3)      随机抖动（防雪崩）
     wait_exponential_jitter(initial=1, max=30)
reraise=True                        重试耗尽后抛原始异常
before_sleep=before_sleep_log(logger, logging.WARNING)
retry_error_callback=回调            重试耗尽时的处理
```

```Python
import logging
import httpx
from tenacity import (
    retry, stop_after_attempt, wait_exponential_jitter,
    retry_if_exception_type, before_sleep_log, RetryError,
)

log = logging.getLogger(__name__)

@retry(
    retry=retry_if_exception_type((httpx.TimeoutException, httpx.HTTPStatusError)),
    stop=stop_after_attempt(5),
    wait=wait_exponential_jitter(initial=1, max=30),   # 1,2,4,8... 加抖动
    before_sleep=before_sleep_log(log, logging.WARNING),
    reraise=True,                                       # 最终失败抛原异常
)
def call_api(url: str) -> dict:
    r = httpx.get(url, timeout=10)
    r.raise_for_status()                                # 5xx 会触发重试
    return r.json()

try:
    data = call_api("https://api.example.com/v1/pods")
except httpx.HTTPStatusError as e:
    log.error("重试耗尽: %s", e)
```

```Python
# ==== 按返回值重试（接口返回 200 但 body 里是错误）====
from tenacity import retry, retry_if_result, stop_after_attempt

def is_bad(result) -> bool:
    return result.get("code") != 0

@retry(retry=retry_if_result(is_bad), stop=stop_after_attempt(3))
def deploy() -> dict:
    return {"code": 1, "msg": "busy"}

# ==== 手动重试（不用装饰器）====
from tenacity import Retrying, stop_after_attempt, wait_fixed

for attempt in Retrying(stop=stop_after_attempt(3), wait=wait_fixed(2), reraise=True):
    with attempt:
        do_something()
```

⚠️ 坑：

- 默认只对 `Exception` 重试且**无限重试**——一定要显式给 `stop=`
- 不加 `reraise=True`，最终抛的是 `RetryError`，原始异常被包在里面不好排查
- 重试前要确认操作**幂等**（POST 重试可能创建两份资源）
- 一定要加抖动（jitter），否则几百个客户端会同时重试把服务打垮

## 3. APScheduler ★★ —— 进程内定时调度

进程内定时任务。比 crontab 好在：能代码管理、能动态增删、能拿执行结果。

### 调度器

```
BlockingScheduler()        阻塞当前线程（纯定时脚本用）
BackgroundScheduler()      后台线程，主程序继续跑（服务里用）
AsyncIOScheduler()         asyncio 环境
scheduler.start() / shutdown(wait=True)
scheduler.add_job(func, trigger, **kw)
scheduler.remove_job(id)
scheduler.get_jobs()
scheduler.pause() / resume()
```

### trigger 三种

```
'interval'   固定间隔
    seconds=30 / minutes=5 / hours=1 / days=1
'cron'       类 crontab
    second / minute / hour / day / month / day_of_week
    day_of_week='mon-fri'
    hour='9-18', minute='*/5'
'date'       只跑一次
    run_date='2026-10-27 10:00:00'
```

### add_job 常用参数

```
func=                 要执行的函数
trigger=              'interval' / 'cron' / 'date'
id=                   任务标识（后面 remove 用）
replace_existing=True 同 id 覆盖旧任务
max_instances=1       同一任务最多几个实例同时跑（防重叠）
coalesce=True         错过多次只补跑一次
misfire_grace_time=60 错过多久内还允许补跑
args= / kwargs=       传参
```

```Python
import logging
import time
from apscheduler.schedulers.blocking import BlockingScheduler
from apscheduler.triggers.cron import CronTrigger

log = logging.getLogger(__name__)

def inspect() -> None:
    log.info("开始巡检")

def cleanup() -> None:
    log.info("开始清理")

scheduler = BlockingScheduler(timezone="Asia/Shanghai")

# ==== 每 5 分钟一次 ====
scheduler.add_job(
    inspect,
    "interval",
    minutes=5,
    id="inspect",
    max_instances=1,          # 上一次没跑完就跳过，避免堆积
    coalesce=True,
)

# ==== 工作日 10:00（等价 cron: 0 10 * * 1-5）====
scheduler.add_job(
    cleanup,
    CronTrigger(day_of_week="mon-fri", hour=10, minute=0),
    id="cleanup",
    misfire_grace_time=300,   # 机器休眠错过 5 分钟内还补跑
)

# ==== 立刻跑一次（不等下一个触发点）====
# next_run_time=datetime.now() 让任务在下次调度检查时立即执行
from datetime import datetime
scheduler.add_job(cleanup, "date", run_date=datetime.now(), id="cleanup_once")

try:
    scheduler.start()         # 阻塞在这
except (KeyboardInterrupt, SystemExit):
    scheduler.shutdown(wait=True)
```

⚠️ 坑：

- 默认时区是系统时区，跨时区部署要显式 `timezone="Asia/Shanghai"`
- 任务重叠会堆积：`max_instances=1` 是必须的
- `BlockingScheduler` 会阻塞主线程；在服务里用 `BackgroundScheduler`
- 进程重启后内存里的任务全丢——需要持久化用 `SQLAlchemyJobStore`
- 单机定时任务其实 crontab 更可靠（不依赖进程常驻）；APScheduler 适合「已经在跑的服务里加定时逻辑」

------

### 检查清单

```
□ 能判断该用线程池还是进程池
□ 知道 max_workers 不是越大越好
□ 会用 as_completed 而不是按提交顺序收
□ 记得 fut.result() 会重抛任务异常
□ tenacity 必须写 stop=，否则会无限重试
□ 重试要加抖动，且只对幂等操作
□ APScheduler 记得 max_instances=1 和 timezone
```

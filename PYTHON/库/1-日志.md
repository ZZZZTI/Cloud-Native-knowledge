> 第 6 类：日志与可观测性。排障时的第一手证据——日志写不好，故障就是黑盒。
>

## 1. logging / logging.handlers ★★★ —— 分级日志、文件轮转

### 核心对象与关系

```
Logger   →   Handler   →   Formatter
（记录）     （往哪写）     （长什么样）

logger = logging.getLogger("inspect")     拿 logger（同名返回同一个）
logger.setLevel(logging.INFO)             本 logger 的级别
logger.addHandler(h) / removeHandler(h)   挂/摘 handler
logger.propagate = False                  不再往父 logger 传（避免重复输出）

logging.basicConfig(level=, format=, datefmt=, handlers=[...], force=True)
```

### 级别

```
DEBUG < INFO < WARNING < ERROR < CRITICAL
低于设定级别的直接丢弃（不产生任何开销）
```

### Logger 方法

```
logger.debug(msg, *args)       调试细节
logger.info(msg, *args)        正常流程
logger.warning(msg, *args)     需要关注
logger.error(msg, *args)       出错了但还能继续
logger.critical(msg, *args)    致命
logger.exception(msg)          只在 except 里用，自动附 traceback
logger.log(level, msg)         自定义级别
```

⚠️ 用 `%s` 占位，不要 f-string：

```Python
logger.debug("参数: %s", params)      # ✅ 不输出时零开销
logger.debug(f"参数: {params}")       # ❌ 无论输不输出都先拼字符串
```

### Handler

```
logging.StreamHandler(stream)                  输出到流（默认 stderr）
logging.FileHandler(path, encoding="utf-8")    输出到文件
logging.handlers.RotatingFileHandler(
    path, maxBytes=10*1024*1024, backupCount=5, encoding="utf-8")   按大小切
logging.handlers.TimedRotatingFileHandler(
    path, when="midnight", interval=1, backupCount=7, encoding="utf-8")  按时间切
logging.handlers.SysLogHandler(address="/dev/log")   写 syslog
logging.NullHandler()                          丢弃（库代码默认用）
```

### Formatter 字段

```
%(asctime)s     时间（配合 datefmt="%Y-%m-%d %H:%M:%S"）
%(levelname)s   级别名
%(name)s        logger 名
%(message)s     消息
%(module)s      模块名
%(funcName)s    函数名
%(lineno)d      行号
%(process)d     进程 ID
%(threadName)s  线程名
%(pathname)s    文件全路径
```

```Python
import logging
import sys

def setup_logging(level: str = "INFO") -> logging.Logger:
    """统一初始化：屏幕 + 轮转文件。"""
    logger = logging.getLogger("ops")
    logger.setLevel(level)
    logger.propagate = False
    logger.handlers.clear()          # 防止重复调用时挂多个 handler

    fmt = logging.Formatter(
        "%(asctime)s %(levelname)-7s %(name)s [%(funcName)s:%(lineno)d] %(message)s",
        datefmt="%Y-%m-%d %H:%M:%S",
    )

    # ==== 屏幕：容器里写 stdout，交给采集器 ====
    sh = logging.StreamHandler(sys.stdout)
    sh.setFormatter(fmt)
    logger.addHandler(sh)

    # ==== 文件：按大小轮转，保留 5 个 ====
    from logging.handlers import RotatingFileHandler
    fh = RotatingFileHandler(
        "/var/log/ops/inspect.log",
        maxBytes=10 * 1024 * 1024,
        backupCount=5,
        encoding="utf-8",            # ⚠️ 不写中文会乱码
    )
    fh.setFormatter(fmt)
    logger.addHandler(fh)

    return logger

log = setup_logging()
log.info("开始巡检 %s", "prod")
try:
    1 / 0
except ZeroDivisionError:
    log.exception("计算出错")         # 自动带完整堆栈
```

⚠️ 坑：

- 不设 `encoding="utf-8"`，Windows 或非 UTF-8 locale 下中文日志直接乱码
- 多次调用 `basicConfig` 没有效果（只在第一次生效），要 `force=True`
- 自己加 handler 前先确认 `logger.handlers` 里没有旧的，否则日志会重复几遍
- 容器里日志写 stdout，**不要写文件**（容器一删就没了）

## 2. traceback ★★ —— 记录完整异常栈

```
traceback.format_exc()              当前异常的完整栈（字符串）← 最常用
traceback.print_exc()               直接打到 stderr
traceback.format_exception(e)       指定异常对象
traceback.extract_tb(tb)            栈帧对象列表（可拿 filename/lineno/name/line）
traceback.TracebackException.from_exception(e)   结构化，可序列化
```

```Python
import logging
import traceback

log = logging.getLogger(__name__)

# ==== 不在 except 里也要记录栈 ====
try:
    risky()
except Exception:
    # 等价于 log.exception()，但要自己拼消息时用这个
    msg = traceback.format_exc()
    log.error("risky 失败:\n%s", msg)

# ==== 把栈写进告警内容 ====
def build_alert(exc: BaseException) -> str:
    tb = "".join(traceback.format_exception(type(exc), exc, exc.__traceback__))
    return f"任务失败\n{tb[-2000:]}"     # 截断，别把告警打成 10 万字

# ==== 结构化：拿到出错文件和行号 ====
try:
    1 / 0
except Exception as e:
    te = traceback.TracebackException.from_exception(e)
    for frame in te.stack:
        print(f"{frame.filename}:{frame.lineno} in {frame.name}")
```

⚠️ 坑：

- `format_exc()` 只能在 `except` 块内用，外面调用返回 `"NoneType: None"`
- 告警里贴完整栈通常没用，**截断到 2000 字**以内，把关键行留在前面

## 3. Loguru ★★ —— 语法更简洁的日志

零配置就有好日志：带颜色、带时间、自动轮转。

```
from loguru import logger

logger.add(
    sink,                    文件路径 / sys.stdout / 函数
    level="INFO",            级别
    format="...",            格式（用 {} 而不是 %）
    rotation="10 MB",        按大小切（也支持 "00:00" 每天、"1 week"）
    retention="7 days",      保留多久（或 "10 files"）
    compression="gz",        压缩旧文件
    encoding="utf-8",        文件编码
    enqueue=True,            多进程/多线程安全（异步写）
    backtrace=True,          显示更完整的栈
    diagnose=False,          生产要关（会打印变量值，可能泄露密钥）
)
logger.remove()              移除默认 handler（避免重复）
logger.info("x {}", var)     用 {} 占位
logger.exception("失败")     在 except 里自动带栈
logger.bind(request_id="abc").info("带上下文")     绑定字段
@logger.catch                装饰器：自动捕获异常并记录
logger.opt(exception=True).error("x")             非 except 里也记录栈
```

```Python
import sys
from loguru import logger

# ==== 初始化：清掉默认的，按需重配 ====
logger.remove()                                        # 去掉默认 stderr handler

logger.add(sys.stdout, level="INFO",
           format="<green>{time:HH:mm:ss}</green> | "
                  "<level>{level: <7}</level> | {message}")

logger.add("/var/log/ops/app.log",
           level="DEBUG",
           rotation="10 MB",        # 写满 10MB 切一个
           retention="7 days",      # 只留 7 天
           compression="gz",
           encoding="utf-8",
           enqueue=True,            # 多线程安全
           diagnose=False)          # 生产必须关

# ==== 带上下文 ====
req = logger.bind(task="backup", host="10.0.0.1")
req.info("开始备份")
req.warning("磁盘不足 {pct}%", pct=92)

# ==== 用装饰器兜住未预期异常 ====
@logger.catch(reraise=True)
def risky():
    return 1 / 0
```

```Shell
# 输出示例
10:00:01 | INFO    | 开始备份
10:00:02 | WARNING | 磁盘不足 92%
```

⚠️ 坑：

- `diagnose=True`（默认值）会在异常时打印**局部变量值**，生产环境可能泄露 token，必须关掉
- 不 `logger.remove()` 会同时输出到默认 stderr 和你的 handler，日志重复
- 多进程写同一个文件必须 `enqueue=True`，否则日志会互相覆盖

## 4. structlog ★ —— 结构化日志，与 OTel 集成好

结构化日志（每行一个 JSON），给日志平台（Loki / ES）和 OTel 用。

```
structlog.configure(
    processors=[...],
    wrapper_class=structlog.make_filtering_bound_logger(logging.INFO),
    logger_factory=structlog.PrintLoggerFactory(),
    cache_logger_on_first_use=True,
)
structlog.get_logger()
log.info("event", key=value, ...)     事件名 + 键值对
```

```Python
import logging
import structlog

structlog.configure(
    processors=[
        structlog.contextvars.merge_contextvars,     # 带上下文变量
        structlog.processors.add_log_level,
        structlog.processors.TimeStamper(fmt="iso"),
        structlog.processors.StackInfoRenderer(),
        structlog.processors.format_exc_info,        # 异常转字符串
        structlog.processors.JSONRenderer(),         # 输出 JSON
    ],
    wrapper_class=structlog.make_filtering_bound_logger(logging.INFO),
    logger_factory=structlog.PrintLoggerFactory(),
    cache_logger_on_first_use=True,
)

log = structlog.get_logger()
log.info("inspect_done", hosts=42, failed=3)         # 字段直接当参数传
# {"event":"inspect_done","hosts":42,"failed":3,"level":"info","timestamp":"..."}
```

定位：日志要进 Loki/ES 做检索、要和 TraceID 关联时用它；小脚本用 Loguru 更省事。

### 选型建议

```
场景                                 选择
标准库、不装依赖                     logging + RotatingFileHandler
中小脚本、想省事                     Loguru
日志进平台做检索、要 JSON            structlog
已在用 OpenTelemetry                 structlog（和 OTel 集成最顺）
```

### 检查清单

```
□ 知道 level 顺序，低于设定级别直接丢弃
□ 会用 %s 占位而不是 f-string
□ 会配 RotatingFileHandler（maxBytes + backupCount + encoding）
□ 记得 log.exception 只能在 except 里
□ 知道 Loguru 的 diagnose 生产要关
□ 容器日志写 stdout，不写文件
```

> 第 8 步：出错是常态。运维脚本的价值不在于「永远不出错」，而在于「出错时能说清楚哪里错了、并优雅退出」。
>
> 异常类型，try/except，raise，自定义异常，断言，logging，pdb 调试

------

## 1. 异常长什么样

```python
1 / 0
# Traceback (most recent call last):
#   File "x.py", line 1, in <module>
#     1 / 0
# ZeroDivisionError: division by zero
```

读 Traceback 的顺序：**从下往上**。

1. 最后一行：异常类型 + 消息（最关键）
2. 倒数第二行：出错的具体代码
3. 再往上：调用链（谁调用了它）

----- 

## 2. 常见异常类型

| 异常 | 触发场景 | 典型原因 |
| :-- | :-- | :-- |
| `SyntaxError` | 语法错误 | 少括号、少冒号、中文标点 |
| `IndentationError` | 缩进错误 | Tab 和空格混用 |
| `NameError` | 名字不存在 | 变量没定义、拼写错 |
| `TypeError` | 类型不对 | `"1" + 1`、参数个数不对 |
| `ValueError` | 值不对 | `int("abc")` |
| `KeyError` | 字典没这个 key | 应该用 `.get()` |
| `IndexError` | 列表越界 | 下标超出 |
| `AttributeError` | 对象没这个属性 | 拼写错、类型不对 |
| `FileNotFoundError` | 文件不存在 | 路径错 |
| `PermissionError` | 没权限 | 用户/文件权限 |
| `ModuleNotFoundError` | 模块没装 | 环境不对 |
| `TimeoutError` | 超时 | 网络/命令执行超时 |

## 3. try / except

```python
try:
    data = int(user_input)          # 可能抛 ValueError
except ValueError:
    print("不是合法数字")
    data = 0
```

```python
# 完整结构：四个分支
try:
    f = open("config.yaml", encoding="utf-8")
    cfg = yaml.safe_load(f)
except FileNotFoundError:
    print("配置文件不存在，用默认值")
    cfg = {}
except yaml.YAMLError as e:          # 捕获并拿到异常对象
    print("YAML 格式错误：", e)
    raise                            # raise 空的 = 原样再抛出去
else:
    print("读取成功")                 # 没有异常才执行
finally:
    f.close()                        # 无论成败都执行（用 with 就不需要它）
```

```python
# 一次捕获多种
try:
    ...
except (ValueError, TypeError) as e:
    print("转换失败：", e)
```

## 4. 三条铁律

### ① 禁止裸 except

```python
try:
    ...
except:              # ❌ 连 Ctrl+C、SystemExit 都被吞掉
    pass
```

裸 `except:` 等价于 `except BaseException:`，会把 `KeyboardInterrupt` 一起接住，脚本变得 Ctrl+C 都停不下来，只能用 `kill -9`。

### ② 禁止静默吞异常

```python
try:
    do_something()
except Exception:
    pass             # ❌ 出错了没人知道，半年后数据少了都查不到
```

至少要记日志：

```python
except Exception:
    logging.exception("do_something 失败")    # 自动带 traceback
```

### ③ 只捕你处理得了的异常

```python
# ✅ 知道怎么处理：文件不存在就用默认值
try:
    cfg = json.load(open("c.json", encoding="utf-8"))
except FileNotFoundError:
    cfg = {}

# ❌ 不知道怎么办就别捕，让它带着完整 traceback 崩掉
#    崩掉总比悄悄用错数据继续跑要好
```

## 5. 主动抛异常：raise

```python
def read_port(path):
    port = int(open(path).read().strip())
    if not (1 <= port <= 65535):
        raise ValueError(f"端口超出范围: {port}")
    return port
```

**为什么主动抛**：发现问题就立刻停下，比让错误数据流到下游再炸出来容易定位得多（fail fast）。

```python
# raise 的三种用法
raise ValueError("参数非法")        # 抛新的
raise                                # 把当前异常原样再抛（在 except 里用）
raise RuntimeError("包装") from e    # 抛出时保留原始异常链
```

## 6. 自定义异常

```python
class OpsError(Exception):
    """所有运维脚本异常的基类。"""

class RetryableError(OpsError):
    """可重试：网络抖动、临时 5xx。"""

class FatalError(OpsError):
    """不可重试：配置错误、权限不足。"""

# 使用
try:
    call_api()
except RetryableError:
    time.sleep(3)
    retry()
except FatalError:
    log.error("放弃")
    sys.exit(2)
```

好处：上层能按「能不能重试」分流，而不是靠字符串匹配错误消息。

## 7. 调试：三种手段

### ① 打印（最快，别不好意思用）

```python
x = 42
print(f"{x=}")                       # x=42    Python 3.8+ 的神技
print(f"{pods=}")                    # 变量名和值一起打

# 关键位置打日志
logging.debug("请求参数 %s", params)
```

### ② breakpoint()：进交互式调试

```python
def process(data):
    breakpoint()          # 执行到这里会停下来
    # 此时可以：
    #   p data           打印变量
    #   n                下一行
    #   s                进入函数
    #   c                继续执行
    #   q                退出调试
    return data
```

比 `print` 强的地方：**能随意查看任意变量、能单步执行**。

### ③ logging：给脚本留证据

```python
import logging

logging.basicConfig(
    level=logging.INFO,                  # 生产用 INFO，调试用 DEBUG
    format="%(asctime)s %(levelname)s %(message)s",
)
log = logging.getLogger(__name__)

log.debug("细节，默认不输出")
log.info("开始处理 %s 个节点", 10)
log.warning("磁盘水位 %s%%", 85)
log.error("连接失败: %s", err)
log.exception("带 traceback 的错误")      # 只能在 except 里用
```

**`print` vs `logging`**：

| | print | logging |
| :-- | :-- | :-- |
| 分级 | 无 | DEBUG/INFO/WARNING/ERROR |
| 时间戳 | 自己拼 | 自动 |
| 输出到文件 | 要手动重定向 | `FileHandler` |
| 生产开关 | 要改代码 | 调 level 即可 |

## 8. 让脚本优雅失败

```python
#!/usr/bin/env python3
import logging, sys

log = logging.getLogger("inspect")

def main() -> int:
    try:
        run()
        return 0
    except FatalError as e:
        log.error("无法继续: %s", e)
        return 2                  # 2 = 执行失败
    except Exception:
        log.exception("未预期的错误")   # 保留完整 traceback
        return 2

if __name__ == "__main__":
    raise SystemExit(main())
```

**退出码约定**：

| 码 | 含义 | 谁关心 |
| :-- | :-- | :-- |
| `0` | 正常 | CI/监控判断成功 |
| `1` | 检查不通过 | 业务异常（有 Pod 挂了） |
| `2` | 脚本执行失败 | 环境/参数/连接问题 |

## 9. 本章检查清单

```python
# 1. 这个 except 有什么问题？
try:
    risky()
except:
    pass
# 答：裸 except 会吞掉 Ctrl+C；静默吞异常导致无法排障

# 2. 改成正确写法
try:
    risky()
except (ValueError, OSError):
    log.exception("risky 失败")

# 3. 让函数在参数非法时立刻失败
def set_replicas(n):
    if n < 0:
        raise ValueError(f"副本数不能为负: {n}")
```

## 核心概念

1. **Traceback 从下往上读**，最后一行才是根因。
2. **禁止裸 `except:`**，禁止 `except Exception: pass`。
3. **只捕获知道怎么处理的异常**，其余让它崩。
4. **`raise` 主动失败**（fail fast）比带病继续跑好。
5. **自定义异常区分「可重试/不可重试」**，比匹配字符串可靠。
6. **`logging.exception` 自动带 traceback**，排障时比 `print(e)` 有用得多。
7. **`breakpoint()` 能单步调试**，复杂问题比 print 快。
8. **退出码分 0/1/2**，监控和 CI 靠它判断结果。

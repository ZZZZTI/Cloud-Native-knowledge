> 第 11 步：并发。运维脚本的并发目的很单一——把「逐个串行等」变成「一起等」。
> 典型场景：同时探测 500 台机器、同时调 200 次 API。
>
> GIL，线程池，进程池，asyncio，限流，超时与取消，常见坑

------

## 1. 先分清：IO 密集还是 CPU 密集

```
类型      特征            例子                                  用什么
IO 密集   大部分时间在等  HTTP 请求、SSH、读文件、查库          线程池 或 asyncio
CPU 密集  大部分时间在算  正则匹配大文本、压缩、算哈希、加解密  进程池
```

**选错的代价**：用线程跑 CPU 密集任务，速度和非并发几乎一样（GIL 限制），还会因为切换开销更慢。

### GIL 是什么

**全局解释器锁**：同一时刻只允许一个线程执行 Python 字节码。

- 所以**多线程不能加速纯计算**
- 但线程在**等待 IO 时会释放 GIL**，所以多线程能加速网络请求

一句话：**线程解决「等」，进程解决「算」**。

## 2. 线程池：IO 密集的首选

```python
from concurrent.futures import ThreadPoolExecutor, as_completed
import socket

HOSTS = [f"10.0.0.{i}" for i in range(1, 101)]

def probe(host: str, port: int = 9100) -> tuple[str, bool]:
    """探测单个目标，返回 (host, 是否可达)。"""
    try:
        with socket.create_connection((host, port), timeout=2):
            return host, True
    except OSError:
        return host, False

results = []

# max_workers 是并发上限，不是越大越好
with ThreadPoolExecutor(max_workers=20) as pool:
    # 提交任务，得到 future 对象
    futures = {pool.submit(probe, h): h for h in HOSTS}

    # as_completed：谁先完成就先处理谁（不是按提交顺序）
    for fut in as_completed(futures):
        host, ok = fut.result()          # 拿返回值；任务抛异常会在这一行抛
        results.append((host, ok))
        if not ok:
            print("不可达:", host)

ok_count = sum(1 for _, ok in results if ok)
print(f"{ok_count}/{len(results)} 可达")
```

**并发数怎么定**：

- IO 密集一般 **10–50** 就够
- 太高会把对端打挂、或本地文件描述符耗尽（`Too many open files`）
- 对上游客服端有速率限制时，要配合重试与退避

### 用 map 简化（不需要区分先后顺序时）

```python
with ThreadPoolExecutor(max_workers=20) as pool:
    for host, ok in pool.map(probe, HOSTS):   # 按输入顺序返回结果
        print(host, ok)
```

## 3. 进程池：CPU 密集

```python
from concurrent.futures import ProcessPoolExecutor
from pathlib import Path
import hashlib

def sha256(path: str) -> tuple[str, str]:
    """算文件哈希（纯 CPU 活）。"""
    h = hashlib.sha256()
    with open(path, "rb") as f:
        for chunk in iter(lambda: f.read(1 << 20), b""):
            h.update(chunk)
    return path, h.hexdigest()

files = [str(p) for p in Path("/data").rglob("*.tar")]

# 不传 max_workers 时默认用 CPU 核数
with ProcessPoolExecutor() as pool:
    for path, digest in pool.map(sha256, files):
        print(digest[:12], path)
```

**进程池的限制**：

- 参数和返回值**必须可 pickle**（不能传连接对象、文件句柄、lambda）
- 启动开销比线程大，任务太碎反而更慢
- 进程间不共享内存，要用 `Queue`/`Manager` 传数据

## 4. asyncio：要同时管上千个连接时用它

```python
import asyncio

async def probe(host: str, port: int = 9100, timeout: float = 2) -> tuple[str, bool]:
    """协程版探测。"""
    try:
        # asyncio.open_connection 不会阻塞事件循环
        reader, writer = await asyncio.wait_for(
            asyncio.open_connection(host, port), timeout=timeout
        )
        writer.close()
        await writer.wait_closed()
        return host, True
    except (OSError, asyncio.TimeoutError):
        return host, False

async def main(hosts: list[str]) -> None:
    sem = asyncio.Semaphore(50)      # 限流：同时最多 50 个

    async def one(host: str):
        async with sem:              # 拿到令牌才真正发请求
            return await probe(host)

    # gather 并发执行所有协程，结果按传入顺序返回
    results = await asyncio.gather(*(one(h) for h in hosts))
    ok = sum(1 for _, up in results if up)
    print(f"{ok}/{len(results)} 可达")

asyncio.run(main([f"10.0.0.{i}" for i in range(1, 501)]))
```

### 三个必备技巧

```python
# ① 超时（3.11+）
async with asyncio.timeout(10):
    await do_something()

# ① 超时（兼容旧版本）
await asyncio.wait_for(do_something(), timeout=10)

# ② 容错：某个失败不影响整体
results = await asyncio.gather(*tasks, return_exceptions=True)
for r in results:
    if isinstance(r, Exception):
        print("失败:", r)

# ③ 分批处理，避免一次性创建百万协程
for i in range(0, len(items), 500):
    batch = items[i:i + 500]
    await asyncio.gather(*(handle(x) for x in batch))
```

## 5. 超时：三层都要设

**没有超时的并发脚本 = 半夜卡死事故。**

```python
requests.get(url, timeout=(3.05, 10))    # (连接超时, 读取超时)
subprocess.run(cmd, timeout=30)          # 外部命令
asyncio.timeout(10)                      # 协程
pool.map(fn, items)                      # ⚠️ 线程池本身不支持整体超时
```

线程池**无法真正杀死**正在运行的线程，所以超时必须**下沉到具体的 IO 调用里**（socket、requests 的 timeout 参数），外层强杀靠不住。

```python
# 折中方案：用 wait 给一个总体超时，超时就放弃等待
from concurrent.futures import wait, FIRST_COMPLETED

done, not_done = wait(futures, timeout=60)
for f in not_done:
    f.cancel()          # 只能取消「还没开始跑」的任务
```

## 6. 常见坑

### ① 共享可变状态没加锁

```python
counter = 0
def work():
    global counter
    counter += 1        # ❌ 读-改-写三步，线程切换会丢计数

# ✅ 用锁
import threading
lock = threading.Lock()
def work():
    global counter
    with lock:
        counter += 1
```

**更好的做法：不要共享状态**。让每个任务返回结果，最后统一汇总：

```python
results = []
with ThreadPoolExecutor() as pool:
    results = list(pool.map(probe, hosts))   # 无共享，无锁
```

### ② 在 asyncio 里调用同步阻塞代码

```python
async def bad():
    time.sleep(1)                  # ❌ 卡住整个事件循环
    requests.get(url)              # ❌ 同上

async def good():
    await asyncio.sleep(1)         # ✅
    await asyncio.to_thread(requests.get, url)   # ✅ 丢进线程池
```

### ③ 一次性提交太多任务

```python
# ❌ 10 万个 future 一起创建，内存爆炸
futures = [pool.submit(f, x) for x in big_list]

# ✅ 分批，或用 Semaphore 限流
for chunk in chunks(big_list, 1000):
    list(pool.map(f, chunk))
```

### ④ 忘了处理异常

```python
# future.result() 会把任务里的异常重新抛出来
for fut in as_completed(futures):
    try:
        r = fut.result()
    except Exception:
        log.exception("任务失败")     # 不接住的话，一个失败就中断整个汇总
```

## 7. 实战：并发 SSH 巡检

```python
from concurrent.futures import ThreadPoolExecutor
import subprocess

HOSTS = ["10.0.0.1", "10.0.0.2", "10.0.0.3"]

def check(host: str) -> dict:
    """登上去看磁盘水位。"""
    try:
        r = subprocess.run(
            ["ssh", "-o", "BatchMode=yes", "-o", "ConnectTimeout=3",
             host, "df -h / | tail -1 | awk '{print $5}'"],
            capture_output=True, text=True, timeout=10,
        )
        usage = r.stdout.strip().rstrip("%")
        return {"host": host, "ok": r.returncode == 0,
                "usage": int(usage) if usage.isdigit() else None}
    except subprocess.TimeoutExpired:
        return {"host": host, "ok": False, "usage": None, "error": "timeout"}
    except Exception as e:
        return {"host": host, "ok": False, "usage": None, "error": str(e)}

with ThreadPoolExecutor(max_workers=10) as pool:
    for res in pool.map(check, HOSTS):
        if not res["ok"]:
            print(f"[FAIL] {res['host']}: {res.get('error')}")
        elif res["usage"] and res["usage"] > 85:
            print(f"[WARN] {res['host']} 磁盘 {res['usage']}%")
        else:
            print(f"[OK]   {res['host']} 磁盘 {res['usage']}%")
```

## 核心概念

1. **IO 密集用线程/协程，CPU 密集用进程**，选错等于没并发。
2. **GIL 让多线程不能加速计算**，但等待 IO 时会释放。
3. **并发度必须有上限**，否则打挂对端或耗尽 fd。
4. **超时下沉到具体 IO 调用**，线程池本身杀不掉运行中的线程。
5. **尽量无共享状态**，任务返回结果、主线程汇总，比加锁干净。
6. **asyncio 里禁止同步阻塞**，用 `asyncio.to_thread` 包一层。
7. **`fut.result()` 会重抛任务异常**，要 try 住否则一个失败中断全部。

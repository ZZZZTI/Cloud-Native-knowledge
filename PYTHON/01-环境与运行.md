## 为什么运维要学 Python

Shell 能做的事 Python 都能做，而且更稳：

```
场景                 Shell            Python
拼字符串、解析 JSON  靠 jq/sed，脆弱  原生支持，不会因空格出错
调用 HTTP API        curl + 手工解析  requests，自动重试、超时
复杂判断/循环        语法笨重，易错   清晰可读
跨平台               依赖 GNU 工具    一处编写到处运行
单元测试             几乎没法测       pytest
```

**结论**：临时一次性操作用 Shell，超过 50 行、要调 API、要解析结构化数据 → 用 Python。

## 1. 安装与确认版本

```bash
# macOS
brew install python@3.12

# RHEL / CentOS
dnf install -y python3 python3-pip

# Ubuntu / Debian
apt install -y python3 python3-pip python3-venv

# 确认装好了（运维脚本建议 3.9+）
python3 --version        # Python 3.12.x
python3 -c "print('ok')" # 能打印 ok 就说明可执行
```

⚠️ 命令是 `python3` 不是 `python`。很多系统上 `python` 不存在，或者指向 Python 2。

## 2. 三种运行方式

```bash
# ① 交互式（REPL）：试语法、算数、看结果，退出用 exit() 或 Ctrl+D
python3
>>> 1 + 1
2
>>> exit()

# ② 执行脚本文件（最常用）
python3 hello.py

# ③ 直接执行一条语句（临时验证）
python3 -c "import sys; print(sys.version)"
```

## 3. 第一个脚本

```python
#!/usr/bin/env python3
# 第一行叫 shebang，告诉系统用哪个解释器执行这个文件
# 加了它，并且 chmod +x 之后，可以直接 ./hello.py 运行

# 这是单行注释，用井号开头，解释器会忽略

"""
这是多行字符串，放在文件开头时通常当作「文档注释」，
说明这个脚本是干什么用的。
"""

import sys          # 导入标准库里的 sys 模块（后面章节详讲）

def main():
    # print() 把内容输出到屏幕（标准输出）
    print("Hello, 运维")

    # sys.argv 是命令行参数列表
    # sys.argv[0] 是脚本名本身，sys.argv[1:] 才是用户传的参数
    print("收到的参数：", sys.argv[1:])

# 这行的意思是：只有「直接运行本文件」时才执行 main()
# 如果本文件被别的脚本 import，则不会自动执行
if __name__ == "__main__":
    main()
```

```bash
chmod +x hello.py    # 加执行权限
./hello.py a b c     # 输出：Hello, 运维 / 收到的参数： ['a', 'b', 'c']
```

## 4. 虚拟环境：每个项目一个

**为什么必须用**：不同项目依赖不同版本的库，直接装进系统 Python 会互相打架，还会污染系统自带工具。

```bash
cd my-ops-scripts
python3 -m venv .venv        # 在项目目录下创建虚拟环境（.venv 是惯例名）
source .venv/bin/activate    # 激活（激活后命令行前面会出现 (.venv)）
# Windows 用：.venv\Scripts\activate

which python3                # 确认现在指向 .venv/bin/python3
pip install requests         # 装到这个环境里，不影响系统

deactivate                   # 退出虚拟环境
```

`.venv/` 目录**不要提交到 git**（写进 `.gitignore`）。

## 5. 依赖管理

```bash
pip install requests          # 装最新版
pip install requests==2.32.3  # 装指定版本（运维脚本推荐）
pip show requests             # 看已装版本和依赖
pip list                      # 列出全部

pip freeze > requirements.txt     # 导出当前环境的精确版本
pip install -r requirements.txt   # 按清单还原（换机器/上线时用）
```

```Shell
# requirements.txt 长这样
requests==2.32.3
PyYAML==6.0.2
prometheus-client==0.21.0
```

**运维铁律**：脚本要交付给别人/跑在服务器上，依赖必须**锁定精确版本**（用 `==`），否则「上周还能跑、这周就报错」。

## 6. 常见报错对照

```
报错                                             原因                                      解决
python3: command not found                       没装或不在 PATH                           装 python3，或用绝对路径
ModuleNotFoundError: No module named 'requests'  没装，或装到了另一个环境                  先 which python3 确认环境，再 pip install
SyntaxError: invalid syntax                      语法错（少括号、少冒号、混用中英文标点）  看报错行号，注意别用中文逗号/引号
IndentationError                                 缩进不一致（空格和 Tab 混用）             统一用 4 个空格
PermissionError                                  文件/目录没权限                           chmod 或换运行用户
UnicodeDecodeError                               编码不对                                  打开文件时显式写 encoding="utf-8"
```

## 核心概念

1. **命令是 `python3`**，不是 `python`；脚本首行 `#!/usr/bin/env python3` 让文件可直接执行。
2. **每个项目一个 `venv`**，不要往系统 Python 装包。
3. **依赖锁定精确版本**，用 `requirements.txt` 交付。
4. **`if __name__ == "__main__"`** 让文件既能直接跑、又能被 import 复用。
5. **缩进必须统一 4 个空格**，混用 Tab 是最常见的低级错误。
6. **报错先看最后一行**（异常类型 + 消息），再看行号。

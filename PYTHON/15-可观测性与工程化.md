## 1. 结构化日志：让日志可检索

日志平台（Loki / ES）要的是**字段**，不是一行拼接文本。

```python
import logging, json, sys

class JsonFormatter(logging.Formatter):
    """把每条日志输出成一行 JSON。"""
    def format(self, record: logging.LogRecord) -> str:
        payload = {
            "ts": self.formatTime(record, "%Y-%m-%dT%H:%M:%S%z"),
            "level": record.levelname,
            "logger": record.name,
            "msg": record.getMessage(),
        }
        if record.exc_info:
            payload["exc"] = self.formatException(record.exc_info)

        # 通过 extra= 传入的自定义字段一并输出
        for k, v in record.__dict__.items():
            if k not in logging.LogRecord.__dict__ and not k.startswith("_"):
                payload.setdefault(k, v)
        return json.dumps(payload, ensure_ascii=False)

handler = logging.StreamHandler(sys.stdout)
handler.setFormatter(JsonFormatter())
logging.basicConfig(level=logging.INFO, handlers=[handler])

log = logging.getLogger("inspect")
log.info("巡检完成", extra={"hosts": 42, "failed": 3})
# {"ts":"2026-10-27T10:00:00+0800","level":"INFO","logger":"inspect","msg":"巡检完成","hosts":42,"failed":3}
```

**容器里的日志必须写 stdout**，交给采集器统一收集，不要自己写文件（容器一删就没了）。

## 2. Prometheus exporter：给系统加指标

```python
from prometheus_client import start_http_server, Counter, Gauge, Histogram
import time

# 选对指标类型是第一步
PROBES   = Counter("probe_requests_total", "探测总次数", ["target", "result"])
LATENCY  = Histogram("probe_latency_seconds", "探测耗时", ["target"],
                     buckets=(.05, .1, .25, .5, 1, 2.5, 5, 10))
UP       = Gauge("probe_up", "目标是否可达", ["target"])

def probe(target: str) -> None:
    start = time.time()
    ok = check(target)                                     # 你的探测逻辑
    PROBES.labels(target=target, result="ok" if ok else "fail").inc()
    LATENCY.labels(target=target).observe(time.time() - start)
    UP.labels(target=target).set(1 if ok else 0)

if __name__ == "__main__":
    start_http_server(9101)        # 暴露 /metrics
    while True:
        for t in ("api", "web", "db"):
            probe(t)
        time.sleep(15)
```

| 类型 | 含义 | 用途 |
| :-- | :-- | :-- |
| `Counter` | 只增不减 | 请求数、错误数（名字以 `_total` 结尾） |
| `Gauge` | 可增可减 | 当前连接数、是否可用、队列长度 |
| `Histogram` | 分桶统计 | 延迟分布，能算 P99 且可跨实例聚合 |
| `Summary` | 客户端分位 | **不能跨实例聚合**，一般不建议当指标用 |

```Shell
# 验证
curl -s localhost:9101/metrics | grep probe_
```

**命名约定**：单位写进名字（`_seconds`、`_bytes`），Counter 加 `_total`。

## 3. OpenTelemetry：统一埋点

```python
from opentelemetry import trace
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from opentelemetry.exporter.otlp.proto.grpc.trace_exporter import OTLPSpanExporter

provider = TracerProvider()
provider.add_span_processor(
    BatchSpanProcessor(OTLPSpanExporter(endpoint="http://otel-collector:4317", insecure=True))
)
trace.set_tracer_provider(provider)
tracer = trace.get_tracer(__name__)

with tracer.start_as_current_span("probe_cluster") as span:
    span.set_attribute("cluster", "prod")
    try:
        do_work()
    except Exception as e:
        span.record_exception(e)
        span.set_status(trace.Status(trace.StatusCode.ERROR))
        raise
```

OTel 的价值是**一套 SDK 同时产出 metrics/logs/traces**，且能关联起来（TraceID 注入日志）。

## 4. 脚本骨架：五件事缺一不可

```python
#!/usr/bin/env python3
"""巡检集群异常 Pod。异常时退出码 1。"""
import argparse, logging, sys

log = logging.getLogger("inspect")

def parse_args() -> argparse.Namespace:
    p = argparse.ArgumentParser(description=__doc__)
    p.add_argument("-n", "--namespace", default="", help="限定命名空间")
    p.add_argument("--dry-run", action="store_true")
    p.add_argument("-v", "--verbose", action="store_true")
    return p.parse_args()

def main() -> int:
    args = parse_args()

    # ① 日志：级别可调，格式统一
    logging.basicConfig(
        level=logging.DEBUG if args.verbose else logging.INFO,
        format="%(asctime)s %(levelname)s %(message)s",
    )

    # ② 参数：全部来自命令行/环境变量，不交互

    # ③ 异常：兜住未预期的错误，保留 traceback
    try:
        problems = run_checks(args.namespace)
    except Exception:
        log.exception("执行失败")
        return 2                                    # 2 = 执行失败

    # ④ 结果：明确输出，便于人看和机器解析
    if problems:
        for p in problems:
            log.warning("异常: %s", p)
        return 1                                    # 1 = 检查不通过
    log.info("全部正常")
    return 0                                        # 0 = 正常

if __name__ == "__main__":
    # ⑤ 退出码：交给调用方（CI / 监控）判断
    raise SystemExit(main())
```

**退出码约定**：

| 码 | 含义 | 谁用 |
| :-- | :-- | :-- |
| `0` | 正常 | 监控判定通过 |
| `1` | 检查不通过 | 业务异常 |
| `2` | 执行失败 | 环境/参数/连接问题 |

## 5. pytest：只测「纯函数」就够

```python
# tests/test_checks.py
from lib.checks import find_problems, classify

def test_find_problems():
    pods = [
        {"name": "a", "status": "Running", "restarts": 0},
        {"name": "b", "status": "Failed",  "restarts": 0},
        {"name": "c", "status": "Running", "restarts": 15},
    ]
    assert [p["name"] for p in find_problems(pods, threshold=10)] == ["b", "c"]

def test_classify():
    assert classify("Running") == "ok"
    assert classify("Pending") == "wait"
    assert classify("weird")   == "bad"
```

```bash
pytest -q                      # 跑全部
pytest -q -k problems          # 只跑名字匹配的
```

```python
# 用 monkeypatch 隔离外部依赖，测试不会真的发请求
def test_api_failure(monkeypatch):
    def boom(*a, **k):
        raise ConnectionError("refused")
    monkeypatch.setattr("lib.client.requests.get", boom)

```

## 7. 分发：优先容器

| 方式 | 适用 | 说明 |
| :-- | :-- | :-- |
| `scp` 脚本 + 目标机 pip 装依赖 | 目标机可控 | 最简单，但依赖会漂移 |
| `python -m zipapp` | 纯标准库脚本 | 打成一个 `.pyz` 文件 |
| `pex` / `shiv` | 带第三方依赖 | 单文件可执行 |
| **Docker 镜像** | 有依赖、要长期跑 | **最稳，推荐** |
| `pyinstaller` | 目标机没有 Python | 体积大，运维少用 |

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
ENTRYPOINT ["python", "main.py"]
```

容器把 **Python 版本、依赖版本、系统库**全部固定，彻底消除「我这儿能跑」。

## 8. 实战：巡检脚本的完整形态

```python
#!/usr/bin/env python3
"""集群巡检：Pod 异常 + 节点水位 + 证书有效期。"""
import argparse, logging, sys
from prometheus_client import start_http_server, Gauge

log = logging.getLogger("inspect")

# 指标：让结果能被 Prometheus 采集，而不只是打印
CHECKS_FAILED = Gauge("inspect_failed_checks", "失败的检查项数量")

def run_all() -> list[str]:
    problems = []
    problems += check_pods()
    problems += check_nodes()
    problems += check_certs()
    return problems

def main() -> int:
    ap = argparse.ArgumentParser(description=__doc__)
    ap.add_argument("--metrics-port", type=int, default=0, help="暴露 /metrics 的端口")
    ap.add_argument("-v", "--verbose", action="store_true")
    args = ap.parse_args()

    logging.basicConfig(
        level=logging.DEBUG if args.verbose else logging.INFO,
        format="%(asctime)s %(levelname)s %(message)s",
    )
    if args.metrics_port:
        start_http_server(args.metrics_port)

    try:
        problems = run_all()
    except Exception:
        log.exception("巡检执行失败")
        return 2

    CHECKS_FAILED.set(len(problems))
    for p in problems:
        log.warning("%s", p)
    return 1 if problems else 0

if __name__ == "__main__":
    raise SystemExit(main())
```

配合 K8s CronJob 时：**退出码非 0 才会让 Job 失败并留下记录**，日志写 stdout 交给采集器。

## 核心概念

1. **日志写 stdout 且结构化（JSON）**，字段可检索才有价值。
2. **exporter 用 `prometheus_client`**，Counter 加 `_total`、单位写进名字。
3. **要算 P99 用 Histogram**，Summary 不能跨实例聚合。
4. **脚本骨架五件事**：参数、日志、异常、结果、退出码。
5. **退出码分 0/1/2**，监控和 CI 靠它判断。
6. **纯函数必须有测试**，用 `monkeypatch` 隔离外部依赖。
7. **分发优先用容器**，彻底消除环境差异。

> 进程与服务
> 覆盖：服务启动、端口占用、监听地址、僵尸进程、服务假死，日志暴涨、证书过期。
------

## 场景 1：服务启动失败

**现象**：`systemctl start nginx` 失败，提示 `Job for nginx.service failed`。

**可能原因**：

- 配置文件语法错误
- 端口被占用
- 运行用户权限不足
- 依赖服务未启动
- SELinux 拦截
- 磁盘满、PID 文件残留

**排查命令**：

```bash
systemctl status nginx -l  # 查看服务状态
journalctl -u nginx -n 100 --no-pager  # 查看服务日志
systemctl cat nginx  # 查看 unit 文件
systemctl show nginx -p ExecStart -p User -p Environment  # 查看 unit 属性
nginx -t  # 检查 Nginx 配置
ss -lntp | grep -E ':(80|443)\b'  # 查看 TCP 监听端口
getenforce  # 查看 SELinux 模式
ausearch -m avc -ts recent  # 查询审计日志
df -h  # 查看磁盘空间
```

**处理命令**：

```bash
# 修复配置后
systemctl daemon-reload  # 重载 systemd 配置
systemctl reset-failed nginx  # 清除服务失败状态
systemctl start nginx  # 启动服务

# 前台运行观察报错
nginx -g 'daemon off;'  # 前台运行 Nginx
```

**注意**：先看 `status` 和 `journalctl`，不要盲目重启；如果是 SELinux，先看 AVC 日志再决定 `restorecon` 或加策略。

## 场景 2：端口被占用

**现象**：服务启动时报 `Address already in use`，8080 端口无法监听。

**可能原因**：

- 旧进程未退出
- 另一个服务占用了同一端口
- 容器端口映射冲突
- 只杀了子进程，父进程仍持有端口

**排查命令**：

```bash
ss -lntp | grep ':8080'  # 查看 TCP 监听端口
lsof -i :8080  # 查看端口占用
fuser -v 8080/tcp  # 查看端口占用进程
ps -fp <PID>  # 查看指定 PID
ps -ef | grep <PID>  # 查找进程
```

**处理命令**：

```bash
kill -TERM <PID>  # 优雅终止进程
systemctl stop <old-service>  # 停止服务
# 确认无用后再强制
kill -9 <PID>  # 强制终止进程
fuser -k 8080/tcp  # 强制结束端口进程
```

**注意**：杀之前确认进程用途和父进程；如果是 systemd 服务，优先 `systemctl stop`，避免被自动拉起。

## 场景 3：服务只监听 127.0.0.1

**现象**：本机 `curl 127.0.0.1:8080` 正常，其他机器访问 `192.168.1.20:8080` 被拒绝。

**可能原因**：

- 应用配置绑定 `127.0.0.1`
- 只监听了 IPv6 回环
- 防火墙/安全组未放行
- 容器端口没有映射到宿主机

**排查命令**：

```bash
ss -lntp | grep ':8080'  # 查看 TCP 监听端口
lsof -i :8080  # 查看端口占用
curl -I http://127.0.0.1:8080/  # 检查 HTTP 响应头
curl -I http://192.168.1.20:8080/  # 检查 HTTP 响应头
firewall-cmd --list-all  # 管理 firewalld 规则
iptables -L -n -v  # 查看 iptables 规则
```

**处理命令**：

```bash
# 修改应用监听地址为 0.0.0.0 或业务网卡 IP
# Nginx: listen 0.0.0.0:8080;
# Tomcat: address="0.0.0.0"
# Python: app.run(host="0.0.0.0")
systemctl restart <service>  # 重启服务

# 验证
ss -lntp | grep ':8080'  # 查看 TCP 监听端口
nc -vz 192.168.1.20 8080  # 测试端口连通性
```

**注意**：开放到公网前加防火墙、ACL、反向代理和 TLS，不要把数据库、Redis、管理端口直接暴露。

## 场景 4：僵尸进程与进程无法杀死

**现象**：`ps` 中看到状态为 `Z` 的进程，数量持续增长；或者某个进程执行 `kill -9` 也杀不掉。

**可能原因**：

- 父进程没有调用 `wait()`/`waitpid()` 回收子进程
- 子进程已经退出，父进程仍在运行
- 进程处于 D 状态，卡在磁盘/NFS I/O
- 内核或驱动问题

**排查命令**：

```bash
ps -eo pid,ppid,stat,cmd | awk '$3 ~ /^Z/'  # 查找僵尸进程
ps -eo pid,ppid,stat,wchan:32,cmd | awk '$3 ~ /^[ZD]/'  # 查看 Z/D 状态进程
pstree -p <PPID>  # 查看父进程和子进程关系
cat /proc/<PID>/status  # 查看进程状态和父进程
cat /proc/<PID>/stack  # 查看内核栈（D 状态）
dmesg -T | tail -50  # 查看内核报错
```

**处理命令**：

```bash
# 僵尸进程：自身已经死了，kill 无效，要处理父进程
systemctl restart <父进程服务>  # 重启父进程，触发回收
# 如果父进程是 1 且不回收，考虑重启系统或修内核/容器问题

# D 状态：先解决 I/O/NFS，I/O 返回后进程才可能退出
umount -f /mnt/nfs  # 强制卸载异常 NFS
systemctl restart <服务>  # 重启卡住的服务
```

**注意**：`kill -9` 对僵尸进程无效；D 状态进程在 I/O 返回前通常也杀不掉。

## 场景 5：服务假死 / 健康检查失败

**现象**：进程还在、端口还在监听，`systemctl status` 显示 active，但请求超时或大量 500。

**可能原因**：

- 线程池耗尽、死锁
- 数据库连接池耗尽
- GC 停顿、内存不足
- 磁盘 I/O 卡住
- DNS/下游依赖超时

**排查命令**：

```bash
systemctl status <service>  # 查看服务状态
curl -v http://127.0.0.1:<port>/health  # 检查健康接口
ss -lntp | grep <port>  # 查看端口监听
ss -tan state established | wc -l  # 统计已建立连接
top -H -p <PID>  # 查看线程 CPU
jstack <PID> > /tmp/jstack.txt  # 导出 Java 线程栈
strace -f -p <PID> -o /tmp/strace.log  # 跟踪系统调用
lsof -p <PID>  # 查看进程打开的文件
```

**处理命令**：

```bash
systemctl restart <service>  # 先恢复业务
# 保留 jstack、heap dump、日志后再重启更稳妥
```

**注意**：重启只是止血；要在线程栈、连接池、GC 日志里找根因，避免反复假死。

## 场景 6：日志暴涨或日志切割不生效

**现象**：`/var/log` 快速变大，或者 logrotate 执行后日志仍持续增长、磁盘不释放。

**可能原因**：

- 应用 debug 日志未关闭
- 异常循环疯狂打日志
- logrotate 配置错误
- 轮转后应用仍写旧文件句柄
- 日志目录权限不对

**排查命令**：

```bash
du -sh /var/log/*  # 统计各日志目录大小
ls -lh /var/log/app.log  # 查看日志文件大小
lsof /var/log/app.log  # 查看谁在写日志
logrotate -d /etc/logrotate.d/app  # 调试 logrotate（只检查）
grep -E 'logrotate' /var/log/syslog  # 查看 logrotate 日志
```

**处理命令**：

```bash
# 测试配置
logrotate -d /etc/logrotate.d/app  # 调试 logrotate（只检查）
# 强制执行
logrotate -f /etc/logrotate.d/app  # 强制执行日志轮转

# 临时清空
truncate -s 0 /var/log/app.log  # 截断文件

# 应用支持重新打开日志时
kill -USR1 $(cat /run/app.pid)  # 通知进程重新打开日志
```

**注意**：`copytruncate` 可能丢少量日志；支持信号重新打开日志的程序优先用 `postrotate` + `USR1`。

## 场景 7：证书过期

**现象**：浏览器或 `curl` 报证书过期/不受信任，HTTPS 访问失败。

**可能原因**：

- 证书到期未续期
- 证书链不完整
- 域名与证书不匹配
- 系统时间错误
- 使用了自签证书但客户端不信任

**排查命令**：

```bash
openssl s_client -connect example.com:443 -servername example.com -showcerts </dev/null  # 查看 TLS 握手和证书链
openssl x509 -in cert.pem -noout -dates -subject -issuer  # 查看证书信息
openssl x509 -in cert.pem -checkend 86400 -noout  # 检查证书是否即将过期
curl -vI https://example.com/  # 带调试信息检查 HTTPS 响应
date  # 查看系统时间
```

**处理命令**：

```bash
# 续期后 reload
certbot renew  # 续期证书
nginx -t && nginx -s reload  # 检查配置并平滑重载

# 检查证书链
openssl verify -CAfile ca.pem cert.pem  # 校验证书链
```

**注意**：证书问题先看系统时间；证书链不完整时，浏览器可能正常而命令行客户端失败。

------

> 备注：命令以 Linux（GNU 工具链）为准；生产环境执行删除、重启、`kill -9`、`fsck`、改权限前，先确认影响范围。

> 磁盘与文件系统
> 覆盖：磁盘满、inode、已删除文件、只读、LVM、RAID、误删恢复、NFS、新盘识别。
------

## 场景 1：磁盘空间满

**现象**：`df -h` 显示根分区或数据盘使用率 100%，创建文件报 `No space left on device`。

**可能原因**：

- 日志、core dump、备份文件占满
- Docker 镜像/容器层/日志占满
- 已删除文件仍被进程占用
- 目录被挂载点覆盖
- 预留块导致 root 之外用户无法写

**排查命令**：

```bash
df -h  # 查看磁盘空间
df -i  # 查看 inode 使用率
du -x -h --max-depth=1 / 2>/dev/null | sort -rh | head -20  # 按目录层级统计大小
du -sh /var/* 2>/dev/null | sort -rh | head  # 统计目录/文件大小
find / -xdev -type f -size +1G -exec ls -lh {} \; 2>/dev/null  # 查找大文件
lsof +L1  # 查看已删除仍被占用的文件
lsof | grep deleted  # 查看已删除仍被占用的文件
ls -l /proc/<PID>/fd | grep deleted  # 查看已删除但被占用的 fd
```

**处理命令**：

```bash
# 日志清理
journalctl --vacuum-size=500M  # 清理 journal 日志
logrotate -f /etc/logrotate.d/nginx  # 日志轮转
truncate -s 0 /var/log/app.log  # 截断文件

# 已删除但仍被占用
: > /proc/<PID>/fd/<FD>  # 清空文件
systemctl restart <service>  # 重启服务

# Docker
docker system df  # 查看 Docker 空间占用
docker system prune -a  # 清理 Docker 无用数据
```

**注意**：不要直接 `rm` 正在写的日志，优先 `logrotate` 或 `truncate`；删除前先确认文件用途。

## 场景 2：inode 耗尽

**现象**：`df -h` 还有空间，但创建文件报 `No space left on device`，`df -i` 显示 inode 使用率接近 100%。

**可能原因**：

- 大量小文件：session、cache、邮件队列、临时文件
- 日志按请求生成，目录下文件数量爆炸
- Docker overlay2 层过多
- 应用异常重试产生海量小文件

**排查命令**：

```bash
df -i  # 查看 inode 使用率
df -h  # 查看磁盘空间
du -x --inodes -h --max-depth=1 / 2>/dev/null | sort -rh | head  # 按 inode 统计目录
find /var -xdev -type f | awk -F/ '{print "/"$2"/"$3"/"$4}' | sort | uniq -c | sort -nr | head  # 查找文件
find / -xdev -type f | wc -l  # 统计文件总数
```

**处理命令**：

```bash
# 清理过期 session
find /var/lib/php/sessions -type f -mtime +7 -delete  # 删除过期文件

# 清理临时文件
systemd-tmpfiles --clean  # 清理临时文件

# 清理邮件队列（先确认业务）
postsuper -d ALL  # 清空邮件队列（谨慎）

# Docker 无用层
docker system prune -a  # 清理 Docker 无用数据
```

**注意**：先定位目录再删；不要对 `/` 直接跑无差别 `find -delete`。

## 场景 3：删除文件后空间不释放

**现象**：删除了一个 20GB 的日志文件，`df -h` 显示空间没有减少。

**可能原因**：

- 文件仍被进程打开，inode 和数据块未释放
- 删除的是目录项，进程还持有 fd
- 日志轮转后旧文件句柄未关闭

**排查命令**：

```bash
lsof +L1  # 查看已删除仍被占用的文件
lsof | grep deleted  # 查看已删除仍被占用的文件
ls -l /proc/<PID>/fd | grep deleted  # 查看已删除但被占用的 fd
```

**处理命令**：

```bash
# 截断仍被占用的文件
: > /proc/<PID>/fd/<FD>  # 清空文件
truncate -s 0 /proc/<PID>/fd/<FD>  # 截断文件

# 或者重启持有文件的进程
systemctl restart <service>  # 重启服务
```

**注意**：不要写成 `lsof | grep deleted > /proc/...`；正确做法是找到 fd 后截断。长期方案是 logrotate 配 `copytruncate` 或 `postrotate` 发信号让应用重新打开日志。

## 场景 4：文件系统变成只读

**现象**：向 `/data` 写入文件时报 `Read-only file system`，重启后暂时恢复，一段时间后再次出现。

**可能原因**：

- 文件系统检测到错误，自动 remount-ro
- 磁盘坏道、I/O error
- 线缆、RAID 卡、SAN 链路故障
- NFS 服务端异常
- 误执行 `mount -o ro`

**排查命令**：

```bash
mount | grep '(ro,'  # 查看只读挂载
dmesg -T | tail -100  # 查看内核日志尾部
touch /data/test  # 测试目录是否可写
smartctl -a /dev/sdb  # 查看磁盘健康
cat /proc/mdstat  # 查看软 RAID 状态
```

**处理命令**：

```bash
# 临时恢复读写
mount -o remount,rw /data  # 将 /data 重新挂载为读写

# 彻底修复：先卸载
umount /data  # 卸载文件系统
fsck -f /dev/sdb1  # 检查文件系统
xfs_repair /dev/sdb1  # 修复 XFS 文件系统

# 根分区需要进救援模式处理
```

**注意**：不要在挂载状态下对根分区跑 `fsck`；硬件报错要优先备份并更换磁盘。

## 场景 5：LVM 扩容后容量没变

**现象**：云盘扩容或加了新盘，`lvextend` 也执行了，但 `df -h` 容量没变化。

**可能原因**：

- 只扩了 LV，没扩文件系统
- 新盘没加入 VG
- 扩错了 LV
- xfs 用 `resize2fs` 而不是 `xfs_growfs`

**排查命令**：

```bash
lsblk  # 查看块设备
df -h  # 查看磁盘空间
pvs  # 查看 LVM 信息
vgs  # 查看 LVM 信息
lvs -a -o +devices  # 查看 LVM 信息
findmnt /data  # 查看挂载信息
```

**处理命令**：

```bash
# 云盘扩容后先扩分区
growpart /dev/sda 2  # 扩展分区
pvresize /dev/sda2  # 调整 PV 大小

# 扩 VG/LV
vgextend vg_data /dev/sdc1  # 扩展卷组
lvextend -L +10G -r /dev/vg_data/lv_app  # 扩展逻辑卷

# 手动扩文件系统
resize2fs /dev/vg_data/lv_app     # ext4
xfs_growfs /data                  # xfs
```

**注意**：xfs 不支持缩容；ext4 缩容必须先卸载并 `e2fsck -f`。

## 场景 6：RAID 降级

**现象**：`cat /proc/mdstat` 显示 `[U_]` 或 `[UU_]`，RAID 处于 degraded 状态。

**可能原因**：

- 磁盘故障
- 线缆/背板/RAID 卡故障
- 磁盘掉线但未完全损坏
- 人为 `mdadm --fail`

**排查命令**：

```bash
cat /proc/mdstat  # 查看软 RAID 状态
mdadm --detail /dev/md0  # 查看 RAID 详情
smartctl -a /dev/sdb  # 查看磁盘健康
dmesg -T | grep -iE 'sd|md|error|timeout'  # 查看内核日志
```

**处理命令**：

```bash
# 标记故障并移除
mdadm --fail /dev/md0 /dev/sdb1  # 标记故障盘
mdadm --remove /dev/md0 /dev/sdb1  # 移除故障盘

# 换新盘后加入
mdadm --add /dev/md0 /dev/sdf1  # 加入新盘
cat /proc/mdstat                 # 观察 rebuild

# 清理旧盘元数据
mdadm --zero-superblock /dev/sdb1  # 清除旧盘 RAID 元数据
```

**注意**：重建期间不要拔盘、不要重启；先备份重要数据，重建会带来额外 I/O 压力。

## 场景 7：文件误删恢复

**现象**：误执行 `rm` 删除了重要文件，进程可能还在写，磁盘可能继续有写入。

**可能原因**：

- 人为误操作
- 脚本变量为空导致 `rm -rf /path/$VAR`
- 日志轮转/清理任务范围写错

**排查命令**：

```bash
lsof | grep deleted  # 查看已删除但仍被进程占用的文件
lsof +L1  # 查看 link count 为 0 的文件
ls -l /proc/<PID>/fd | grep deleted  # 查看进程 fd
```

**处理命令**：

```bash
# 如果进程还持有 fd，优先从 /proc 恢复
cp /proc/<PID>/fd/<FD> /recovery/file  # 复制回文件

# 如果没有进程持有，立即停止写入并卸载
umount /data  # 卸载分区，避免覆盖数据
extundelete /dev/sdb1 --restore-file /path/file  # ext4 尝试恢复
testdisk /dev/sdb1  # 分区/文件恢复
photorec /dev/sdb1  # 按文件类型恢复
```

**注意**：删除后越少写入，恢复成功率越高；XFS 没有官方 undelete 工具，优先依赖备份、快照或副本。

## 场景 8：NFS 挂载卡死

**现象**：`ls /mnt/nfs`、`df -h` 卡住，负载升高，出现大量 D 状态进程。

**可能原因**：

- NFS 服务端宕机或网络中断
- 防火墙拦截 2049/111
- 服务端 exports 权限变化
- 客户端使用 `hard` 挂载，一直重试
- 服务端磁盘/负载异常

**排查命令**：

```bash
mount | grep nfs  # 查看 NFS 挂载
nfsstat -c  # 查看客户端 NFS 统计
rpcinfo -p <server>  # 查看服务端 RPC 端口
showmount -e <server>  # 查看服务端 exports
ping -c 3 <server>  # 测试服务端连通性
ss -lntp | grep 2049  # 查看服务端 NFS 端口
dmesg -T | grep -i nfs  # 查看内核 NFS 报错
ps -eo state,pid,wchan:32,cmd | awk '$1 == "D"'  # 查看 D 状态进程
```

**处理命令**：

```bash
umount -f /mnt/nfs  # 强制卸载
umount -l /mnt/nfs  # 懒卸载，先断开目录树

# 服务端恢复后重新挂载
mount -t nfs -o vers=4.2,hard,timeo=600,retrans=2 <server>:/data /mnt/nfs  # 重新挂载
```

**注意**：`umount -l` 只是从命名空间摘掉，未必释放内核里的挂载；极端的 NFS 卡死可能需要重启。fstab 建议加 `nofail` 和 `x-systemd.automount`。

## 场景 9：新磁盘识别不到 / 分区表未刷新

**现象**：插入新盘或云盘扩容后，`lsblk` 看不到新设备，或分区大小没变化。

**可能原因**：

- 硬盘背板/HBA 没识别
- 云盘需要先在控制台挂载
- SCSI 总线未重新扫描
- 分区表已改但内核未重读

**排查命令**：

```bash
lsblk  # 查看块设备
lsblk -f  # 查看文件系统类型
cat /proc/partitions  # 查看内核识别的分区
dmesg -T | tail -50  # 查看内核识别日志
echo '- - -' > /sys/class/scsi_host/host0/scan  # 重新扫描 SCSI 总线
rescan-scsi-bus.sh  # 重新扫描 SCSI 设备
partprobe /dev/sdb  # 让内核重读分区表
```

**处理命令**：

```bash
parted /dev/sdb mklabel gpt  # 初始化 GPT 分区表
parted /dev/sdb mkpart data 1MiB 100%  # 创建一个分区
partprobe /dev/sdb  # 重读分区表
mkfs.xfs /dev/sdb1  # 格式化分区
```

**注意**：`mkfs` 会清空数据，执行前务必用 `lsblk` 确认设备；云盘扩容后可能还要先 `growpart`。

------

> 备注：命令以 Linux（GNU 工具链）为准；生产环境执行删除、重启、`kill -9`、`fsck`、改权限前，先确认影响范围。

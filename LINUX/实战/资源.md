> 资源与性能
> 覆盖：CPU、load、OOM、磁盘 I/O、文件句柄、软中断。

### 排障方法论

```text
1. 定义现象：慢、卡、报错、断开，具体从什么时候开始
2. 确定范围：单机/集群、单服务/全站、入站/出站
3. 建立时间线：变更、发布、流量、定时任务、告警
4. 分层排查：应用 -> OS -> 网络 -> 存储
5. 先观察再动手：保留现场，最小化变更
6. 处理并验证：指标恢复、业务验证、复盘

# 速查
CPU 高      top -> top -H -> perf/strace/jstack
内存高       free -h -> ps --sort=-rss -> dmesg OOM -> cgroup
磁盘满       df -h -> df -i -> du -x -> lsof +L1
IO 高       iostat -x -> iotop -o -> pidstat -d
负载高       uptime -> vmstat -> D 状态进程 -> IO/NFS
网络不通     ip addr/route -> ping -> ss -> 防火墙 -> tcpdump
DNS 失败     /etc/resolv.conf -> getent -> dig +trace
端口占用     ss -lntp -> lsof -i -> fuser
服务起不来   systemctl status -> journalctl -> 配置检查 -> 端口/权限/SELinux
SSH 慢      ssh -vvv -> sshd -T -> UseDNS/GSSAPI -> PAM/家目录
```

## 场景 1：CPU 使用率持续 100%

**现象**：监控告警 CPU 使用率接近 100%，业务响应变慢，登录后 `top` 看到某个进程长期占满 CPU。

**可能原因**：

- 应用死循环、复杂计算、正则回溯
- JVM Full GC 频繁
- 定时任务、批处理、备份、压缩突然启动
- 系统调用频繁、软中断高
- 病毒、挖矿、异常子进程

**排查命令**：

```bash
uptime  # 查看运行时间和负载
top  # 实时查看系统资源
ps -eo pid,ppid,%cpu,%mem,stat,cmd --sort=-%cpu | head -20  # 按 CPU 排序查看进程
top -H -p <PID>  # 查看进程内线程
ps -L -p <PID> -o pid,tid,pcpu,stat,cmd  # 查看进程线程
pidstat -u -p <PID> 1 5  # 查看进程资源使用
vmstat 1 5  # 查看系统整体状态
mpstat -P ALL 1  # 查看各 CPU 核心
```

### 进一步定位：

```bash
strace -f -T -tt -p <PID> -o /tmp/strace.log  # 跟踪系统调用
perf top -p <PID>  # 性能采样分析
jstack <PID> > /tmp/jstack.txt          # Java
printf '%x\n' <TID>                     # 线程 TID 转十六进制
```

**处理命令**：

```bash
renice 10 -p <PID>                      # 降低优先级
kill -TERM <PID>                        # 先优雅终止
systemctl restart <service>             # 重启异常服务
# 如果是软中断/网络问题，查网卡、驱动、中断亲和性
```

**注意**：不要一上来就 `kill -9`，先保留现场；`%sy` 高看系统调用，`%wa` 高看磁盘，`%si` 高看网络中断。

## 场景 2：load average 很高但 CPU 空闲

**现象**：`uptime` 显示 15 分钟负载 20 以上，但 `top` 中 CPU 空闲率超过 80%，业务明显变慢。

**可能原因**：

- 大量进程处于 D 状态，卡在磁盘 I/O
- NFS/网络文件系统挂起
- 磁盘故障、RAID 重建
- 内存回收、锁竞争
- 进程 fork 过多，可运行队列堆积

**排查命令**：

```bash
uptime  # 查看运行时间和负载
cat /proc/loadavg  # 查看系统负载
vmstat 1 5  # 查看系统整体状态
ps -eo state,pid,ppid,wchan:32,cmd | awk '$1 == "D"'  # 查找 D 状态进程
iostat -x 1 5  # 查看磁盘 I/O
iotop -o  # 查看进程 I/O
pidstat -d 1  # 查看进程资源使用
mount | grep -E 'nfs|cifs'  # 查看 NFS/CIFS 挂载
nfsstat -c  # 查看 NFS 统计
dmesg -T | tail -50  # 查看内核日志尾部
cat /proc/pressure/io  # 查看 IO 压力
```

**处理命令**：

```bash
# NFS 卡住：恢复网络，必要时强制卸载
umount -f /mnt/nfs  # 强制卸载
umount -l /mnt/nfs  # 懒卸载

# 磁盘故障：备份数据，更换磁盘
smartctl -a /dev/sdb  # 查看磁盘健康
cat /proc/mdstat  # 查看软 RAID 状态

# 单个进程 I/O 太大：限速或降优先级
ionice -c2 -n7 -p <PID>  # 调整 I/O 优先级
renice 10 -p <PID>  # 调整进程优先级
```

**注意**：D 状态进程在 I/O 返回前通常杀不掉，`kill -9` 也可能无效；重点查存储和 NFS。

## 场景 3：内存不足与 OOM

**现象**：服务进程偶尔被杀，`systemctl status` 显示 `killed`，系统日志出现 `Out of memory: Killed process`。

**可能原因**：

- 应用内存泄漏
- JVM 堆或容器 limit 设置不合理
- 缓存/连接池无限增长
- 系统内存被多个服务挤占
- swap 不足或 `overcommit` 策略

**排查命令**：

```bash
free -h  # 查看内存使用
cat /proc/meminfo  # 查看内存详情
vmstat 1 5  # 查看系统整体状态
ps -eo pid,ppid,rss,vsz,cmd --sort=-rss | head -20  # 按内存排序查看进程
dmesg -T | grep -iE 'oom|killed process'  # 查 OOM 记录
journalctl -k | grep -i oom  # 查内核 OOM 记录
grep -i oom /var/log/messages  # 查 OOM 记录

cat /proc/<PID>/oom_score  # 查看 OOM 分数
cat /proc/<PID>/oom_score_adj  # 查看 OOM 调整值
systemd-cgtop  # 查看 cgroup 资源
cat /sys/fs/cgroup/system.slice/<service>/memory.max  # 查看 cgroup 内存硬限制
cat /sys/fs/cgroup/system.slice/<service>/memory.current  # 查看 cgroup 当前内存
cat /sys/fs/cgroup/system.slice/<service>/memory.events  # 查看 cgroup 内存事件
```

**处理命令**：

```bash
# 限制服务内存
systemctl set-property <service> MemoryMax=1G MemoryHigh=800M  # 设置 cgroup 资源限制

# 保护关键进程（需要权限）
echo -500 > /proc/<PID>/oom_score_adj  # 调整 OOM 分数

# 调整应用堆、连接池、缓存上限
# 必要时扩容或拆分服务
```

**注意**：增加 swap 只能缓解，不能根治泄漏；`available` 比 `free` 更有参考价值，buff/cache 大部分可回收。

## 场景 4：磁盘 I/O 飙高

**现象**：业务写入变慢，`iostat` 显示某块盘 `%util` 接近 100%，`await` 很大。

**可能原因**：

- 备份、压缩、批处理集中跑
- 数据库慢查询、全表扫描
- 日志写入过猛
- RAID 重建、磁盘故障
- NFS/网络存储变慢

**排查命令**：

```bash
iostat -x 1 5  # 查看磁盘 I/O
iotop -o  # 查看进程 I/O
pidstat -d 1  # 查看进程资源使用
vmstat 1 5  # 查看系统整体状态
dmesg -T | grep -iE 'error|timeout|reset'  # 查内核错误
smartctl -a /dev/sdb  # 查看磁盘健康
cat /proc/mdstat  # 查看软 RAID 状态
```

**处理命令**：

```bash
# 降低后台任务 I/O 优先级
ionice -c2 -n7 -p <PID>  # 调整 I/O 优先级
renice 10 -p <PID>  # 调整进程优先级

# 暂停/错峰备份
systemctl stop backup.timer  # 暂停备份定时器

# 磁盘故障则备份并更换
```

**注意**：`%util` 高不一定是磁盘瓶颈，还要结合 `await`、`aqu-sz`、应用侧延迟；SSD 和机械盘的基线不同。

## 场景 5：Too many open files

**现象**：服务报 `Too many open files`，无法建立新连接或打开文件。

**可能原因**：

- `ulimit -n` 太小
- 应用 fd 泄漏
- 连接池只增不减
- systemd 服务 `LimitNOFILE` 太小

**排查命令**：

```bash
ulimit -n  # 查看资源限制
cat /proc/<PID>/limits  # 查看进程资源限制
cat /proc/sys/fs/file-nr  # 查看文件句柄使用
lsof -p <PID> | wc -l  # 统计进程打开的 fd 数
lsof -p <PID> | awk 'NR>1 {print $9}' | sort | uniq -c | sort -nr | head  # 按文件类型统计 fd
ls -l /proc/<PID>/fd | wc -l  # 统计进程 fd 数量
```

**处理命令**：

```bash
# 临时
ulimit -n 65535  # 设置文件句柄限制

# 永久：/etc/security/limits.conf
# 用户级文件句柄限制
* soft nofile 65535
* hard nofile 65535

# systemd 服务
# 文件句柄上限
LimitNOFILE=65535

# 系统级
sysctl -w fs.file-max=1000000  # 临时修改内核参数
```

**注意**：调大限制只能缓解，fd 持续增长要查应用泄漏；`lsof` 看打开最多的文件类型。

## 场景 6：软中断高 / 网卡中断不均

**现象**：`top` 中 `%si` 很高，某个 CPU 核被占满，网络延迟增大或丢包。

**可能原因**：

- 网络 PPS 过高、小包攻击
- 网卡只有单队列，未开启 RSS
- 中断都落在 CPU0
- 驱动/网卡 ring buffer 太小

**排查命令**：

```bash
mpstat -P ALL 1  # 查看各 CPU 核和软中断
cat /proc/interrupts | grep -E 'eth|ens'  # 查看网卡中断分布
ethtool -l eth0  # 查看网卡队列
ethtool -S eth0 | grep -iE 'drop|error'  # 查看网卡丢包/错误
cat /proc/softirqs  # 查看软中断统计
```

**处理命令**：

```bash
systemctl status irqbalance  # 查看中断均衡服务
ethtool -G eth0 rx 4096 tx 4096  # 调整 ring buffer
cat /proc/irq/<IRQ>/smp_affinity_list  # 查看中断绑核
echo <CPU> > /proc/irq/<IRQ>/smp_affinity_list  # 绑定中断到指定 CPU
```

**注意**：先确认是业务流量还是攻击；多队列/RSS 需要网卡和驱动支持，改中断亲和性前先记录原值。

------

> 备注：命令以 Linux（GNU 工具链）为准；生产环境执行删除、重启、`kill -9`、`fsck`、改权限前，先确认影响范围。

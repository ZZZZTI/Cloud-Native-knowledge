> 八股文

# 一、启动与 systemd

## Q1：Linux 启动流程是什么？

```text
一句话：BIOS/UEFI → GRUB2 → 内核 + initramfs → systemd → target → getty/登录。

展开：

1. BIOS/UEFI：硬件自检，按启动顺序找启动设备。
2. GRUB2：读取 /boot/grub2/grub.cfg，加载内核 vmlinuz 和 initramfs。
3. 内核 + initramfs：内核初始化硬件，initramfs 加载磁盘/文件系统驱动，挂载真正的根分区。
4. systemd：PID 1 启动，按依赖并行拉起 unit，进入默认 target。
5. getty/login：启动登录终端，用户登录后进入 Shell。

追问：GRUB 坏了怎么办？→ 进救援模式，grub2-mkconfig 重建；根分区找不到，检查 UUID、initramfs 驱动。
```

------

## Q2：initramfs 的作用是什么？

```text
一句话：initramfs 是启动早期的临时根文件系统，负责加载驱动并挂载真正的根分区。

展开：

- 内核启动时还没有完整的根文件系统，需要 initramfs 里的驱动、udev、挂载工具。
- 它能处理 LVM、RAID、加密盘、NFS 根等复杂场景。
- 挂载成功后执行 switch_root，切换到真实根分区。

常用命令：

lsinitrd /boot/initramfs-$(uname -r).img  # 查看 initramfs 内容（RHEL）
dracut -f                                  # 重建 initramfs（RHEL）
update-initramfs -u                        # 重建 initramfs（Debian/Ubuntu）
```

------

## Q3：systemd 相比 SysV init 有什么优势？

```text
一句话：systemd 并行启动、按需激活、依赖管理、cgroup 资源控制、统一日志。

展开：

- 并行启动：按依赖关系并行拉起服务，启动更快。
- 按需激活：socket、dbus、path、timer 触发，减少常驻进程。
- 依赖管理：After、Wants、Requires 描述顺序和依赖。
- 资源控制：通过 cgroup 限制 CPU、内存、任务数。
- 统一日志：服务日志进 journald，journalctl 统一查询。

追问：systemd 的 PID 是多少？→ 1。
```

------

## Q4：target 和运行级别怎么对应？

```text
一句话：target 是 systemd 的一组 unit，替代传统 runlevel。

poweroff.target    关机
rescue.target      单用户救援
multi-user.target  多用户命令行（服务器常用）
graphical.target   图形界面
reboot.target      重启

常用命令：

systemctl get-default                      # 查看默认 target
systemctl set-default multi-user.target    # 设置默认 target
systemctl isolate rescue.target            # 立即切换
```

------

## Q5：systemd service 的 Type 有哪些？

```text
一句话：常见 simple、forking、oneshot、notify、dbus。

simple    ExecStart 启动的进程就是主进程（最常用）
forking   传统守护进程，父进程 fork 后退出
oneshot   一次性任务，执行完就退出
notify    应用通过 sd_notify 通知 systemd 已就绪
dbus      通过 D-Bus 获取服务名

追问：Restart=on-failure 和 Restart=always 区别？→ 前者只在非零退出/信号时重启，后者总是重启。
```

------

## Q6：忘记 root 密码怎么进入系统？

```text
一句话：GRUB 内核行加 rd.break，挂载 /sysroot 为读写，chroot 后改密码。

# GRUB 菜单按 e，在 linux 行末尾加 rd.break
mount -o remount,rw /sysroot
chroot /sysroot
passwd root
touch /.autorelabel        # SELinux 开启时必须
exit
reboot

也可以用 init=/bin/bash：

mount -o remount,rw /
passwd root
exec /sbin/init

注意：需要控制台/IPMI/云 VNC；SELinux 未重打标签可能导致登录异常。
```

------

## Q7：daemon-reload 和 restart 有什么区别？

```text
一句话：daemon-reload 重新读取 unit 文件，restart 重启服务进程。

systemctl daemon-reload    # 改了 unit 文件后执行
systemctl restart nginx    # 改了应用配置后执行

追问：journald 和 rsyslog 区别？→ journald 是二进制结构化日志，rsyslog 是文本日志和转发；两者常共存。
```

# 二、进程与线程

## Q1：进程和线程的区别？

```text
一句话：进程是资源分配单位，线程是 CPU 调度单位。

展开：

- 进程有独立地址空间、文件描述符表、信号处理等。
- 线程共享进程地址空间和资源，切换成本更低。
- 进程间通信需要管道、socket、共享内存等；线程直接读写共享变量，但要加锁。
- 一个进程崩溃通常不影响其他进程；一个线程崩溃可能拖垮整个进程。

追问：协程？→ 用户态调度，切换成本更低，适合高并发 I/O。
```

------

## Q2：进程状态 R/S/D/T/Z 分别是什么？

```text
R  Running/Runnable   运行或可运行
S  Sleeping           可中断睡眠，等待事件
D  Disk Sleep         不可中断睡眠，通常在等 I/O
T  Stopped            暂停/被跟踪
Z  Zombie             已退出但父进程未回收

追问：D 状态为什么杀不掉？→ 进程在内核里等待 I/O，不响应信号，I/O 返回后才可能退出。

ps -eo state,pid,ppid,wchan:32,cmd | awk '$1 == "D"'
```

------

## Q3：僵尸进程和孤儿进程的区别？

```text
一句话：僵尸是“死了但没被收尸”，孤儿是“父进程先死，被 init/systemd 收养”。

展开：

- 僵尸进程：子进程退出，父进程没有 wait()，留下 PID 和退出状态。
- 僵尸不能 kill -9，因为已经死了；要处理父进程。
- 孤儿进程：父进程先退出，子进程被 PID 1 收养，通常能正常运行。

处理：

ps -eo pid,ppid,stat,cmd | awk '$3 ~ /^Z/'
systemctl restart <父进程服务>
```

------

## Q4：fork 和 exec 的区别？

```text
一句话：fork 复制进程，exec 替换进程映像。

展开：

- fork 创建子进程，采用写时复制（COW），共享父进程内存页直到写入。
- exec 用新程序替换当前进程的代码、数据、堆栈，PID 不变。
- Shell 执行命令通常是 fork + exec + wait。

追问：fork 后父子进程谁先运行？→ 不确定，由调度器决定。
```

------

## Q5：nice 和 renice 怎么理解？

```text
一句话：nice 值范围 -20～19，值越小优先级越高。

nice -n 10 command        # 启动时设置
renice 10 -p <PID>        # 运行时调整

展开：

- 普通用户只能调高 nice 值（降低优先级），不能调低。
- Linux CFS 调度器用权重计算 CPU 时间，nice 只是权重映射。
- 实时进程用 chrt，不是 nice。
```

------

## Q6：进程间通信有哪些方式？

```text
一句话：管道、命名管道、socket、共享内存、信号量、消息队列、信号。

pipe/FIFO     亲缘进程/无亲缘进程的字节流
socket        本机或网络通信
shared memory 最快，但需要同步
semaphore     同步/互斥
message queue 带消息边界的队列
signal        异步通知，信息量小

常用命令：

ipcs -m        # 查看共享内存
ipcs -q        # 查看消息队列
ipcs -s        # 查看信号量
```

------

## Q7：什么是上下文切换？

```text
一句话：CPU 从一个进程/线程切换到另一个时，保存和恢复执行现场的过程。

展开：

- 保存寄存器、程序计数器、栈指针、页表等。
- 触发原因：时间片用完、阻塞 I/O、中断、优先级更高的任务。
- 切换过多会增加 %sy，vmstat 的 cs、pidstat -w 可以看。

vmstat 1 5
pidstat -w 1 5
```

# 三、内存管理

## Q1：虚拟内存是什么？

```text
一句话：每个进程有独立虚拟地址空间，通过页表映射到物理内存。

展开：

- MMU 负责虚拟地址到物理地址的转换。
- 访问的页不在内存时触发缺页异常，从磁盘换入。
- 虚拟内存让进程隔离、内存复用、按需分配成为可能。

追问：VSZ 很大代表内存占用高吗？→ 不一定，VSZ 是虚拟地址空间，RSS 才是常驻物理内存。
```

------

## Q2：RSS、VSZ、PSS 有什么区别？

```text
VSZ  虚拟地址空间大小，包含未分配/未使用的映射
RSS  常驻物理内存，包含共享库
PSS  按共享比例分摊后的物理内存，更接近真实占用

排查：

ps -eo pid,rss,vsz,cmd --sort=-rss | head
smem -rk
pmap -x <PID>
```

------

## Q3：free 里的 buff/cache 和 available 是什么？

```text
一句话：buff/cache 是页缓存和目录项缓存，大部分可回收；available 是系统估计的可用内存。

buff/cache = page cache + dentry/inode cache + buffers
available  = free + 可回收的 cache（比 free 更有参考价值）

注意：drop_caches 只适合测试，生产上不要用它“优化”内存。

sync
echo 3 > /proc/sys/vm/drop_caches
```

------

## Q4：swap 的作用是什么？

```text
一句话：swap 把不常用的内存页换到磁盘，缓解内存压力，但不能替代物理内存。

展开：

- 内存不足时，内核把冷页换出，给热页腾空间。
- vm.swappiness 控制换出倾向，0～100，默认通常 60。
- 频繁 swap 会导致 I/O 升高、延迟变大，说明内存真的不够。

free -h
swapon --show
sysctl vm.swappiness
```

------

## Q5：OOM Killer 是怎么选进程的？

```text
一句话：内核根据 oom_score 选择“最该杀”的进程，oom_score_adj 可以人工调整。

展开：

- oom_score 综合内存占用、运行时间、nice 等因素。
- oom_score_adj 范围 -1000～1000，越低越不容易被杀。
- cgroup memory limit 触发的是 cgroup 内 OOM，不一定是全局 OOM。

dmesg -T | grep -iE 'oom|killed process'
cat /proc/<PID>/oom_score
cat /proc/<PID>/oom_score_adj
```

------

## Q6：内存泄漏怎么判断？

```text
一句话：观察进程 RSS 是否持续增长，且不随业务下降而回落。

展开：

- ps/smem 看 RSS 趋势。
- pmap -x 看内存段。
- Java 用 jmap/heap dump，C/C++ 用 Valgrind/ASan。
- 临时处理：重启、限制内存；根治：修代码。

ps -eo pid,rss,cmd --sort=-rss | head
pmap -x <PID>
```

------

## Q7：page cache 和脏页是什么？

```text
一句话：page cache 缓存文件数据，脏页是已修改但还没写回磁盘的页。

展开：

- 读文件先查 page cache，命中就不读磁盘。
- 写文件先写 page cache，标记为 dirty，由内核回写。
- sync/fsync 可以触发回写；突然断电可能丢脏页。

cat /proc/meminfo | grep -i dirty
sync
```

# 四、文件系统与 inode

## Q1：inode 是什么？里面有什么？

```text
一句话：inode 是文件的元数据，保存权限、大小、时间戳、数据块指针，但不保存文件名。

inode 包含：
- 文件类型、权限、属主/属组
- 大小、时间戳（atime/mtime/ctime）
- 数据块指针
- 链接数
不包含：
- 文件名（文件名在目录项里）

stat /etc/passwd
df -i
```

------

## Q2：目录项 dentry 是什么？

```text
一句话：dentry 是“文件名 → inode”的映射，缓存在内存里叫 dcache。

展开：

- 目录也是一种特殊文件，里面存放目录项。
- 路径解析时逐级查 dentry，命中缓存就快。
- 硬链接就是多个文件名指向同一个 inode。
```

------

## Q3：硬链接和软链接的区别？

```text
硬链接：
- 多个文件名指向同一个 inode
- 不能跨文件系统
- 一般不能给目录创建
- 删除其中一个，inode 链接数减一，数据还在

软链接：
- 独立 inode，内容是目标路径
- 可以跨文件系统
- 可以指向目录
- 目标删除后会变成悬空链接

ln source hardlink
ln -s target symlink
ls -li
```

------

## Q4：删除文件后，空间什么时候释放？

```text
一句话：删除只是去掉目录项并减少链接数；如果还有进程打开文件，数据块要等 fd 关闭才释放。

展开：

- rm 调用 unlink，inode 链接数减一。
- 链接数为 0 且没有进程打开，才真正释放数据块。
- 进程还开着文件时，df 不降，lsof +L1 能看到。

lsof +L1
: > /proc/<PID>/fd/<FD>
```

------

## Q5：inode 耗尽是什么原因？

```text
一句话：磁盘还有空间，但小文件太多，把 inode 用完了。

展开：

- 常见于 session、cache、邮件队列、临时文件、Docker 层。
- df -h 正常，df -i 接近 100%。
- 处理：找小文件密集目录，清理；预防：独立分区、监控 inode。

df -i
du -x --inodes -h --max-depth=1 / | sort -rh | head
```

------

## Q6：ext4 和 xfs 的区别？

```text
ext4：
- 成熟稳定，支持缩容
- 工具：resize2fs、e2fsck、dumpe2fs
- 适合通用场景

xfs：
- 大文件、高并发性能好
- 不支持缩容，只能扩容
- 工具：xfs_growfs、xfs_repair、xfs_info
- RHEL/CentOS 默认

追问：xfs 扩容用什么？→ xfs_growfs /mountpoint，不是 resize2fs。
```

------

## Q7：df 和 du 结果不一致，怎么解释？

```text
一句话：常见原因是已删除但仍被进程占用的文件、挂载点覆盖、预留块、稀疏文件。

展开：

- 已删除文件仍被占用：lsof +L1。
- 目录被挂载点覆盖：du -x 与 df 对比。
- 文件系统预留块：root 可写，普通用户看到的空间少。
- 稀疏文件：du 按实际块，ls -l 按逻辑大小。

df -h
du -x -h --max-depth=1 / | sort -rh | head
lsof +L1
```

------

## Q8：文件系统变成只读是什么原因？

```text
一句话：文件系统检测到错误或磁盘故障，内核把挂载点 remount 成只读，保护数据。

展开：

- dmesg 里常见 EXT4-fs error、I/O error、remount-ro。
- 处理：先备份，卸载后 fsck/xfs_repair；根分区进救援模式。
- 硬件坏道要换盘，不要只修文件系统。

mount | grep '(ro,'
dmesg -T | tail -100
```

# 五、磁盘与 I/O

## Q1：RAID 0/1/5/6/10 有什么区别？

```text
RAID0  条带，无冗余，性能最好，坏一块全丢
RAID1  镜像，至少 2 块，容量 50%，坏一块可恢复
RAID5  奇偶校验，至少 3 块，坏 1 块可恢复
RAID6  双校验，至少 4 块，坏 2 块可恢复
RAID10 镜像+条带，至少 4 块，性能和冗余兼顾

追问：RAID5 写洞？→ 写入过程中掉电可能导致校验不一致，重要场景配合 BBU/日志/RAID6。
```

------

## Q2：LVM 的原理和扩容步骤？

```text
一句话：LVM 把物理卷组成卷组，再从卷组切逻辑卷，支持动态扩容。

PV 物理卷：分区/磁盘打上 LVM 标记
VG 卷组：多个 PV 组成的存储池
LV 逻辑卷：从 VG 切出来的可用设备

扩容流程：

vgextend vg_data /dev/sdc1                 # 扩卷组
lvextend -L +10G -r /dev/vg_data/lv_app    # 扩 LV 并扩文件系统
# 或手动：
resize2fs /dev/vg_data/lv_app              # ext4
xfs_growfs /data                           # xfs
```

------

## Q3：为什么 xfs 不能缩容？

```text
一句话：xfs 的设计只支持增长，不支持在线缩小；需要缩只能备份、重建、恢复。

展开：

- ext4 可以 resize2fs 缩容，但必须先卸载并 e2fsck -f。
- xfs 没有官方 shrink 工具，生产上不要尝试。
- 规划容量时留余量，或使用 LVM 快照/新盘迁移。
```

------

## Q4：IOPS、吞吐、await、%util 是什么？

```text
IOPS     每秒 I/O 次数
吞吐     每秒读写字节数
await    平均 I/O 等待时间
%util    磁盘繁忙程度
aqu-sz   平均队列长度

展开：

- 小文件随机读写看 IOPS，大文件顺序读写看吞吐。
- %util 高不一定瓶颈，要结合 await 和业务延迟。
- 机械盘 await 通常 < 10ms，SSD 通常 < 1ms。

iostat -x 1 5
```

------

## Q5：IO 调度器怎么选？

```text
none/mq-deadline   SSD、NVMe 常用，减少调度开销
bfq                机械盘/桌面，强调公平和延迟
kyber              部分低延迟设备

cat /sys/block/sda/queue/scheduler

注意：虚拟化/云盘环境调度器可能由宿主机决定，不要盲目改。
```

------

## Q6：NFS 的 hard 和 soft 挂载有什么区别？

```text
一句话：hard 会一直重试，可能卡成 D 状态；soft 超时返回错误。

展开：

- hard 保证数据一致性，适合重要共享，但服务端故障时客户端可能卡死。
- soft 避免无限等待，但可能返回旧数据/错误。
- 常见参数：timeo、retrans、vers=4.2。

mount -t nfs -o vers=4.2,hard,timeo=600,retrans=2 server:/data /mnt
nfsstat -c
```

# 六、网络与 TCP

## Q1：TCP 三次握手过程？为什么是三次？

```text
一句话：SYN → SYN-ACK → ACK，三次才能确认双方收发能力并同步序列号。

客户端 -> 服务端：SYN，seq=x
服务端 -> 客户端：SYN-ACK，seq=y，ack=x+1
客户端 -> 服务端：ACK，ack=y+1

为什么三次：

- 两次无法确认客户端能收到服务端的包。
- 三次可以防止历史重复 SYN 建立错误连接。
- 同时交换并确认双方的初始序列号。
```

------

## Q2：TCP 四次挥手过程？为什么是四次？

```text
一句话：FIN → ACK → FIN → ACK，TCP 是全双工，两个方向要分别关闭。

主动关闭方 -> 被动方：FIN
被动方 -> 主动方：ACK
被动方 -> 主动方：FIN
主动方 -> 被动方：ACK

为什么四次：被动方收到 FIN 后，可能还有数据要发，所以 ACK 和 FIN 通常不能合并。
```

------

## Q3：TIME_WAIT 的作用是什么？

```text
一句话：主动关闭方等待 2MSL，确保最后一个 ACK 到达，并让旧连接的数据包过期。

展开：

- 只有主动关闭方进入 TIME_WAIT。
- 持续时间约 60 秒（2MSL）。
- 大量短连接会导致 TIME_WAIT 堆积，可能耗尽本地端口。

处理：连接池、keep-alive、减少短连接；tcp_tw_reuse 只对客户端场景有帮助。

ss -tan state time-wait | wc -l
```

## Q4：CLOSE_WAIT 很多是什么原因？

```text
一句话：被动关闭方收到 FIN，但应用没有调用 close()，通常是连接泄漏。

展开：

- 内核已经把连接交给应用，等待应用关闭。
- 常见于线程阻塞、异常分支未释放、连接池只借不还。
- 调内核参数没用，要修应用。

ss -tan state close-wait | wc -l
lsof -i :<端口>
```

## Q5：TCP 和 UDP 的区别？

```text
TCP：面向连接、可靠、字节流、拥塞控制、有序
UDP：无连接、不可靠、数据报、开销小、实时性好

追问：什么时候用 UDP？→ DNS、视频、游戏、日志采集等能容忍丢包的场景。
```

## Q6：backlog、somaxconn、SYN queue 是什么？

```text
一句话：backlog 是监听队列长度，涉及 SYN 队列和 accept 队列。

SYN 队列：收到 SYN，等待三次握手完成
accept 队列：握手完成，等待应用 accept
somaxconn：accept 队列上限
tcp_max_syn_backlog：SYN 队列上限

ss -lnt
sysctl net.core.somaxconn
sysctl net.ipv4.tcp_max_syn_backlog
```

## Q7：一次 HTTP 请求经过哪些环节？

```text
一句话：DNS → TCP → TLS → HTTP → 负载均衡 → 应用 → 数据库/缓存 → 响应。

展开：

1. DNS 解析域名。
2. 与服务器建立 TCP 连接。
3. HTTPS 还要 TLS 握手。
4. 发送 HTTP 请求，经过 LB/Nginx。
5. 应用处理，访问数据库/缓存。
6. 返回响应，浏览器渲染。
7. 连接复用或关闭。
```

## Q8：502 和 504 的区别？

```text
502 Bad Gateway：网关收到上游的无效响应
- 上游没启动、端口错、进程崩溃、返回非法响应

504 Gateway Timeout：网关等待上游超时
- 上游处理慢、数据库慢、网络丢包、超时设置太短

排查：Nginx error.log、curl 上游、ss 端口、应用日志、数据库慢查询。
```

## Q9：iptables 四表五链是什么？

```text
四表：
filter  过滤，默认表
nat     地址转换
mangle  修改包头
raw     跳过 conntrack

五链：
PREROUTING   进入网卡后、路由前
INPUT        发给本机

OUTPUT       本机发出
POSTROUTING  离开网卡前

NAT：
```

## Q10：HTTPS/TLS 握手做了什么？

# 七、权限与安全

## Q1：rwx、SUID、SGID、sticky 是什么？

```text
rwx    读/写/执行
SUID   执行时获得文件属主权限（如 passwd）
SGID   执行时获得文件属组权限；目录下新文件继承属组
sticky 目录下只有文件属主/root 能删除（如 /tmp）

chmod 4755 file    # SUID
chmod 2750 dir     # SGID
chmod 1777 /tmp    # sticky
```

------

## Q2：umask 怎么计算默认权限？

```text
一句话：默认权限 = 基础权限 & ~umask；文件基础 666，目录基础 777。

umask 022 -> 文件 644，目录 755
umask 027 -> 文件 640，目录 750
umask 077 -> 文件 600，目录 700

umask
```

------

## Q3：ACL 是什么？

```text
一句话：ACL 在传统 ugo 权限之外，给特定用户/组单独授权。

getfacl file
setfacl -m u:alice:rw file
setfacl -m g:dev:rx dir
setfacl -x u:alice file
setfacl -d -m g:dev:rx /shared    # 默认 ACL，新文件继承

追问：ACL 和 chmod 冲突？→ ACL 更细，ls -l 看到 + 号表示有 ACL。
```

------

## Q4：sudo 的原理是什么？

```text
一句话：sudo 是 setuid root 的程序，按 sudoers 规则决定谁能以谁的身份执行什么命令。

展开：

- 检查 /etc/sudoers 和 /etc/sudoers.d/。
- 通过 PAM 做认证，记录日志。
- 支持命令别名、用户别名、NOPASSWD、限制参数。
- 配置错误可能锁死提权，改完用 visudo -c 检查。

visudo -c
sudo -l
```

## Q5：PAM 是什么？

```text
一句话：PAM 是可插拔认证模块，把认证、账户、密码、会话交给不同模块处理。

auth      认证身份
account   账户是否有效/过期/锁定
password  修改密码
session   登录前后动作

常见模块：pam_unix、pam_faillock、pam_pwquality、pam_limits、pam_systemd。
```

## Q6：SELinux 是什么？怎么排障？

```text
一句话：SELinux 是基于标签的强制访问控制，即使 root 也要受策略限制。

展开：

- 模式：enforcing、permissive、disabled。
- 文件有 context，进程有 domain，策略决定能否访问。
- 被拒绝会记录 avc: denied。

getenforce
ls -Z /var/www/html
ausearch -m avc -ts recent
restorecon -Rv /var/www/html
semanage fcontext -a -t httpd_sys_content_t '/web(/.*)?'
setsebool -P httpd_can_network_connect on

注意：不要把 setenforce 0 当长期方案。
```

## Q7：SSH 公钥登录失败怎么排查？

```text
一句话：看权限、上下文、sshd 配置和日志。

ssh -vvv user@host
ls -ld ~ ~/.ssh
ls -l ~/.ssh/authorized_keys
namei -l ~/.ssh/authorized_keys
sshd -T | grep -Ei 'pubkey|authorizedkeys|permitrootlogin|allowusers'

常见原因：家目录 group/other 可写、authorized_keys 权限不对、SELinux 上下文错误、AllowUsers 限制。
```

# 八、性能与排查

## Q1：load average 到底是什么？

```text
一句话：load average 是“可运行 + 不可中断睡眠”进程数的 1/5/15 分钟平均值。

展开：

- 不等于 CPU 使用率，Linux 把 D 状态进程也算进去。
- 单核 load 1 表示刚好跑满，4 核 load 4 表示跑满。
- load 高但 CPU 空闲，通常是 I/O、NFS、锁等待。

uptime
cat /proc/loadavg
```

------

## Q2：CPU 的 us/sy/wa/si/st 怎么看？

```text
us  用户态，应用计算
sy  内核态，系统调用/上下文切换
wa  I/O 等待
si  软中断，网络/磁盘中断
st  被虚拟化层偷走的时间

判断：

- us 高：应用计算密集，查代码/GC。
- sy 高：系统调用频繁，查 strace、vmstat cs。
- wa 高：磁盘/NFS 慢，查 iostat。
- si 高：网络软中断高，查网卡/流量。
- st 高：宿主机超售，找云厂商。
```

------

## Q3：CPU、内存、IO 瓶颈怎么快速判断？

```text
uptime
vmstat 1 5
mpstat -P ALL 1
pidstat -u -r -d 1
iostat -x 1
free -h

思路：

- CPU：us/sy 高，id 低。
- 内存：available 低，si/so 持续非零，OOM。
- IO：wa 高，%util 高，await 大。
- 网络：ss -s、sar -n DEV、tcpdump。
```

------

## Q4：strace 和 perf 有什么区别？

```text
一句话：strace 跟踪系统调用，perf 做采样和性能分析。

strace：看进程调用了哪些系统调用、参数、耗时、错误
perf：采样 CPU、调用栈、热点函数，开销相对低

strace -f -T -tt -p <PID> -o /tmp/strace.log
perf top -p <PID>
perf record -F 99 -g -p <PID> -- sleep 30
```

------

## Q5：CPU 100% 怎么定位到线程和代码？

```text
top
top -H -p <PID>
ps -L -p <PID> -o pid,tid,pcpu,stat,cmd
printf '%x\n' <TID>
jstack <PID> > /tmp/jstack.txt    # Java
perf top -p <PID>

思路：进程 → 线程 → 线程栈/系统调用 → 代码或配置。
```

------

## Q6：进程卡在 D 状态怎么办？

```text
一句话：D 状态在等不可中断的 I/O，先查磁盘/NFS，再考虑重启。

ps -eo state,pid,wchan:32,cmd | awk '$1 == "D"'
cat /proc/<PID>/stack
dmesg -T | tail -50
iostat -x 1
mount | grep -E 'nfs|cifs'

处理：恢复 NFS、换盘、减少 I/O；极端情况只能重启。
```

## Q7：系统变慢的排查顺序？

```text
1. 现象：慢在哪、什么时候开始、影响范围
2. 变更：发布、配置、流量、依赖
3. 资源：CPU、内存、IO、网络
4. 应用：线程、GC、连接池、慢查询
5. 分层：入口 -> 应用 -> OS -> 存储
6. 处理：先止血，再根因
7. 验证：指标、日志、业务
```

# 四大黄金信号
延迟：请求从发出到响应的时间，需区分成功请求与失败请求的延迟。
流量：系统承受的需求量（QPS、连接数、活跃用户等），用于预判扩缩容需求。
错误：请求失败的数量或比率，包括显式错误（如 5xx）和隐式错误（如返回成功但内容错误）。
饱和度：系统资源（CPU、内存、I/O 等）接近极限的程度，是容量瓶颈的先行指标。



# 服务水平
SLI（Service Level Indicator）：服务水平的量化指标，：可用性，延迟，吞吐量，质量
SLO（Service Level Objective）：对 SLI 设定的内部目标，例如“99.9% 的请求延迟小于 200ms”。
SLA（Service Level Agreement）：对外的法律/商业承诺，通常比 SLO 宽松，违反会有赔偿。
错误预算（Error Budget）： = 1 − SLO 目标，用于决定能承受多少风险性变更，当预算耗尽时，暂停新功能发布，集中修复稳定性问题。
燃烧速率（Burn Rate）： = 实际错误率 / 允许的错误率，是真正驱动告警和决策的前瞻信号

压测：是用可控负载提前验证系统在多大负载下会击穿 SLO，并找出满足延迟、错误率目标的最大稳定容量与安全边际。覆盖基准、负载、压力、稳定性和全链路测试，它必须把结果映射到错误预算和 burn rate，判断容量能否承诺、何时该刹车。

容量规划：是在满足 SLO 和成本约束下，提前决定需要多少资源、何时扩容、扩哪里、留多少安全边际的闭环过程。它用压测得到的 SLO 安全容量曲线和拐点，结合需求预测、冗余系数、扩容提前期与瓶颈分析，计算可承诺容量而非峰值 QPS。


# 发布策略
发布策略是在错误预算约束下，把变更风险切成可观测、可回滚、可止损小块的受控过程，目标不是零风险，而是早暴露、小影响、快回滚。用 SLI、burn rate 和 SLO 阈值决定继续放量还是自动回滚，并由预算政策决定当前是否允许发布。  

策略	    做法	                      优点	                         适用场景
滚动发布	 逐批替换实例，新旧版本短暂共存	资源开销小，Kubernetes 原生支持		无状态服务、兼容性良好的常规发布
蓝绿部署	 维护两套完整环境，切换流量	   切换和回滚都快，验证充分		        关键服务、需要快速回滚的场景
金丝雀发布	先放少量流量到新版本，逐步扩大	 影响面可控，用真实流量验证		     大多数在线服务的默认选择
功能开关	 代码先上线，功能按开关逐步开放	部署与发布解耦，可按用户/租户灰度	  功能灰度、实验、紧急关停
A/B 测试	按用户分组对比不同版本效果	     可验证业务指标而非仅稳定性		     产品决策驱动的发布


# 韧性机制
韧性机制（Resilience Mechanisms）是系统在部分组件故障、依赖不可用或负载过载时，仍能维持核心功能或快速恢复的设计模式与技术手段的集合
入口限流 → 舱壁隔离 → 超时控制 → 熔断保护 → 失败重试（带退避）→ 降级兜底

机制	               解决什么问题	                         核心做法	
超时（Timeout）	      请求无限等待拖垮线程和连接	             为每次调用设定最大等待时间
重试（Retry）	        瞬时故障导致偶发失败	                 失败后有限次重试
熔断（Circuit Breaker）依赖持续故障时继续调用浪费资源并放大故障	失败率达到阈值后快速失败，不再调用依赖
舱壁隔离（Bulkhead）	 一个依赖或一类请求耗尽全部资源	        按依赖/租户/请求类型划分独立线程池或连接池
限流（Rate Limiting）	流量超过系统处理能力导致雪崩	          按 QPS、并发数或配额限制入口流量
降级（Degradation）	  依赖不可用时核心功能无法完成	          关闭非核心功能，返回缓存/默认值/简化结果
负载均衡与故障转移	     单实例故障导致请求失败	               健康检查 + 自动摘除故障实例 + 流量重新分配
异步化与队列缓冲	      突发流量直接冲击后端	                请求先入队列，后端按能力消费
幂等性设计	            重试或重复投递导致数据重复           	用唯一请求 ID、去重表或幂等键保证重复执行一致
背压（Backpressure）	上游生产速度超过下游消费能力	          下游向上游传递“慢下来”的信号


# 混沌工程
混沌工程（Chaos Engineering）是通过主动向系统注入受控故障，来验证系统在真实混乱条件下能否守住稳态的科学实验学科，探索的是故障边界而非负载边界。  
它以 SLI/SLO 定义稳态假设，以错误预算约束爆炸半径，以 burn rate 驱动自动中止，并遵循假设、实验、观察、结论的闭环。  
落地应从预发游戏日渐进到生产小范围实验，最终持续自动化，把发现的韧性缺口转化为改进项而非一次性演练。
